## 二、 具体考察内容

### 1. 顺序表的物理存储结构与随机存取寻址原理

#### (1) 线性表与顺序存储的形式化定义
线性表（Linear List）是由 $n$ ($n \ge 0$) 个具有相同特性的数据元素构成的有限序列。记为：
$$L = (a_1, a_2, \dots, a_i, \dots, a_n)$$
其中 $a_1$ 称为表头元素，$a_n$ 称为表尾元素；对于任意元素 $a_i$ ($1 < i \le n$)，其唯一的直接前驱为 $a_{i-1}$；对于任意元素 $a_i$ ($1 \le i < n$)，其唯一的直接后继为 $a_{i+1}$。

**顺序表（Sequential List）**是线性表的顺序存储实现形式。其物理实现特征为：使用一组地址连续的存储单元，依次存储线性表中的各个数据元素，从而使得**逻辑上相邻的元素在物理存储位置上也相邻**。

#### (2) 物理地址计算公式与随机存取（Random Access）特性
设顺序表中每个数据元素占用 $L$ 个字节（存储单元），顺序表的起始内存地址（即首元素 $a_1$ 的物理地址）为 $\text{LOC}(a_1)$。

根据物理空间连续性，第 $i$ 个数据元素 $a_i$ 的存储地址可以通过基地址与偏移量直接计算得出：

* **基于 1 为起始位序（1-based，逻辑位序）：**
  $$\text{LOC}(a_i) = \text{LOC}(a_1) + (i - 1) \times L \quad (1 \le i \le n)$$

* **基于 0 为起始下标（0-based，C/C++ 数组下标）：**
  $$\text{LOC}(A[i]) = \text{LOC}(A[0]) + i \times L \quad (0 \le i \le n - 1)$$

**核心定理**：顺序表中任意元素的物理存储地址与其逻辑位序 $i$ 满足线性映射函数关系。CPU 访问任意给定序号的元素时，只需进行一次基地址加乘法偏移运算即可直接定位目标物理内存，寻址时间与表长 $n$ 及元素位置 $i$ 无关。这种存取特性称为**随机存取（Random Access）**，其按位查找操作的时间复杂度为 $O(1)$。

```text
顺序表物理内存映射示意：
物理基地址 LOC(A[0])
    ↓
    +-----------+-----------+-----------+-----+-----------+
    |   A[0]    |   A[1]    |   A[2]    | ... |  A[n-1]   |
    +-----------+-----------+-----------+-----+-----------+
    |← L 字节 →|← L 字节 →|← L 字节 →|     |← L 字节 →|
    ↑           ↑
   LOC(A[0])   LOC(A[0])+L
```

#### (3) 静态分配与动态分配机制
1. **静态分配（Static Allocation）**：
   在编译期确定数组容量，顺序表存储空间预先分配固定上限。若数据元素超过预设大小，将产生数组越界溢出；若预留空间过大，将造成物理内存闲置浪费。
   ```c
   #define MaxSize 100
   typedef struct {
       int data[MaxSize]; // 静态分配的数组空间
       int length;        // 顺序表当前有效长度
   } SqList;
   ```
2. **动态分配（Dynamic Allocation）**：
   在程序运行时根据需要通过堆内存管理函数（如 C 语言的 `malloc()` / `free()`，C++ 的 `new` / `delete`）按需开辟空间。当原有存储空间饱和时，重新开辟一块更大的连续存储空间，将旧空间数据整体迁移至新空间，并释放原有旧内存。
   ```c
   #define InitSize 100
   typedef struct {
       int *data;   // 指向动态分配数组的基地址指针
       int MaxSize; // 顺序表最大存储容量
       int length;  // 顺序表当前有效长度
   } SeqList;
   ```

#### (4) 动态数组倍增扩容机制及均摊复杂度分析
在动态顺序表的实现中，容量饱和时通常采用**几何级数倍增策略**（如每次扩容为原容量的 2 倍），而非**线性算术增长策略**（如每次仅增加常数 $c$ 个容量）。

* **线性扩容策略均摊开销**：
  若每次扩容固定增加 $c$ 个空间，插入 $n$ 个元素的过程中将发生 $\Theta(n/c)$ 次内存重新分配与数据搬移。第 $k$ 次扩容需要复制的数据量为 $k \cdot c$。
  总复制数据量为：
  $$W(n) = \sum_{k=1}^{\lceil n/c \rceil} k \cdot c = c \cdot \frac{\lceil n/c \rceil (\lceil n/c \rceil + 1)}{2} = \Theta(n^2)$$
  单次插入的均摊时间复杂度为 $\Theta(n^2) / n = \Theta(n)$，性能低下。

* **加倍扩容策略均摊开销（聚合分析法，Aggregate Method）**：
  设初始容量为 1，每次满载时容量扩展为前一次的 2 倍。向表中连续插入 $n$ 个元素：
  * 常规插入开销：每次插入均耗费 1 次基本赋值操作，总计 $n$ 次。
  * 扩容数据迁移开销：仅在插入第 $1, 2, 4, 8, \dots, 2^k$ ($2^k \le n$) 个元素时触发扩容与元素拷贝。
  总拷贝次数上限为：
  $$\sum_{j=0}^{\lfloor \log_2 n \rfloor} 2^j = 2^{\lfloor \log_2 n \rfloor + 1} - 1 < 2n$$
  执行 $n$ 次插入操作的总耗费步数小于 $n + 2n = 3n$。
  因此，单次插入操作的**均摊时间复杂度（Amortized Time Complexity）**为：
  $$T_{\text{amortized}} = \frac{O(n)}{n} = O(1)$$

* **势能分析法（Potential Method）证明**：
  定义势能函数 $\Phi(D_i) = 2 \cdot \text{size}_i - \text{capacity}_i$。
  在扩容前夕，$\text{size}_i = \text{capacity}_i$，势能 $\Phi = \text{size}_i$；扩容并复制完成瞬间，容量翻倍，新势能 $\Phi' = 2 \cdot \text{size}_i - 2 \cdot \text{size}_i = 0$。释放出的势能足以完全冲抵元素迁移的实际耗费，证明了单次插入的均摊代价恒为 $O(1)$。

### 2. 顺序表基本操作及复杂度严密代数推导

#### (1) 按位查找（GetElem）
直接利用基地址偏移公式寻址。
* 最好时间复杂度：$O(1)$
* 最坏时间复杂度：$O(1)$
* 平均时间复杂度：$O(1)$

#### (2) 按值查找（LocateElem）
在无序顺序表中，按值查找采用顺序查找算法，依次比对各个元素与给定值：
```c
int LocateElem(SqList L, int elem) {
    for (int i = 0; i < L.length; i++) {
        if (L.data[i] == elem) {
            return i + 1; // 返回逻辑位序（1-based）
        }
    }
    return 0; // 查找失败
}
```
* **平均查找长度（ASL，Average Search Length）推导**：
  设表中各元素被查找的概率相等，即对于任意元素 $P_i = \frac{1}{n}$ ($1 \le i \le n$)：
  $$\text{ASL}_{\text{成功}} = \sum_{i=1}^n P_i \times C_i = \sum_{i=1}^n \frac{1}{n} \times i = \frac{1}{n} \cdot \frac{n(n + 1)}{2} = \frac{n + 1}{2}$$
  若查找失败，必须遍历全部 $n$ 个元素，比较次数为 $n$（若设哨兵或边界检测则为 $n+1$）。
* **复杂度分析**：
  * 最好时间复杂度：$O(1)$（目标元素位于首位）
  * 最坏时间复杂度：$O(n)$（目标元素位于末位或不存在）
  * 平均时间复杂度：$O(n)$

#### (3) 插入操作（ListInsert）
在长度为 $n$ 的顺序表中的第 $i$ 个逻辑位置（$1 \le i \le n + 1$）插入新元素 $e$。
需要将第 $n$ 个至第 $i$ 个元素依次向后移动一个位置，腾出空位放入新元素，最后表长加 1。

```c
bool ListInsert(SqList *L, int i, int e) {
    if (i < 1 || i > L->length + 1) { // 检查插入位置合法性
        return false;
    }
    if (L->length >= MaxSize) {      // 检查存储空间是否已满
        return false;
    }
    for (int j = L->length; j >= i; j--) { // 元素后移：自后向前移动，避免数据被覆盖
        L->data[j] = L->data[j - 1];
    }
    L->data[i - 1] = e;               // 放入新元素（转化为 0-based 下标）
    L->length++;                     // 表长自增
    return true;
}
```

* **平均移动次数推导**：
  在第 $i$ 个位置插入元素时，需要向后移动的元素个数为 $n - i + 1$。
  插入位置共有 $n + 1$ 个合法可能（即 $1 \le i \le n + 1$）。假设在每一个合法位置插入的概率均等，即 $P_i = \frac{1}{n + 1}$：
  $$E_{\text{insert}} = \sum_{i=1}^{n + 1} P_i \times (n - i + 1) = \frac{1}{n + 1} \sum_{i=1}^{n + 1} (n - i + 1)$$
  令 $k = n - i + 1$，当 $i$ 从 1 遍历到 $n+1$ 时，$k$ 对应从 $n$ 递减到 0。
  $$E_{\text{insert}} = \frac{1}{n + 1} \sum_{k=0}^n k = \frac{1}{n + 1} \cdot \frac{n(n + 1)}{2} = \frac{n}{2}$$
* **复杂度分析**：
  * 最好时间复杂度：$O(1)$（在表尾第 $n+1$ 处插入，移动 0 个元素）
  * 最坏时间复杂度：$O(n)$（在表头第 1 处插入，移动全部 $n$ 个元素）
  * 平均时间复杂度：$O(n)$

#### (4) 删除操作（ListDelete）
删除长度为 $n$ 的顺序表中的第 $i$ 个逻辑元素（$1 \le i \le n$），并将被删除元素通过参数返回。
需要将第 $i + 1$ 个至第 $n$ 个元素依次向前移动一个位置，填补空位，最后表长减 1。

```c
bool ListDelete(SqList *L, int i, int *e) {
    if (i < 1 || i > L->length) {     // 检查删除位置合法性
        return false;
    }
    *e = L->data[i - 1];              // 取出被删除元素
    for (int j = i; j < L->length; j++) { // 元素前移：自前向后移动，避免数据被覆盖
        L->data[j - 1] = L->data[j];
    }
    L->length--;                      // 表长自减
    return true;
}
```

* **平均移动次数推导**：
  删除第 $i$ 个元素时，需要向前移动的元素个数为 $n - i$。
  删除位置共有 $n$ 个合法可能（即 $1 \le i \le n$）。假设删除各个位置元素的概率均等，即 $P_i = \frac{1}{n}$：
  $$E_{\text{delete}} = \sum_{i=1}^n P_i \times (n - i) = \frac{1}{n} \sum_{i=1}^n (n - i)$$
  令 $k = n - i$，当 $i$ 从 1 遍历到 $n$ 时，$k$ 对应从 $n - 1$ 递减到 0。
  $$E_{\text{delete}} = \frac{1}{n} \sum_{k=0}^{n - 1} k = \frac{1}{n} \cdot \frac{(n - 1)n}{2} = \frac{n - 1}{2}$$
* **复杂度分析**：
  * 最好时间复杂度：$O(1)$（删除表尾第 $n$ 个元素，移动 0 个元素）
  * 最坏时间复杂度：$O(n)$（删除表头第 1 个元素，移动 $n - 1$ 个元素）
  * 平均时间复杂度：$O(n)$

#### (5) 顺序表与单链表核心特性全方位对比

| 对比维度 | 顺序表（Sequential List） | 链表（Linked List） |
| :--- | :--- | :--- |
| **物理存储结构** | 连续物理内存空间，逻辑相邻即物理相邻 | 任意离散物理内存单元，依靠指针维系逻辑后继 |
| **存取访问方式** | 随机存取（Random Access），直接计算偏移量寻址 | 顺序存取（Sequential Access），必须沿指针链顺序遍历 |
| **按位查找开销** | $O(1)$ | $O(n)$ |
| **按值查找开销** | 无序表 $O(n)$；有序表经折半查找可达 $O(\log n)$ | $O(n)$（无法直接使用折半查找） |
| **插入/删除开销** | 均需移动大约半数元素，时间开销为 $O(n)$ | 给定节点指针前提下只需修改指针指针域，开销为 $O(1)$ |
| **空间存储密度** | 高，存储密度为 1（全量空间存储业务数据） | 较低，每个节点需额外附带 4/8 字节指针域 |
| **容量弹性扩展** | 静态分配不可扩充；动态扩容需重新开辟整块内存并搬移数据 | 动态按需分配节点，内存利用极具弹性，无容量上限限制 |
| **硬件缓存友好性** | 内存局部性极佳，Cache 命中率高 | 内存节点随机分布，空间局部性差，易发生 Cache Miss |

### 3. 顺序表高频算法设计四大范式体系

408 近十年在综合应用大题（第 41 题）中对顺序表（数组）的考查已完全脱离单纯的元素增删，全面升级为综合性算法设计。以下四大算法范式涵盖了近十年真题的核心解法：

#### 范式一：双指针与多指针协同演进法（Multi-Pointer Technique）
利用数组的单调性或有序性，设置两个或多个下标指针，根据数值关系以单向或双向收缩的方式滑动，从而避免多重循环，将时间复杂度从 $O(n^2)$ 或 $O(n^3)$ 降低至 $O(n)$。
* **相向对撞指针**：一左一右向中间收缩（如回文判定、有序数组两数之和、快速排序单趟划分）；
* **同向快慢指针**：一快一慢同向推进（如原地删除指定重复元素、区间滑动窗口）；
* **多路同步推进指针**：针对多个有序数组，每次仅推动满足特定极值条件的指针（如 2020 年第 41 题三元组最小距离、两有序表合并归并）。

#### 范式二：单向极值维护与动态规划扫描法（Extremum Maintenance）
对于需要计算区间极值、前后缀组合极值的问题，通常无需通过两层循环遍历子区间。通过自前向后或自后向前的**单遍线性扫描**，动态维护前缀或后缀的最小、最大状态，实现常数空间 $O(1)$ 下的线性扫描。
* **典型代表**：2025 年第 41 题（后缀极值动态维护求最大乘积）、股票买卖最佳时机、最大子数组和（Kadane 算法）。

#### 范式三：鸽巢原理与空间换时间哈希打表法（Pigeonhole & Hash Indexing）
当题目涉及“未出现的最小整数”、“出现频次超过半数的元素”等问题时，充分利用**鸽巢原理（抽屉原理）**界定可能解的有限数学边界：
* **辅助标记打表（空间换时间）**：分配大小为 $n$ 的布尔数组 `vis`，直接将数值映射为数组下标，达到 $O(n)$ 时间复杂度和 $O(n)$ 空间复杂度（如 2018 年第 41 题）；
* **原地置换哈希（原地归位法）**：若限制额外空间为 $O(1)$，可将数组自身作为哈希表，通过循环交换将正整数 $x$ 交换至下标 $x-1$ 位置，实现 $O(n)$ 时间和 $O(1)$ 空间的极致优化。

#### 范式四：原地分块重排与三步逆置法（Triple-Inversion Technique）
针对数组块的循环位移、对称变换问题，利用线性代数矩阵求逆恒等式 $(A^{-1}B^{-1})^{-1} = BA$ 的逆置原理，在 $O(1)$ 辅助空间内完成任意区间的原地对调。
* **算法三步法则**：
  1. 逆置前半部分区间：$\text{Reverse}(0, p - 1) \to A^{-1}$
  2. 逆置后半部分区间：$\text{Reverse}(p, n - 1) \to B^{-1}$
  3. 逆置整个数组：$\text{Reverse}(0, n - 1) \to (A^{-1}B^{-1})^{-1} = BA$
* **典型代表**：2010 年第 42 题（顺序表循环左移 $p$ 个位置）。

### 【真题 1】2025 年 408 第 41 题 · 后缀极值单遍线性维护（算法大题，13分）

#### 【题目】
设有两个长度均为 $n$ 的一维整型数组 $A$ 和 $res$，对数组 $A$ 中的每个元素 $A[i]$，计算 $A[i]$ 与 $A[j]$ ($0 \le i \le j \le n-1$) 乘积的最大值，并将其保存到 $res[i]$ 中。例如，若 $A = \{1, 4, -9, 6\}$，则得到 $res = \{6, 24, 81, 36\}$。现给定数组 $A$，请设计一个时间和空间上尽可能高效的算法 `calMulMax`，求 $res$ 中各元素的值。函数原型为：
`void calMulMax(int A[], int res[], int n)`  
要求：  
(1) 给出算法的基本设计思想；  
(2) 根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释；  
(3) 说明你所设计算法的时间复杂度和空间复杂度。

#### 【解析】

##### 1. 数学本质与符号法则分析
对于每一个固定的下标 $i$，需要在区间 $[i, n-1]$ 内寻找下标 $j$，使得乘积 $P(i, j) = A[i] \times A[j]$ 最大。
根据乘法运算的符号法则：
* **情况 1：若 $A[i] > 0$**  
  欲使乘积最大，应使乘数 $A[j]$ 取后缀区间 $A[i \dots n-1]$ 中的**最大值**：
  $$\max_{i \le j \le n-1} (A[i] \times A[j]) = A[i] \times \max_{i \le j \le n-1} A[j]$$
* **情况 2：若 $A[i] < 0$**  
  负负得正。欲使乘积最大，应使乘数 $A[j]$ 取后缀区间 $A[i \dots n-1]$ 中的**最小值**：
  $$\max_{i \le j \le n-1} (A[i] \times A[j]) = A[i] \times \min_{i \le j \le n-1} A[j]$$
* **情况 3：若 $A[i] = 0$**  
  无论 $A[j]$ 为何值，乘积恒为 0，任取极值相乘均成立。

若采用双重循环枚举所有的 $(i, j)$ 对，时间复杂度为 $O(n^2)$，效率较低。注意到：当遍历方向由后向前（从 $n-1$ 逆序扫描至 0）时，当前后缀区间 $A[i \dots n-1]$ 的最大值和最小值完全可以由后一个后缀区间 $A[i+1 \dots n-1]$ 的最大值和最小值在 $O(1)$ 时间内递推得到：
$$\text{max\_val}_i = \max(A[i], \text{max\_val}_{i+1})$$
$$\text{min\_val}_i = \min(A[i], \text{min\_val}_{i+1})$$
因此，只需进行单遍从右向左的逆向线性扫描，维护当前后缀的极值，即可在常数时间内求得每一个 $res[i]$。

##### 2. 算法基本设计思想
采用自右向左逆向单遍扫描数组的贪心/动态规划思想：
1. 设置两个整型变量 `max_val` 和 `min_val`，分别用于实时维护当前后缀子数组 $A[i \dots n-1]$ 中的最大值和最小值。
2. 初始时，从表尾元素开始处理（$i = n - 1$），此时后缀区间仅包含 $A[n-1]$ 本身，令 `max_val = A[n-1]`, `min_val = A[n-1]`，计算 $res[n-1] = A[n-1] \times A[n-1]$。
3. 从 $i = n - 2$ 逆序遍历至 0，对于当前元素 $A[i]$：
   - 将当前元素纳入后缀极值考量，动态更新极值：$\text{max\_val} = \max(\text{max\_val}, A[i])$，$\text{min\_val} = \min(\text{min\_val}, A[i])$；
   - 根据 $A[i]$ 的正负性计算最大乘积：若 $A[i] \ge 0$，则 $res[i] = A[i] \times \text{max\_val}$；若 $A[i] < 0$，则 $res[i] = A[i] \times \text{min\_val}$。
4. 逆序循环结束时，数组 $res$ 即被完整计算填充。

##### 3. 算法实现（C 语言）
```c
#include <stdio.h>

void calMulMax(int A[], int res[], int n) {
    if (A == NULL || res == NULL || n <= 0) {
        return; // 边界防御：非法输入处理
    }

    // 初始化后缀极值：以数组末尾元素 A[n-1] 作为初始基准
    int max_val = A[n - 1];
    int min_val = A[n - 1];
    res[n - 1] = A[n - 1] * A[n - 1];

    // 自后向前单遍逆向扫描数组
    for (int i = n - 2; i >= 0; i--) {
        // 将当前元素 A[i] 纳入后缀区间，动态更新当前后缀的最大值与最小值
        if (A[i] > max_val) {
            max_val = A[i];
        }
        if (A[i] < min_val) {
            min_val = A[i];
        }

        // 根据 A[i] 符号特征确定取最大值还是最小值相乘
        if (A[i] >= 0) {
            res[i] = A[i] * max_val;
        } else {
            res[i] = A[i] * min_val;
        }
    }
}
```

##### 4. 复杂度推导与说明
* **时间复杂度**：算法仅包含一层单重 `for` 循环，从 $n-2$ 递减到 0，循环体内部仅包含常数次比较、赋值和乘法操作，总操作次数为线性步数。因此，时间复杂度为 $O(n)$。
* **空间复杂度**：算法仅使用了 `max_val`、`min_val` 和循环控制变量 `i` 等常数个辅助变量，未申请任何与输入规模 $n$ 相关的额外动态内存空间。因此，辅助空间复杂度为 $O(1)$。

### 【真题 2】2023 年 408 第 1 题 · 顺序存储存取特性辨析（选择题）

#### 【题目】
下列对顺序存储的有序表（长度为 $n$）实现给定操作的算法中平均时间复杂度为 $O(1)$ 的是（ ）。  
A. 查找包含指定值元素的算法  
B. 插入包含指定值元素的算法  
C. 删除第 $i$ 个元素的算法  
D. 获取第 $i$ 个值的算法  

#### 【解析】
本题全面考查顺序存储结构的物理特性及其基本操作的代数复杂度。

* **A 项错误**：在顺序存储的有序表中查找指定值的元素，最有效的方法是折半查找（二分查找），其比较判定树的高度为 $\lfloor \log_2 n \rfloor + 1$，平均时间复杂度为 $O(\log n)$；若采用顺序查找，平均时间复杂度为 $O(n)$。无论何种查找算法，平均时间复杂度均不可能达到 $O(1)$。
* **B 项错误**：在有序表中插入指定值的元素，首先需要通过查找确定插入位置（耗时 $O(\log n)$ 或 $O(n)$）；确定位置后，必须将该位置及其后续的所有元素依次向后移动一位，腾出存储空间。平均移动元素个数为 $n/2$，因此平均时间复杂度为 $O(n)$。
* **C 项错误**：删除第 $i$ 个元素时，尽管定位该元素仅耗时 $O(1)$，但为了维持物理存储单元的连续性，必须将第 $i+1$ 至第 $n$ 个元素依次向前平移一位。根据数学期望推导，删除操作平均需要移动 $(n - 1) / 2$ 个元素，平均时间复杂度为 $O(n)$。
* **D 项正确**：顺序表的核心物理特性在于**随机存取（Random Access）**。系统获知顺序表起始基地址 $\text{LOC}(a_1)$ 及单个元素占用空间 $L$ 后，获取第 $i$ 个值的物理内存地址可直接通过基地址偏移公式直接得出：
  $$\text{LOC}(a_i) = \text{LOC}(a_1) + (i - 1) \times L$$
  CPU 执行一次乘法和一次加法寻址指令即可在恒定时间内完成数据读取，执行时间与表长 $n$ 和位序 $i$ 完全无关，其平均时间复杂度为 $O(1)$。

**正确答案**：**D**

### 【真题 3】2020 年 408 第 41 题 · 三有序表多指针贪心逼近（算法大题，13分）

#### 【题目】
定义三元组 $(a, b, c)$（$a, b, c$ 均为正数）的距离 $D = |a - b| + |b - c| + |c - a|$。给定 3 个非空整数集合 $S_1, S_2, S_3$，按升序分别存储在 3 个数组中。请设计一个尽可能高效的算法，计算并输出所有可能的三元组 $(a, b, c)$（$a \in S_1, b \in S_2, c \in S_3$）中的最小距离。例如 $S_1 = \{-1, 0, 9\}, S_2 = \{-25, -10, 10, 11\}, S_3 = \{2, 9, 17, 30, 41\}$，则最小距离为 2，相应的三元组为 $(9, 10, 9)$。  
要求：  
(1) 给出算法的基本设计思想；  
(2) 根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释；  
(3) 说明你所设计算法的时间复杂度和空间复杂度。

#### 【解析】

##### 1. 数学几何化简与单调性分析
设三元组中的三个数值按大小排序后为 $x \le y \le z$（其中 $x, y, z$ 为 $a, b, c$ 的某一置换）。
在实数轴上，点 $y$ 必然落在点 $x$ 与点 $z$ 构成的线段区间 $[x, z]$ 之内：
$$|x - y| = y - x$$
$$|y - z| = z - y$$
$$|z - x| = z - x$$
将三者代入距离公式 $D$：
$$D = |x - y| + |y - z| + |z - x| = (y - x) + (z - y) + (z - x) = 2(z - x)$$

```text
三元组几何数轴分布模型：
        x (最小值)          y (中间值)          z (最大值)
--------+-------------------+-------------------+-------->
        |←---- y - x ------→|←---- z - y ------→|
        |←----------------- z - x --------------→|
```

**数学结论**：任意三元组的距离 $D$，在数值上严格等于**该三元组中最大值与最小值之差的 2 倍**。中间变量 $y$ 的具体数值对总距离 $D$ 没有任何数值贡献。  
因此，“求最小距离 $D$”完全等价于“在三个数组中各选一个数，使得三者的最大值与最小值之差 $\max(a,b,c) - \min(a,b,c)$ 达到最小”。

##### 2. 贪心多指针滑动策略证明
若采用三重暴力枚举，时间复杂度高达 $O(|S_1| \times |S_2| \times |S_3|) = O(n^3)$。
利用三个数组均已**按升序排列**的先决条件，采用三指针同步协同推进：
* 设三个下标指针 $i, j, k$ 分别初始化为 0，指向三个数组的起始端。
* 当前考察的三元组为 $(A[i], B[j], C[k])$，计算当前距离 $D$ 并尝试刷新历史最小距离 $D_{\min}$。
* **下一步推进方向的选择**：
  若试图缩小跨度 $z - x$：
  - 若移动最大值 $z$ 对应的指针（指针后移，数值变大），由于数组递增，最大值将进一步增大，导致跨度 $z - x$ 必然变大或保持不变，不可能使距离减小；
  - 若移动中间值 $y$ 对应的指针，跨度 $z - x$ 根本不受影响；
  - **唯一可能使距离减小的操作**：将**当前最小值 $x$ 所对应的指针向后移动一位**。随着该指针后移，新的元素增大，极有可能缩小与最大值 $z$ 之间的差距，从而诞生更小的跨度。
* 当最小值指针对应的数组遍历结束时，整个搜索过程可以安全终止。因为此时最小值无法再增大，若移动其余指针只会让最大值更大，不可能再产生更小的距离。

##### 3. 算法基本设计思想
1. 定义全局最小距离变量 $D_{\min}$，初始化为整型最大值 `INT_MAX`。
2. 设置三个下标变量 $i = 0, j = 0, k = 0$，分别指示数组 $S_1, S_2, S_3$ 的当前处理位置。
3. 当且仅当 $i < |S_1|$ 且 $j < |S_2|$ 且 $k < |S_3|$ 时，循环执行以下操作：
   - 计算当前三元组 $(S_1[i], S_2[j], S_3[k])$ 的距离 $D = |S_1[i] - S_2[j]| + |S_2[j] - S_3[k]| + |S_3[k] - S_1[i]|$；
   - 若 $D < D_{\min}$，则更新 $D_{\min} = D$；
   - 比较 $S_1[i], S_2[j], S_3[k]$ 三者大小，找出其中的最小值：若 $S_1[i]$ 最小，则令 $i$ 自增 1；若 $S_2[j]$ 最小，则令 $j$ 自增 1；若 $S_3[k]$ 最小，则令 $k$ 自增 1；
4. 只要有任意一个数组扫描完毕，循环立即终止，返回并输出 $D_{\min}$。

##### 4. 算法实现（C 语言）
```c
#include <stdio.h>
#include <stdlib.h>
#include <limits.h>

// 辅助函数：判断 a 是否是 a, b, c 三者中的最小值
int is_min(int a, int b, int c) {
    return (a <= b && a <= c);
}

int findMinDistance(int S1[], int n1, int S2[], int n2, int S3[], int n3) {
    int i = 0, j = 0, k = 0;
    int min_D = INT_MAX; // 记录全局最小距离

    // 当三个数组均未遍历到末尾时持续循环
    while (i < n1 && j < n2 && k < n3) {
        int a = S1[i];
        int b = S2[j];
        int c = S3[k];

        // 计算当前三元组的距离 D
        int cur_D = abs(a - b) + abs(b - c) + abs(c - a);
        if (cur_D < min_D) {
            min_D = cur_D; // 发现更小距离，更新最优解
        }

        // 贪心策略：仅将当前三元组中最小值所在的指针后移
        if (is_min(a, b, c)) {
            i++;
        } else if (is_min(b, a, c)) {
            j++;
        } else {
            k++;
        }
    }

    return min_D;
}
```

##### 5. 复杂度推导与说明
* **时间复杂度**：设三个数组的长度分别为 $n_1, n_2, n_3$，数据规模总和为 $n = n_1 + n_2 + n_3$。在 `while` 循环的每次迭代中，指针 $i, j, k$ 中有且仅有一个严格向前移动 1 位。因此，循环的最大迭代步数不超过 $n_1 + n_2 + n_3$。循环体内部均为 $O(1)$ 的数学运算，故算法总时间复杂度为 $O(n_1 + n_2 + n_3) = O(n)$。
* **空间复杂度**：算法仅申请了指针变量、当前数值缓存及最小距离记录等若干辅助整型变量，并未申请额外动态数组，空间开销为常数阶。故辅助空间复杂度为 $O(1)$。

### 【真题 4】2018 年 408 第 41 题 · 鸽巢原理与缺失最小正整数（算法大题，13分）

#### 【题目】
给定一个含 $n$ ($n \ge 1$) 个整数的数组，请设计一个在时间上尽可能高效的算法，找出数组中未出现的最小正整数。例如，数组 $\{-5, 3, 2, 3\}$ 中未出现的最小正整数是 1；数组 $\{1, 2, 3\}$ 中未出现的最小正整数是 4。  
要求：  
(1) 给出算法的基本设计思想；  
(2) 根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释；  
(3) 说明你所设计算法的时间复杂度和空间复杂度。

#### 【解析】

##### 1. 鸽巢原理（抽屉原理）严格数学推导
设输入数组的长度为 $n$。未出现的最小正整数的值域边界具有严格的数学确定性：
**定理**：含 $n$ 个整数的数组中，未出现的最小正整数必严格落在闭区间 $[1, n + 1]$ 内。
* **证明**：
  将正整数 $1, 2, 3, \dots, n$ 视为 $n$ 个“鸽巢”。
  - 极端情况：若原数组中恰好不重不漏地包含了全部 $1 \sim n$ 这 $n$ 个正整数，则这 $n$ 个鸽巢全满，未出现的最小正整数显然为下一个正整数 $n + 1$。
  - 一般情况：若数组中存在任何小于等于 0 的整数、严格大于 $n$ 的整数，或者存在重复的正整数，则这些无效数据将占用数组空间，导致属于 $[1, n]$ 范围内的正整数个数严格少于 $n$ 个。根据鸽巢原理，在区间 $[1, n]$ 内必然存在至少一个没有对应元素的“空鸽巢”。因此，未出现的最小正整数必然落在 $[1, n]$ 范围内。
  综上，算法只需重点考察正整数 $1 \sim n$ 是否在数组中出现，无需理会任何 $\le 0$ 或 $> n$ 的冗余数值。

##### 2. 算法基本设计思想（空间换时间哈希打表法）
为了在时间上达到最高效率，采用空间换时间的哈希标记策略：
1. 动态申请一个大小为 $n$ 的辅助标记数组 `vis`，初始化所有元素均为 0。其中 `vis[i]` 的值用于标识正整数 $i + 1$ 是否在原数组中出现（`vis[0]` 对应正整数 1，`vis[n-1]` 对应正整数 $n$）。
2. 从头至尾单遍遍历原数组 $A$：
   - 检查元素 $A[i]$，若满足 $1 \le A[i] \le n$，则将其对应的标记置位：`vis[A[i] - 1] = 1`；
   - 若 $A[i] \le 0$ 或 $A[i] > n$，则直接忽略跳过。
3. 原数组遍历完毕后，对辅助数组 `vis` 进行自左向右的线性顺序扫描：
   - 若找到首个满足 `vis[i] == 0` 的位置，说明正整数 $i + 1$ 未曾出现，直接返回 $i + 1$ 即为未出现的最小正整数；
   - 若遍历完整个 `vis` 数组，所有元素均为 1，说明 $1 \sim n$ 均已出现，直接返回 $n + 1$。

##### 3. 算法实现（C 语言）
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int findMissMin(int A[], int n) {
    if (A == NULL || n <= 0) {
        return 1; // 边界防御
    }

    // 申请大小为 n 的辅助标记数组，并将其全部初始化为 0
    int *vis = (int *)calloc(n, sizeof(int));
    if (vis == NULL) {
        return -1; // 内存分配失败处理
    }

    // 第一遍遍历原数组 A：记录 1 ~ n 范围内正整数的出现情况
    for (int i = 0; i < n; i++) {
        if (A[i] > 0 && A[i] <= n) {
            vis[A[i] - 1] = 1; // 将对应正整数位置标记为 1
        }
    }

    // 第二遍扫描标记数组 vis：寻找第一个未出现的正整数
    for (int i = 0; i < n; i++) {
        if (vis[i] == 0) {
            int result = i + 1;
            free(vis); // 释放堆内存，防止内存泄漏
            return result;
        }
    }

    // 若 1 ~ n 均出现，则缺失的最小正整数为 n + 1
    free(vis);
    return n + 1;
}
```

##### 4. 复杂度推导与说明
* **时间复杂度**：算法执行两次独立的单层循环，第一次遍历原数组 $A$（执行 $n$ 次），第二次遍历标记数组 `vis`（至多执行 $n$ 次）。循环体内部均为常数级数组寻址与比较操作，因此总运行时间为线性阶，时间复杂度为 $O(n)$。
* **空间复杂度**：算法分配了一个长度为 $n$ 的辅助整型数组 `vis`，占用的额外存储空间与输入规模 $n$ 呈线性正比关系，因此辅助空间复杂度为 $O(n)$。

##### 5. 学术拓展：原地置换哈希法（Cyclic Sort，O(1) 辅助空间极致解法）
若题目进一步苛求空间复杂度达到 $O(1)$，可利用原数组自身作为哈希表，通过元素的“归位”操作实现原地标记：
* **核心逻辑**：只要满足 $1 \le A[i] \le n$，且目标位置上的数不等于当前数（即 $A[A[i] - 1] \ne A[i]$），就不断通过 `swap` 将 $A[i]$ 交换到其对应的正确下标 $A[i] - 1$ 处；
* **复杂度分析**：每个正整数至多被交换一次即可放置到正确位置，整个置换过程均摊比较次数不超过 $2n$，时间复杂度仍为 $O(n)$，且额外空间复杂度达到严格的 $O(1)$。

```text
    - 变量命名需具有明确的语义（如 `max_val`, `min_D`, `left`, `right`），关键分支与循环必须添加简要注释。
(3) 复杂度分析
    - 时间复杂度：必须指明基本操作（如元素比较次数、循环单步迭代数），规范书写形如 $O(n)$ 的大 $O$ 表达式。
    - 空间复杂度：严格区分工作变量 $O(1)$ 与辅助数组 $O(n)$，明确指明辅助空间开销的物理来源。
```

### 3. 高频易错陷阱清单

1. **逻辑位序（1-based）与物理下标（0-based）混淆**：
   408 题干若表述“第 $i$ 个元素”，其对应的 C 语言物理数组下标为 $i - 1$。在书写插入、删除算法的边界条件时，插入的合法位置是 $1 \le i \le n+1$（在表尾追加是第 $n+1$ 个位置），而删除的合法位置是 $1 \le i \le n$。混淆二者边界将直接导致扣除边界检查分。
2. **元素平移方向与数据覆盖灾难**：
   * **插入操作**：必须自表尾向目标位置**从后向前**遍历平移（`for (int j = L.length; j >= i; j--) L.data[j] = L.data[j-1];`）。若从前向后移动，前面的元素移动后将直接覆盖后面的元素，导致数据全部被首个移动元素污染。
   * **删除操作**：必须自被删除位置**从前向后**遍历平移（`for (int j = i; j < L.length; j++) L.data[j-1] = L.data[j];`）。若从后向前移动，同样会导致数据覆盖错误。
3. **动态扩容的野指针与内存泄漏**：
   在动态扩容操作中，使用 `malloc` 开辟新内存后，必须先通过循环将旧数据整体迁移至新内存块，随后**务必调用 `free(L.data)` 释放旧内存**，最后再将指针指向新内存块。遗漏 `free()` 会造成内存泄漏；过早释放旧内存会导致数据悬空访问崩溃。

## 五、 考点速记清单

1. **寻址公式**：$\text{LOC}(a_i) = \text{LOC}(a_1) + (i - 1) \times L$（1-based）。
2. **存取特性**：随机存取（Random Access），按位查找耗时 $O(1)$，与表长和位置无关。
3. **平均移动次数**：
   * 插入操作：$\frac{n}{2}$
   * 删除操作：$\frac{n - 1}{2}$
4. **动态倍增均摊**：容量翻倍扩容时，单次插入均摊时间复杂度为 $O(1)$；固定常数扩容均摊时间复杂度退化为 $O(n)$。
5. **四大解题范式**：
   * 跨度极值最小化 $\to$ 几何化简 + 多指针贪心推进当前最小值（2020 年第 41 题）；
   * 后缀乘积最大化 $\to$ 自右向左单遍逆向扫描 + 同步维护最大与最小值（2025 年第 41 题）；
   * 缺失最小正整数 $\to$ 鸽巢原理值域落在 $[1, n+1]$ + 标记数组打表（2018 年第 41 题）；
   * 块循环左移 $p$ 位 $\to$ 原地三步逆置法 $(A^{-1}B^{-1})^{-1} = BA$（2010 年第 42 题）。
