## 二、 具体考察内容

### 1. TCP 连接建立的核心目标和报文控制字段

TCP 作为可靠的、面向连接的传输层协议，其三次握手必须达成以下关键目标：
1. **确认双方全双工通信能力正常**：确保通信双发均具备接收和发送数据的能力。
2. **协商并同步初始序列号（ISN）**：使双方建立各自发送字节流的基准编号，防止网络中因乱序、重复导致的数据混淆。
3. **协商连接参数**：在可选项中交换最大报文段长度（MSS）、窗口扩大因子（Window Scale）、选择确认支持（SACK）等参数。

#### （1）关键首部控制字段解析
在 TCP 报文段首部中，握手阶段最为关键的字段包括：
- **序号字段（Sequence Number, seq，32 bit）**：表示本报文段所发送的数据的第一个字节的序号。在连接建立阶段，发送方选定的起始序号称为初始序列号（Initial Sequence Number, ISN）。
- **确认号字段（Acknowledgment Number, ack，32 bit）**：期望收到对方下一个报文段的数据的第一个字节的序号。只有当确认标志位 $\text{ACK}=1$ 时，确认号字段才有效。
- **控制位（Flags，各占 1 bit）**：
  - **SYN（Synchronize Sequence Numbers，同步位）**：用于在连接建立时同步序号。当 $\text{SYN}=1$$ \text{而} $$\text{ACK}=0$$ \text{时，表明这是一个连接请求报文段；若对方同意连接，则在响应报文段中使} $$\text{SYN}=1$$ \text{且} $$\text{ACK}=1$。
  - **ACK（Acknowledgment，确认位）**：当 $\text{ACK}=1$ 时确认号字段生效；TCP 规定，在连接建立完成后，所有传送的报文段都必须将 ACK 置 1。
  - **RST（Reset，复位位）**：当 $\text{RST}=1$ 时，表明 TCP 连接中出现严重差错，必须释放连接并重新建立。

#### （2）序号消耗的核心规则（考研命题高频陷阱）
- **规则 1**：当报文段中包含 $\text{SYN}=1$$ \text{时（第一、二次握手），即使该报文段不携带任何应用层数据（数据载荷长度为 0），也**必须消耗 1 个序号**。因此，下一个报文段的序号必须为} $$\text{seq} = \text{ISN} + 1$。
- **规则 2**：包含 $\text{FIN}=1$ 的连接释放报文段，即使不携带数据，同样**消耗 1 个序号**。
- **规则 3**：单纯的确认报文段（如第三次握手且不携带应用层数据时），由于 $\text{SYN}=0$$ \text{且} $$\text{FIN}=0$，**不消耗序号**。若其未携带数据，其下一个发送报文段将继续沿用此序号。

### 2. 三次握手工作流程和状态机迁移

三次握手的标准时序及状态变迁如下图所示：

```text
      客户端 (Client)                                  服务器端 (Server)
    [ CLOSED ]                                           [ CLOSED ]
        |                                                    |
        | 应用程序被动打开                                    | 应用程序被动打开
        |                                                    v
        |                                               [ LISTEN ]
        |                                                    |
        | 应用程序主动打开                                    |
        | 发送 SYN=1, seq=x                                  |
        v                                                    |
   [ SYN_SENT ] ---------------- SYN=1, seq=x -------------> | 接收 SYN
        |                                                    | 创建 TCB
        |                                                    v
        |                                               [ SYN_RCVD ]
        |                                                    |
        | <------- SYN=1, ACK=1, seq=y, ack=x+1 ------------ | 发送 SYN+ACK
        |                                                    |
   接收 SYN+ACK                                              |
   发送 ACK=1, seq=x+1, ack=y+1                              |
        v                                                    |
 [ ESTABLISHED ] ------- ACK=1, seq=x+1, ack=y+1 ----------> | 接收 ACK
        |                                                    v
 (可立即发送数据)                                       [ ESTABLISHED ]
```

#### （1）三次握手全时序交互详解

- **第一次握手（Client $\to$ Server）**：
  - **控制位**：$\text{SYN}=1, \text{ACK}=0$。
  - **序号**：$\text{seq} = x$$ \text{（客户端随机选取的初始序号} $$\text{ISN}_{\text{client}}$）。
  - **载荷**：不携带应用层数据。
  - **动作**：客户端由 `CLOSED` 转移至 `SYN_SENT` 状态；服务端收到后为该连接分配传输控制块（TCB），从 `LISTEN` 转移至 `SYN_RCVD` 状态。

- **第二次握手（Server $\to$ Client）**：
  - **控制位**：$\text{SYN}=1, \text{ACK}=1$。
  - **序号**：$\text{seq} = y$$ \text{（服务端随机选取的初始序号} $$\text{ISN}_{\text{server}}$）。
  - **确认号**：$\text{ack} = x + 1$（对客户端初始序号的确认）。
  - **载荷**：不携带应用层数据。
  - **动作**：服务端发出响应报文段；客户端收到后确认服务端已正确接收其初始序号，客户端进入 `ESTABLISHED` 状态。

- **第三次握手（Client $\to$ Server）**：
  - **控制位**：$\text{SYN}=0, \text{ACK}=1$。
  - **序号**：$\text{seq} = x + 1$。
  - **确认号**：$\text{ack} = y + 1$（对服务端初始序号的确认）。
  - **载荷**：**可以携带应用层数据**，若不携带数据则不消耗序号。
  - **动作**：服务端收到该报文段后，确认客户端已收到自己的初始序号，服务端进入 `ESTABLISHED` 状态。此时双向通信信道完全建立。

#### （2）状态机迁移关键路径总结
- **客户端变迁路径**：`CLOSED` $\to$ `SYN_SENT` $\to$ `ESTABLISHED`
- **服务端变迁路径**：`CLOSED` $\to$ `LISTEN` $\to$ `SYN_RCVD` $\to$ `ESTABLISHED`

### 3. 连接建立时间延迟计算推导

在 408 综合题及选择题中，连接建立的时延是全流程时延计算的起点：

1. **单向传播时延**记为 $t_{\text{prop}}$$ \text{，往返时延记为} $$\text{RTT} = 2 \times t_{\text{prop}}$。
2. 忽略分组传输时延和排队时延：
   - 客户端发送第一次握手（经过 $0.5 \times \text{RTT}$ 到达服务端）。
   - 服务端发出第二次握手（经过 $0.5 \times \text{RTT}$ 到达客户端）。
   - 客户端此时进入 `ESTABLISHED` 状态，耗时共计：
     $$T_{\text{client\_ready}} = 0.5 \times \text{RTT} + 0.5 \times \text{RTT} = 1 \times \text{RTT}$$
   - 客户端发送第三次握手报文段。根据 RFC 793 协议规范，第三次握手可以携带客户端发送给服务器的第一批应用层数据（例如 HTTP GET 请求）。
   - 服务端接收到第三次握手并解析到数据，耗时为：
     $$T_{\text{server\_recv}} = 1 \times \text{RTT} + 0.5 \times \text{RTT} = 1.5 \times \text{RTT}$$
   - 服务端回传应用层响应数据至客户端，客户端收到首个响应字节所耗费的总时间为：
     $$T_{\text{response\_received}} = 1.5 \times \text{RTT} + 0.5 \times \text{RTT} = 2 \times \text{RTT}$$

**考点结论**：纯粹建立连接的过程（客户端从发起连接到可以发送数据）消耗 $1 \times \text{RTT}$$ \text{；服务端从收到请求到完成连接同样消耗} $$1 \times \text{RTT}$$ \text{；客户端发起连接到接收到首个应用层响应数据至少耗时} $$2 \times \text{RTT}$。

### 4. 核心原理深入：为什么两次握手无法满足可靠建立连接？

考研大题和选择题反复考查“为什么不能采用两次握手”。其本质原因在于以下两点数学及系统层面的严格约束：

#### （1）防止已失效的历史连接请求报文段引发资源死锁
考虑以下典型异常时序模型：
1. 客户端发送了一个连接请求报文段 $\text{SYN}_1$。由于网络节点发生严重拥塞，该报文在网络某个路由器队列中长时间滞留，未能按时到达服务端。
2. 客户端在重传定时器超时后，判定 $\text{SYN}_1$$ \text{丢失，遂重新发送} $$\text{SYN}_2$。
3. 服务端正常收到 $\text{SYN}_2$，双方通过三次握手建立连接，数据传输完毕后正常断开连接并释放资源。
4. 在此之后，滞留在网络中的 $\text{SYN}_1$ 终于送达服务端。这是一个**已经失效的历史报文段**。

**若采用两次握手机制**：
- 服务端只要收到 $\text{SYN}_1$，便认为客户端又发起了一次新连接，立即分配传输控制块（TCB）、输入输出缓存并发送确认报文段，单方面进入 `ESTABLISHED` 状态。
- 但客户端此前已收到数据并关闭连接，或者当前并未发出此请求，客户端处于 `CLOSED` 状态，对服务端的确认报文不予理睬，更不会发送数据。
- 服务端由此一直处于等待数据状态，导致服务器端的 CPU、内存和套接字资源被无限期占用，产生死锁及资源泄漏。

**在三次握手机制下的防护**：
- 服务端收到 $\text{SYN}_1$$ \text{后，回复确认段（携带确认号} $$\text{ack} = x_1 + 1$）。
- 客户端收到该确认报文时，发现自己并未维护对应 $x_1$$ \text{序号的连接，立刻向服务端发送复位报文段（} $$\text{RST}=1$）。
- 服务端收到 $\text{RST}$ 后，立即终止连接建立，释放预分配资源，避免了死锁。

#### （2）双向序列号同步及全双工确认不可或缺
TCP 是全双工信道，必须保证两个方向上的序列号都经过确认：
- 客户端选定 $\text{ISN}_{\text{client}}$，必须由服务端发送 ACK 确认已接收；
- 服务端选定 $\text{ISN}_{\text{server}}$，必须由客户端发送 ACK 确认已接收。
两次握手只能完成服务端对客户端序号的确认，服务端无法得知客户端是否已经成功接收了自己的 $\text{ISN}_{\text{server}}$，无法建立可靠的双向同步。

### 5. 网络安全机制：SYN Flood 攻击原理和 SYN Cookie 防御

三次握手机制在实现可靠连接的同时，也引入了半开连接的脆弱性。

#### （1）SYN Flood 攻击机理剖析
在操作系统的 TCP 协议栈底层，维护着两个重要队列：
- **半连接队列（SYN Queue / Incomplete Connection Queue）**：存放收到 SYN 并回复了 SYN+ACK、正在等待第三次握手 ACK 的套接字条目。
- **全连接队列（Accept Queue / Completed Connection Queue）**：存放已完成三次握手、等待应用程序调用 `accept()` 取出的套接字条目。

**攻击模型**：
攻击者向服务端伪造源 IP 地址发送大量 $\text{SYN}=1$ 请求，但从不发送第三次握手 ACK，或者使源地址指向不存在的主机导致响应超时。服务端发送 SYN+ACK 后必须为每个连接创建 TCB 并启动重传定时器。随着时间推移，半连接队列被未决的半开连接（`SYN_RCVD` 状态）迅速占满，正常用户的 SYN 请求将因队列溢出被丢弃，造成拒绝服务（DoS）。

#### （2）SYN Cookie 防御机制
为了抵御 SYN Flood 攻击，Linux 等操作系统引入了 SYN Cookie 技术：
- **核心思想**：服务端收到客户端 SYN 报文段时，**不在内存中分配 TCB 或半连接条目**。
- **动态编码生成 $\text{ISN}_{\text{cookie}}$$ \text{**：服务端利用单向散列加密算法，将客户端连接要素编码到服务端的初始序号} $$\text{ISN}_{\text{server}}$ 中：
  $$\text{ISN}_{\text{server}} = \text{Hash}( \text{src\_ip}, \text{dst\_ip}, \text{src\_port}, \text{dst\_port}, t, \text{secret\_key} ) + \text{MSS\_Index}$$
  其中 $t$$ \text{为随时间缓慢递增的计数器，} $$\text{MSS\_Index}$ 编码了双方协商的 MSS 大小。
- **校验还原**：
  - 若客户端是正常主机，它将回复第三次握手 ACK，其确认号为 $\text{ack} = \text{ISN}_{\text{server}} + 1$。
  - 服务端收到后，计算 $\text{ack} - 1$，利用预设密钥重新运算散列函数比对；若哈希匹配且时间窗口合法，直接从计算结果中还原出 MSS 等连接参数，当场分配连接结构并直接置入全连接队列。
  - 这种设计避免了在收到 ACK 之前占用服务器内核内存。

### 6. 重点易混淆概念对比剖析

| 辨析维度 | 第一次握手（SYN） | 第二次握手（SYN+ACK） | 第三次握手（ACK） |
| :--- | :--- | :--- | :--- |
| **首部标志位** | $\text{SYN}=1, \text{ACK}=0$ | $\text{SYN}=1, \text{ACK}=1$ | $\text{SYN}=0, \text{ACK}=1$ |
| **发送方** | 客户端（发起主动打开） | 服务端（响应被动打开） | 客户端（确认连接） |
| **是否消耗序号** | **必须消耗 1 个序号** | **必须消耗 1 个序号** | **不携带数据时不消耗**；携带数据则按字节数消耗 |
| **能否携带数据** | **绝对不能携带数据** | **绝对不能携带数据** | **允许携带应用层数据** |
| **异常处理措施** | 超时未收到回复则按指数退避重传 SYN | 超时未收到 ACK 则重传 SYN+ACK | 服务端未收到则重传第二次握手，客户端若发数据会超时重发 |
| **底层队列归属** | 进入半连接队列预备 | 驻留半连接队列（`SYN_RCVD`） | 服务端处理完毕后转入全连接队列（`Accept Queue`） |

## 三、 近十年真题精讲（2016~2025）

### 1. 2024 年全国统考 408 第 38 题

#### 【真题题干】
假设主机 H 通过 TCP 向服务器发送长度为 $3000\text{ B}$$ \text{的报文，往返时间} $$\text{RTT}=10\text{ ms}$$ \text{，最长报文段寿命} $$\text{MSL}=30\text{ s}$$ \text{，最大报文段长度} $$\text{MSS}=1000\text{ B}$，忽略 TCP 段的传输时延，报文传输结束后 H 首先请求断开连接，则从 H 请求建立 TCP 连接时刻起，到 H 进入 CLOSED 状态为止，所需时间至少是（ ）。
A. $30.03\text{ s}$  
B. $30.04\text{ s}$  
C. $60.03\text{ s}$  
D. $60.04\text{ s}$  

#### 【深度解析及推导过程】
本题全面考查了 TCP 连接建立（三次握手）、拥塞控制慢开始数据传输、连接释放（四次挥手）全生命周期的时序计算。

1. **连接建立阶段（三次握手）**：
   - 客户端 H 发送第一次握手 SYN 段，经 $0.5\text{ RTT}$ 到达服务器。
   - 服务器回复第二次握手 SYN+ACK 段，经 $0.5\text{ RTT}$ 到达 H。
   - H 收到后发出第三次握手 ACK 段，此时 H 的 TCP 连接正式建立。
   - 在此题中，H 发出第三次握手的同时即可连续发送应用层数据（数据可捎带或紧随发送），因此建立连接阶段所需的基础往返时延为：
     $$T_1 = 1 \times \text{RTT} = 10\text{ ms}$$

2. **数据传输阶段（慢开始算法）**：
   - 待传输数据总量为 $3000\text{ B}$$ \text{，已知} $$\text{MSS} = 1000\text{ B}$，共计 3 个 MSS 数据段。
   - 依据 TCP 慢开始机制：
     - **第 1 个传输轮次**：初始拥塞窗口 $\text{cwnd} = 1\text{ MSS} = 1000\text{ B}$$ \text{。H 发送第 1 个报文段（} $$1000\text{ B}$$ \text{），等待服务器确认，经历} $$1 \times \text{RTT}$$ \text{。收到确认后，} $$\text{cwnd}$$ \text{翻倍变为} $$2\text{ MSS} = 2000\text{ B}$。
     - **第 2 个传输轮次**：$\text{cwnd} = 2\text{ MSS} = 2000\text{ B}$$ \text{。H 可以连续发送剩余的 2 个报文段（第 2 和第 3 个报文段，共} $$2000\text{ B}$$ \text{），等待服务器确认，经历} $$1 \times \text{RTT}$。
   - 至此，$1000\text{ B} + 2000\text{ B} = 3000\text{ B}$ 全部发送并确认完毕。
   - 数据传输阶段耗时：
     $$T_2 = 1 \times \text{RTT} + 1 \times \text{RTT} = 2 \times \text{RTT} = 20\text{ ms}$$

3. **连接释放阶段（四次挥手）**：
   - 数据传输完成后，H 立即主动请求断开连接，发送第一次挥手 FIN 段。
   - 服务器收到后回复第二次挥手 ACK 段。由于此时服务器端无数据需要向 H 发送，服务器紧接着发出第三次挥手 FIN 段（或者将第二次和第三次挥手合并发送）。
   - 从 H 发出第一次挥手 FIN，到收到服务器的 FIN 并发出第四次挥手 ACK，至少经历：
     $$T_{\text{wave}} = 1 \times \text{RTT} = 10\text{ ms}$$
   - **关键状态驻留机制**：H 在发出第四次挥手 ACK 报文段后，不能立即进入 `CLOSED` 状态，必须进入 `TIME_WAIT` 状态并启动时间等待计时器，经过 $2\text{MSL}$ 之后，才最终转移至 `CLOSED` 状态。
   - 因此连接释放耗费的时间为：
     $$T_3 = 1 \times \text{RTT} + 2 \times \text{MSL} = 10\text{ ms} + 2 \times 30\text{ s} = 60.01\text{ s}$$

4. **全过程总耗时汇总**：
   $$T_{\text{total}} = T_1 + T_2 + T_3 = 1\text{ RTT} + 2\text{ RTT} + (1\text{ RTT} + 2\text{ MSL}) = 4\text{ RTT} + 2\text{ MSL}$$
   代入数值：
   $$T_{\text{total}} = 4 \times 10\text{ ms} + 2 \times 30\text{ s} = 0.04\text{ s} + 60\text{ s} = 60.04\text{ s}$$

#### 【正确答案】
**D**

### 2. 2020 年全国统考 408 第 39 题

#### 【真题题干】
若主机甲与主机乙建立 TCP 连接时发送的 SYN 段中的序号为 1000，在断开连接时，甲发送给乙的 FIN 段中的序号为 5001，则在无任何重传的情况下，甲向乙已经发送的应用层数据的字节数为（ ）。
A. 4002  
B. 4001  
C. 4000  
D. 3999  

#### 【深度解析及推导过程】
本题重点考查 TCP 序号连续编址规则及特殊控制位消耗序号的规定。

1. **初始序号及首个数据字节的对应关系**：
   - 主机甲发起建立连接时，发送的第一次握手报文段中 $\text{SYN}=1$$ \text{，其序列号} $$\text{seq} = 1000$。
   - 根据 TCP 协议规定，SYN 段不携带应用层数据，但必须**虚拟消耗 1 个序号**。
   - 因此，TCP 连接建立后，主机甲发送的第一个应用层数据字节所占用的序号必须是：
     $$\text{Seq}_{\text{start}} = 1000 + 1 = 1001$$

2. **终止序号及末尾数据字节的对应关系**：
   - 设主机甲在连接期间共向乙发送了 $N$ 个字节的应用层数据。
   - 这 $N$ 个字节在序号空间中占据连续的区间，其序号范围为：
     $$[1001, \, 1001 + N - 1]$$
     即最后一个数据字节占用的序号为 $1000 + N$。
   - 数据发送完毕后，主机甲发送断开连接的 FIN 报文段。FIN 报文段的序号必须紧接在最后一个发送的数据字节之后：
     $$\text{seq}_{\text{FIN}} = (1000 + N) + 1 = 1001 + N$$

3. **代入求解数据字节数 $N$**：
   - 题目给定 FIN 段中的序号为 5001：
     $$1001 + N = 5001 \implies N = 5001 - 1001 = 4000$$
   - 即甲向乙发送的应用层数据字节数恰好为 4000 字节。

#### 【正确答案】
**C**

### 3. 2019 年全国统考 408 第 39 题

#### 【真题题干】
若主机甲主动发起一个与主机乙的 TCP 连接，甲、乙选择的初始序列号分别为 2018 和 2046，则第三次握手 TCP 段的确认序列号是（ ）。
A. 2018  
B. 2019  
C. 2046  
D. 2047  

#### 【深度解析及推导过程】
本题直接考查三次握手中确认号字段的生成原理及递增计算。

1. **各次握手报文段参数推演**：
   - **第一次握手（甲 $\to$ 乙）**：
     - 甲主动发起连接，首部设置 $\text{SYN}=1, \text{ACK}=0$。
     - 甲选取的初始序列号为 $$ \text{seq} = \text{ISN}_{\text{甲}} = 2018 $$。
     - 由于此段属于主动发起，无前序报文需要确认，$\text{ack}$ 字段无效。
   - **第二次握手（乙 $\to$ 甲）**：
     - 乙同意建立连接，首部设置 $\text{SYN}=1, \text{ACK}=1$。
     - 乙选取的初始序列号为 $$ \text{seq} = \text{ISN}_{\text{乙}} = 2046 $$。
     - 乙对甲的 SYN 进行确认：因为甲的 SYN 消耗一个序号（2018），故乙期望收到甲的下一个字节序号为 $2018 + 1 = 2019$$ \text{。即确认号} $$\text{ack} = 2019$。
   - **第三次握手（甲 $\to$ 乙）**：
     - 甲收到乙的确认后，发出最后的确认报文段，首部设置 $\text{SYN}=0, \text{ACK}=1$。
     - 甲的发送序号为：$\text{seq} = 2019$。
     - 甲必须对乙的 SYN 报文段进行确认：乙发来的报文段中 $\text{SYN}=1, \text{seq}=2046$$ \text{，同样消耗一个序号，因此甲期望收到的乙的下一个序号为} $$2046 + 1 = 2047$。
     - 故甲发送的第三次握手报文段中的确认序列号（$\text{ack}$）应为 2047。

#### 【正确答案】
**D**

### 4. 2016 年全国统考 408 第 41 题

#### 【真题题干】
假设题 33～41 图中的 H3 访问 Web 服务器 S 时，S 为新建的 TCP 连接分配了 $20\text{ KB}$ ($K=1024$$ \text{) 的接收缓存，最大段长} $$\text{MSS}=1\text{ KB}$$ \text{，平均往返时间} $$\text{RTT}=200\text{ ms}$$ \text{。H3 建立连接时的初始序号为 100，且持续以 MSS 大小的段向 S 发送数据，拥塞窗口初始阈值为} $$32\text{ KB}$；S 对收到的每个段进行确认，并通告新的接收窗口。假定 TCP 连接建立完成后，S 端的 TCP 接收缓存仅有数据存入而无数据取出。请回答下列问题。
(1) 在 TCP 连接建立过程中，H3 收到的 S 发送过来的第二次握手 TCP 段的 SYN 和 ACK 标志位的值分别是多少？确认序号是多少？  
(2) H3 收到的第 8 个确认段所通告的接收窗口是多少？此时 H3 的拥塞窗口变为多少？H3 的发送窗口变为多少？  
(3) 当 H3 的发送窗口等于 0 时，下一个待发送的数据段序号是多少？H3 从发送第 1 个数据段到发送窗口等于 0 时刻为止，平均数据传输速率是多少（忽略段的传输延时）？  
(4) 若 H3 与 S 之间通信已经结束，在 $t$$ \text{时刻 H3 请求断开该连接，则从} $$t$ 时刻起，S 释放该连接的最短时间是多少？  

#### 【深度解析及推导过程】

- **小问 (1) 解析（三次握手核心考点）**：
  - 客户端 H3 发起的第一次握手：$\text{SYN}=1, \text{seq}=100$。
  - 服务端 S 收到后回复第二次握手报文段。按照协议标准规范：
    - 同步标志位：$\text{SYN}=1$。
    - 确认标志位：$\text{ACK}=1$。
    - 确认序号：对 H3 初始序号（100）的确认，SYN 消耗 1 个序号，故确认序号为 $\text{ack} = 100 + 1 = 101$。

- **小问 (2) 解析（滑动窗口及慢开始机制联动）**：
  - S 的接收缓存总量为 $20\text{ KB}$$ \text{。题目给定“接收缓存仅有数据存入而无数据取出”，因此每收到一个} $$1\text{ KB}$$ \text{的数据段，接收缓存可用空间减少} $$1\text{ KB}$。
  - 当收到第 8 个确认段时，S 已存入 8 个段（共 $8\text{ KB}$ 数据），通告的接收窗口为：
    $$\text{rwnd} = 20\text{ KB} - 8\text{ KB} = 12\text{ KB}$$
  - H3 处于慢开始阶段，初始拥塞窗口 $\text{cwnd} = 1\text{ KB}$$ \text{。在慢开始算法中，发送方**每收到一个确认段**，拥塞窗口增加} $$1\text{ MSS} = 1\text{ KB}$。收到了 8 个确认段，因此：
    $$\text{cwnd} = 1\text{ KB} + 8 \times 1\text{ KB} = 9\text{ KB}$$
  - 发送方的发送窗口受流量控制和拥塞控制共同制约：
    $$ \text{发送窗口} = \min(\text{cwnd}, \text{rwnd}) = \min(9\text{ KB}, 12\text{ KB}) = 9\text{ KB} $$

- **小问 (3) 解析（字节序列号计算及传输速率）**：
  - 发送窗口等于 0 时，意味着 S 端接收缓存已被填满，通告的 $\text{rwnd} = 0$$ \text{，即 S 已接收了全部} $$20\text{ KB} = 20 \times 1024 = 20480\text{ B}$ 的数据。
  - 数据的起始序号为 101，已发送并接收的字节区间为 $[101, 101 + 20480 - 1] = [101, 20580]$。
  - 因此下一个待发送的数据段的起始序号为：
    $$\text{Next\_Seq} = 20480 + 101 = 20581$$
  - 经历的传输轮次分析（慢开始翻倍过程）：
    - 轮次 1：发 1KB（累计 1KB），耗时 1 RTT；
    - 轮次 2：发 2KB（累计 3KB），耗时 1 RTT；
    - 轮次 3：发 4KB（累计 7KB），耗时 1 RTT；
    - 轮次 4：发 8KB（累计 15KB），耗时 1 RTT；
    - 轮次 5：还剩 $20 - 15 = 5\text{ KB}$，发送 5KB（累计 20KB），耗时 1 RTT。
    - 共有 5 个传输轮次，总耗时：
      $$T = 5 \times \text{RTT} = 5 \times 200\text{ ms} = 1000\text{ ms} = 1\text{ s}$$
  - 平均数据传输速率：
    $$\text{Rate} = \frac{20\text{ KB}}{1\text{ s}} = 20\text{ KB/s} = 20 \times 1024 \times 8\text{ bps} = 163.84\text{ kbps}$$
    （注：按大题官方评分细则，答 $20\text{ KB/s}$$ \text{或} $$163.84\text{ kbps}$ 均可给满分）。

- **小问 (4) 解析（四次挥手最短释放时间）**：
  - 通信结束，H3 在 $t$ 时刻发出连接释放报文段（第一次挥手）。
  - S 收到后发出确认（第二次挥手），且因 S 已经没有数据传输，S 可以紧接着发出释放报文（第三次挥手）。
  - H3 收到 S 的释放报文后，向 S 发出确认报文段（第四次挥手）。
  - S 收到该确认段后即刻释放连接。因此从 $t$ 时刻起，S 释放该连接的最短时间是：
    $$T = 1.5 \times \text{RTT} = 1.5 \times 200\text{ ms} = 300\text{ ms}$$

#### 【答案汇总】
- (1) $\text{SYN}=1$，$\text{ACK}=1$；确认序号是 101。
- (2) 通告的接收窗口为 $12\text{ KB}$$ \text{；拥塞窗口} $$\text{cwnd}$$ \text{为} $$9\text{ KB}$$ \text{；发送窗口为} $$9\text{ KB}$。
- (3) 下一个待发送数据段序号是 20581；平均数据传输速率为 $20\text{ KB/s}$$ \text{（或} $$163.84\text{ kbps}$）。
- (4) S 释放该连接的最短时间是 $300\text{ ms}$。

## 四、 综合解答题深度拓展（大题考法联动）

在 408 统考综合应用大题中，TCP 三次握手经常结合应用层协议、网络层路由及数据链路层封装进行全协议栈串联考核。考生需掌握以下三种核心考法及思维模型：

### 1. 跨层时序串联分析模型
一个完整的网络通信过程（例如在浏览器中输入网址 `http://www.abc.com`）在大题中通常被分解为以下四个有序阶段：

```text
阶段 1: DNS 域名解析
  └── 若本地无缓存，H 发送 DNS 查询报文（基于 UDP）经路由器至 DNS 服务器，经历解析时延。
阶段 2: ARP 地址解析
  └── 若本地 ARP 表无网关 MAC，H 先广播 ARP 请求获取默认网关 MAC 地址。
阶段 3: TCP 三次握手
  └── H 和 Web 服务器建立 TCP 连接，消耗 1 个 RTT。
阶段 4: HTTP 报文交互
  └── H 发送 HTTP 请求报文（可由第三次握手捎带或紧随发出），服务器返回页面数据，至少消耗 1 个 RTT。
```

**解题技巧**：题目若设问“从主机发出连接请求到收到首批 Web 页面数据经过了多长时间”，计算时切勿漏掉 TCP 三次握手的 $1 \times \text{RTT}$$ \text{开销。若未采用持久连接，每次请求新对象都需要重新经历} $$1 \times \text{RTT}$ 的握手时延。

### 2. 真实 Wireshark 抓包序列分析及状态推断
大题常常给出一组网络抓包表格，要求考生补全字段或判断连接所处的具体阶段：
- **抓包标志识别法则**：
  - 若抓包条目仅有 `[SYN]` 且 `ACK=0`，必为**第一次握手**，源端口为客户端随机端口，目的端口为知名端口（如 80、443），此端处于 `SYN_SENT`。
  - 若抓包条目为 `[SYN, ACK]`，必为**第二次握手**，源端口为服务器端口，确认号为客户端 seq + 1。
  - 若抓包条目为 `[ACK]` 且 `Length=0`，紧随在第二次握手之后，必为**第三次握手**，此后连接建立完成（`ESTABLISHED`）。
- **确认号连续性判定法则**：
  - 无论抓包序列多么复杂，牢记数学公式：
    $$ \text{下一个期望确认号 ack} = \text{当前报文序号 seq} + \text{有效载荷长度 Payload\_Len} + (\text{SYN 或 FIN 控制位占用数}) $$

### 3. 大题常见失分陷阱剖析
- **陷阱 1：SYN 报文序号消耗的遗忘**。计算后续数据段序号时，误将客户端初始序号直接作为数据第一个字节的序号。必须记住：首字节序号为 $\text{ISN} + 1$。
- **陷阱 2：混淆连接建立耗时及应用数据传输耗时**。握手本身耗费 $1 \times \text{RTT}$$ \text{，慢开始第一轮发送数据又耗费} $$1 \times \text{RTT}$，两者是前后相继的时序关系，不能简单重叠。
- **陷阱 3：混淆半连接队列和全连接队列的溢出表现**。SYN Flood 攻击导致的是半连接队列满，系统表现为新收到的 SYN 报文被直接丢弃；而全连接队列满通常是由于应用层进程处理过慢未能及时调用 `accept()`，导致完成三次握手的 ACK 被丢弃或响应 RST。

## 五、 考点速记清单

### 1. 核心结论速记
- **标志位口诀**：一握 SYN，二握 SYN+ACK，三握纯 ACK；前两握手绝无数据，第三握手方可带载荷。
- **序号消耗口诀**：SYN 为 1 必耗号，FIN 为 1 亦耗号；纯 ACK 若无数据，绝不平白占序号。
- **时延口诀**：握手成链耗一时延（$1\text{ RTT}$$ \text{），首包响应两时延（} $$2\text{ RTT}$$ \text{），挥手等待终了归于} $$2\text{MSL}$。

### 2. 避坑指南（四必须、四严防）
- **必须**在计算数据起始序号时在 $\text{ISN}$ 基础上加 1。
- **必须**区分主动发起端（发出 SYN，状态为 `SYN_SENT`）和被动响应端（发出 SYN+ACK，状态为 `SYN_RCVD`）。
- **必须**在计算总传输时间时准确判断慢开始每个轮次传输的 MSS 段数（1, 2, 4, 8...）。
- **必须**注意第三次握手若丢失，服务器将依据超时重传定时器反复重传第二次握手报文段。
- **严防**将两次握手误认为可以防范失效连接报文段。
- **严防**混淆发送窗口的计算：$$ \text{发送窗口} = \min(\text{cwnd}, \text{rwnd}) $$。
- **严防**遗漏 $2\text{MSL}$ 的等待阶段，只有主动断开连接方才进入 `TIME_WAIT`。
- **严防**在大题计算速率时混淆字节单位（$\text{B/s}$$ \text{）和比特单位（} $$\text{bps}$），$1\text{ B} = 8\text{ bit}$。

### 3. 高频公式速查表

| 公式项目 | 物理含义及数学表达式 |
| :--- | :--- |
| **第一次握手报文** | $\text{SYN}=1, \text{ACK}=0, \text{seq}=x$ |
| **第二次握手报文** | $\text{SYN}=1, \text{ACK}=1, \text{seq}=y, \text{ack}=x+1$ |
| **第三次握手报文** | $\text{SYN}=0, \text{ACK}=1, \text{seq}=x+1, \text{ack}=y+1$ |
| **首个数据字节序号** | $\text{Seq}_{\text{first\_byte}} = \text{ISN}_{\text{client}} + 1$ |
| **FIN 段序号** | $\text{seq}_{\text{FIN}} = \text{Seq}_{\text{first\_byte}} + \text{Data\_Bytes}$ |
| **发送窗口计算** | $W_{\text{send}} = \min(\text{cwnd}, \text{rwnd})$ |
| **三次握手单向耗时** | 客户端就绪耗时 $1 \times \text{RTT}$$ \text{；服务端就绪耗时} $$1 \times \text{RTT}$ |
| **断开释放总延时** | $T_{\text{release}} \ge 1 \times \text{RTT} + 2 \times \text{MSL}$（主动关闭方进入 CLOSED 最短时间） |
