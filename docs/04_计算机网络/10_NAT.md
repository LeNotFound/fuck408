## 二、 具体考察内容

### 1. 私有 IP 地址及 NAT 产生背景

#### 1.1 IPv4 地址危机和私有 IP 地址（RFC 1918）
IPv4 采用 32 位地址编址，理论最大地址容量仅为 $2^{32} \approx 42.9$ 亿个。随着互联网规模爆炸式增长，全球公网 IPv4 地址迅速耗尽。为缓解该危机，IETF 制定了两项关键过渡技术：
- **CIDR（无类域间路由）**：消除传统分类编址造成的地址块内部浪费。
- **NAT（网络地址转换）**：允许多台内部网络主机共用少数甚至一个全球唯一的公网 IP 地址接入互联网。

为保证内部局域网的独立运行，RFC 1918 专门保留了三段 IP 地址作为**专用地址（Private Address）**，亦称**私有 IP 地址**或**内部地址**：

```text
+------+-----------------------+-----------------------------+---------------+--------------+
| 类别 | CIDR 前缀表示         | 私有 IP 地址范围            | 包含网络块数  | 单网络主机容量 |
+------+-----------------------+-----------------------------+---------------+--------------+
| A 类 | 10.0.0.0/8            | 10.0.0.0 ~ 10.255.255.255   | 1 个 A 类网络 | $2^{24}-2$   |
| B 类 | 172.16.0.0/12         | 172.16.0.0 ~ 172.31.255.255 | 16 个 B 类网络| $2^{20}-2$   |
| C 类 | 192.168.0.0/16        | 192.168.0.0 ~ 192.168.255.255| 256 个 C 类网络| $2^{16}-2$  |
+------+-----------------------+-----------------------------+---------------+--------------+
```

#### 1.2 私有 IP 地址的路由特性
1. **本地唯一性**：私有 IP 地址仅在企业网、校园网或家庭内部网络中有效，不同内部网络可以重复使用相同的私网地址段而互不干扰。
2. **公网不可路由性**：互联网所有骨干路由器和公网边界路由器的路由表中均不包含私网地址的路由表项。若公网路由器收到源 IP 或目的 IP 为私有地址的 IP 分组，会直接予以丢弃，不向公网核心转发。
3. **互联转换要求**：内部网络主机若要和互联网上的主机通信，必须通过部署在网络出口处的具备 NAT 功能的路由器，将其私有 IP 地址转换为全球唯一的公网 IP 地址。

### 2. NAT 和 NAPT 工作原理

NAT 技术经历了从单纯网络层地址替换到结合传输层端口复用的演进过程。

```text
                               NAT 技术的演进分类
                                       │
        ┌──────────────────────────────┴──────────────────────────────┐
        ▼                                                             ▼
   传统 NAT (单纯网络层)                                     网络地址端口转换 (NAPT / PAT)
        ├─ 静态 NAT (1 对 1 固定映射)                                 ├─ 动态 NAPT (多对 1，端口多路复用)
        └─ 动态 NAT (多对多地址池映射)                                └─ 端口映射 (静态 DNAT / 虚拟服务器)
```

#### 2.1 基础 NAT（Basic NAT）
- **静态 NAT（Static NAT）**：
  内部私有 IP 地址和外部公有 IP 地址建立一对一的固定静态映射表项。外部公网 IP 数量和内部同时外访的主机数量严格相等，不节约公网 IP，主要用于将内部特定服务器长期发布给外部访问。
- **动态 NAT（Dynamic NAT）**：
  NAT 路由器配置一个合法的公网 IP 地址池。当内部主机向外部发送数据报时，NAT 路由器动态从地址池中分配一个空闲的公网 IP 替换其源 IP，并在映射表中记录。会话结束后归还公网 IP。
  若公网地址池中地址已耗尽，后续内部主机的出站连接将被拒绝。因此动态 NAT 无法实现真正意义上的地址多路复用。

#### 2.2 网络地址端口转换（NAPT / PAT）
网络地址端口转换（Network Address Port Translation, NAPT）又称端口地址转换（PAT）或端口多路复用。**408 统考及实际工业界中所泛指的 NAT，若无特别说明，默认均为 NAPT。**

NAPT 巧妙地利用了传输层协议（TCP 或 UDP）的 **16 位端口号**，将多个内部私有 IP 地址映射到同一个外部公网 IP 地址的不同端口上，实现极高密度的 IP 地址复用。

理论上，一个公网 IPv4 地址拥有 $2^{16} = 65536$$ \text{个端口号。除去熟知端口号（} $$0 \sim 1023$），单个公网 IP 可同时支持数万个并发传输层会话。

### 3. NAPT 转换表项及动态双向转换流程

#### 3.1 NAPT 转换表结构
NAPT 路由器内部维护一张动态地址转换表，其核心表项包含四元组或五元组信息：

$$ \text{\{\text{协议类型}, \text{内部私网 IP}, \text{内部源端口}, \text{外部公网 IP}, \text{外部转换端口}\}} $$

若需要更精细的会话跟踪，还会包含外部目的端主机的 IP 和目的端口。

#### 3.2 动态双向工作流程（出站及入站）

假设内网主机 $H$（IP: $192.168.1.5$$ \text{）通过客户端程序（分配临时源端口} $$50001$$ \text{）访问公网 Web 服务器} $$S$$ \text{（公网 IP:} $$203.0.113.8$$ \text{，端口} $$80$$ \text{）。NAPT 路由器的外网接口公网 IP 为} $$101.1.2.10$。

```text
内网主机 H                               NAPT 路由器                          公网服务器 S
(192.168.1.5)                            (WAN: 101.1.2.10)                    (203.0.113.8:80)
      │                                         │                                    │
      │  [出站] IP: 192.168.1.5 -> 203.0.113.8   │                                    │
      │         TCP: 50001 -> 80                │                                    │
      ├────────────────────────────────────────>│  查表未命中，建立映射：             │
      │                                         │  (192.168.1.5, 50001) <->          │
      │                                         │  (101.1.2.10, 60001)               │
      │                                         │                                    │
      │                                         │  [转发出站] IP: 101.1.2.10 -> 203.0.113.8
      │                                         │            TCP: 60001 -> 80        │
      │                                         ├───────────────────────────────────>│
      │                                         │                                    │
      │                                         │  [入站回包] IP: 203.0.113.8 -> 101.1.2.10
      │                                         │            TCP: 80 -> 60001        │
      │                                         │<───────────────────────────────────┤
      │                                         │  查表命中，执行反向替换：           │
      │                                         │  目的 IP 替换为 192.168.1.5         │
      │                                         │  目的端口替换为 50001               │
      │                                         │                                    │
      │  [转发入站] IP: 203.0.113.8 -> 192.168.1.5│                                    │
      │            TCP: 80 -> 50001             │                                    │
      │<────────────────────────────────────────┤                                    │
```

1. **出站连接（SNAT 过程，内部访问外部）**：
   - 主机 $H$$ \text{发送 TCP 分组，源地址为} $$(192.168.1.5, 50001)$$ \text{，目的地址为} $$(203.0.113.8, 80)$。
   - NAPT 路由器收到该分组，检查 NAPT 表。若不存在对应项，则从其空闲端口池中分配一个临时端口（如 $60001$）。
   - 路由器将表项写入 NAPT 表：
     
     $$ \text{WAN 端 } (101.1.2.10, 60001) \longleftrightarrow \text{LAN 端 } (192.168.1.5, 50001) $$
     
   - 路由器修改数据报：将**源 IP 地址**替换为 $101.1.2.10$$ \text{，将**源端口号**替换为} $$60001$。目的 IP 和目的端口保持不变。
   - 重新计算 IP 首部校验和及 TCP 校验和，更新 TTL，将分组通过 WAN 口转发至 Internet。

2. **入站应答（DNAT 过程，外部回应内部）**：
   - Web 服务器 $S$$ \text{收到请求并生成响应报文，其源地址为} $$(203.0.113.8, 80)$$ \text{，目的地址为} $$(101.1.2.10, 60001)$。
   - NAPT 路由器的 WAN 口接收到该数据报，提取其协议（TCP）、目的 IP（$101.1.2.10$$ \text{）和目的端口（} $$60001$）。
   - 检索 NAPT 表，成功匹配到映射项，得知该会话属于内网主机 $(192.168.1.5, 50001)$。
   - 路由器修改数据报：将**目的 IP 地址**替换为 $192.168.1.5$$ \text{，将**目的端口号**替换为} $$50001$。源 IP 和源端口保持不变。
   - 重新计算 IP 首部校验和及 TCP 校验和，更新 TTL，将分组通过 LAN 口转发给内网主机 $H$。

#### 2.3 端口映射（静态 DNAT / 虚拟服务器）
普通的动态 NAPT 只能由**内网主机主动发起外访**才能动态建立表项。公网主机若主动向 NAPT 路由器的公网 IP 发送连接请求，路由器由于在 NAPT 表中找不到对应的目的端口映射规则，将直接丢弃该数据报。

若内部网络建有对外提供服务的服务器（如 Web 服务器、FTP 服务器），必须在 NAT 路由器上**手动静态配置端口映射表项**（即虚拟服务器功能）：

$$ \text{外网 IP: 端口} \longleftrightarrow \text{内网服务器私网 IP: 熟知服务端口} $$

例如在路由器上配置：$(203.10.2.2, 80) \longleftrightarrow (192.168.1.2, 80)$$ \text{。当公网任意主机访问} $$203.10.2.2:80$ 时，路由器直接将目的 IP 和端口转换为内网服务器地址进行转发（2020 年第 47 题考点）。

### 4. 报文首部字段修改及校验和重新计算深度推导

NAT/NAPT 转发过程并非透明传输，它对分组首部有着极其严格的修改机制。这是 2025 年第 37 题等高难度题目的考查核心。

#### 4.1 网络层（IP 数据报）首部字段的变化情况
当一个封装了 UDP 或 TCP 报文段的 IP 数据报经过 NAT 路由器转发时，IP 首部字段变化如下：

| IP 首部字段 | 出站转发（LAN $\to$$ \text{WAN） | 入站转发（WAN} $$\to$ LAN） | 说明 |
| :--- | :--- | :--- | :--- |
| **源 IP 地址** | **被修改**（私网 IP $\to$ 公网 IP） | 保持不变 | 出站替换源 IP（SNAT） |
| **目的 IP 地址** | 保持不变 | **被修改**（公网 IP $\to$ 私网 IP） | 入站替换目的 IP（DNAT） |
| **TTL** | **被修改**（递减 1） | **被修改**（递减 1） | 经过三层路由器正常递减 |
| **首部校验和** | **被修改**（必须重新计算） | **被修改**（必须重新计算） | 源/目的 IP 和 TTL 改变，校验和必变 |
| **总长度** | 保持不变 | 保持不变 | NAT 不改变载荷及首部长度 |
| **标识/标志/片偏移** | 保持不变 | 保持不变 | 分片相关字段不受 NAT 影响 |
| **协议号** | 保持不变 | 保持不变 | 仍为 6(TCP) 或 17(UDP) |

#### 4.2 传输层（UDP/TCP）首部字段的变化情况
以 UDP 为例（TCP 机制相同），UDP 首部共 8 字节，包含 4 个字段：

```text
 0                   15 16                  31
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|          源端口号     |        目的端口号     |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|          长    度     |        校  验  和     |
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
```

| UDP 首部字段 | 出站转发（LAN $\to$$ \text{WAN） | 入站转发（WAN} $$\to$ LAN） | 字段是否修改的原因剖析 |
| :--- | :--- | :--- | :--- |
| **源端口号** | **会被修改** | 保持不变 | NAPT 出站时为防止端口冲突，将其映射为外部端口 |
| **目的端口号** | 保持不变 | **会被修改** | 出站时指向远端固定服务端口；入站时还原为内网端口 |
| **总长度** | **保持不变** | **保持不变** | 载荷数据未增删，UDP 首部长度固定 8 字节，总长度不变 |
| **校验和** | **必须重新计算（修改）** | **必须重新计算（修改）** | **伪首部中的 IP 及首部端口均改变，必须重新计算** |

#### 4.3 传输层校验和重新计算数学推导及伪首部机制
许多考生常误认为“传输层校验和只校验传输层自身数据，因此 IP 地址变了不影响传输层校验和”。**这是极其严重的认知错误！**

根据计算机网络传输层协议标准（RFC 768 定义的 UDP，RFC 793 定义的 TCP），传输层在计算校验和时，强制引入了 **12 字节的虚拟伪首部（Pseudo Header）**：

```text
 0                   15 16                  31
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                   源 IP 地址                  | (4 字节)
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|                  目的 IP 地址                 | (4 字节)
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
|      全 0     | 协议号(17/6)  |    UDP/TCP 长度| (4 字节)
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
```

校验和的计算覆盖范围为：

$$ \text{校验范围} = \text{伪首部} + \text{传输层首部} + \text{传输层数据载荷} $$

计算算法采用**二进制反码求和取反**算法。设参与校验的所有 16 位字序列为 $W_1, W_2, \dots, W_m$，则校验和为：

$$\text{Checksum} = \sim \left( \sum_{i=1}^{m} W_i \right)$$

在出站转发时：
1. 伪首部中的**源 IP 地址**被 NAT 修改（例如从 $192.168.1.5$$ \text{修改为} $$101.1.2.10$）。
2. UDP 首部中的**源端口号**被 NAT 修改（例如从 $50001$$ \text{修改为} $$60001$）。

由于求和序列中的两个 16 位操作数发生了变化：

$$W_{\text{src\_ip}}' \neq W_{\text{src\_ip}}, \quad W_{\text{src\_port}}' \neq W_{\text{src\_port}}$$

其反码加法和必然改变：

$$\sum W' \neq \sum W \implies \text{Checksum}' \neq \text{Checksum}$$

因此，NAT 路由器在转发封装了 UDP 或 TCP 报文段的 IP 数据报时，**必须重新计算传输层校验和**并覆盖原校验和字段；否则接收端主机计算校验和必将出错并丢弃该分组。

### 5. NAT 技术的优缺点和端到端透明性影响

#### 5.1 NAT 的优势
1. **极大缓解 IPv4 地址耗尽**：使成千上万台内部主机可通过极少量的公网 IP 接入互联网。
2. **隐藏内部网络拓扑**：公网外部无法直接嗅探到内部网络的具体 IP 分配及主机数量，提供了一定的网络安全防护边界。
3. **增强内部网络编址灵活性**：内部网络变动或重组时，无需向 ISP 申请新的公网地址段。

#### 5.2 NAT 破坏端到端通信原则及分层模型
虽然 NAT 在工程上获得了巨大成功，但在计算机网络体系结构理论上一直备受争议：
1. **违反体系结构分层原则**：
   按照 OSI 和 TCP/IP 分层模型，路由器属于网络层设备，仅能检查和修改网络层首部（IP 首部），绝不应窥探或修改传输层（端口号）及应用层内容。NAT 跨越网络层深入修改传输层首部，破坏了层次间的独立性。
2. **破坏端到端（End-to-End）IP 通信透明性**：
   互联网最初的设计哲学是端到端透明通信，即网络核心仅负责分组路由转发，两端主机拥有全球唯一地址，可无障碍相互发起通信。
   NAT 阻断了公网外部主机主动向内部主机发起连接的能力。
3. **严重阻碍 P2P（对等网络）通信**：
   在 P2P 应用（如分布式下载、音视频即时通讯、VoIP）中，任意两个对等节点需要相互直接建连。若两端均处于 NAT 之后，双方都无法直接获知对方内网真实 IP 和端口，导致建连失败。必须采用复杂的 **NAT 穿透技术（Hole Punching 打洞，如 STUN、TURN、ICE 协议）** 辅助建连。
4. **应用层载荷携带 IP 地址的失效问题（ALG 需求）**：
   某些传统应用层协议（如 FTP 主动模式的 PORT 命令、SIP 会话初始协议）在应用层数据载荷中直接填入了主机的内网 IP 和端口。NAT 路由器若仅替换 IP/TCP 首部，公网服务器根据载荷中的私网 IP 连接内部主机将彻底失败。为此，NAT 路由器必须额外集成**应用层网关（Application Level Gateway, ALG）**，深度解析并改写应用层载荷。

### 2025 年真题 · 第 37 题

#### 题目题干
假设路由器实现 NAT 功能，内网中主机 H 的 IP 地址为 192.168.1.5/24。若 H 运行某应用向 Internet 发送一个 UDP 报文段，则路由器在转发封装该 UDP 报文段的 IP 数据报的过程中，UDP 报文的首部字段会被修改的是（ ）。  
I. 源端口号  
II. 目的端口号  
III. 总长度  
IV. 校验和  

A. 仅 I、III  
B. 仅 I、IV  
C. 仅 II、III  
D. 仅 II、IV  

#### 逐步推导解析
- **考察点**：本题考查 NAPT（网络地址端口转换）对传输层 UDP 报文首部字段的底层修改机制。
- **逐项剖析**：
  - **字段 I 分析（源端口号）**：内网主机 H 向 Internet 发送数据报属于出站连接。在实际网络中，由于多个内网主机可能选择相同的源端口号，或者路由器需要利用端口复用来区分不同会话，NAT（NAPT）路由器在转发时会将内网主机的私网源端口号映射为路由器出口的临时公网端口号。因此，**源端口号会被修改**，I 正确。
  - **字段 II 分析（目的端口号）**：UDP 报文段的目的端口号用于指示公网接收端主机上的目标应用程序（例如访问 DNS 服务固定使用端口 53，访问 NTP 使用端口 123）。NAT 路由器的职责是转换内部源端信息，绝不能篡改接收端目标应用的服务端口，否则报文到达公网目的主机后将无法送达正确的应用程序。因此，**目的端口号不会被修改**，II 错误。
  - **字段 III 分析（总长度）**：UDP 首部中的“总长度”字段记录的是 UDP 首部（8 字节）加上 UDP 用户数据载荷的总字节数。NAT 路由器的操作是替换首部中的 IP 地址及端口号，并不对数据载荷进行增删或截断，UDP 报文段的总长度保持恒定。因此，**总长度字段不会被修改**，III 错误。
  - **字段 IV 分析（校验和）**：根据 UDP 协议规范（RFC 768），UDP 校验和的计算范围涵盖三部分：**12 字节的 IP 伪首部**（包含源 IP、目的 IP、全 0、协议号 17、UDP 长度）、**8 字节的 UDP 首部**以及 **UDP 数据载荷**。在路由器转发时，NAT 不仅将源 IP 地址由私网 IP（192.168.1.5）替换为公网 IP，还修改了 UDP 首部中的源端口号。伪首部中的源 IP 和 UDP 首部中的源端口号均发生改变，参与反码求和的数据发生实质变化，路由器必须重新计算 UDP 校验和并重写该字段，否则目的主机校验将直接判定分组损坏而丢弃。因此，**校验和字段会被修改**，IV 正确。

综上所述，UDP 报文首部中会被修改的字段是 I 和 IV。

#### 【正确答案】
**B**

### 2023 年真题 · 第 38 题

```text
      ┌───┴───┐
```

A. 192.168.0.33

D. 192.168.0.3  

#### 逐步推导解析
- **考察点**：本题考查 NAT 出口源 IP 地址转换机制及 CIDR 无类域间路由子网可用地址计算。
- **逐步推导**：
  1. **NAT 源地址转换规则判断**：
     主机 H 处于局域网内部，其原始 IP 地址为私有地址 $192.168.0.3$。
     当主机 H 向 Internet 发送 IP 分组时，该分组首先送达其默认网关 R2 的内网接口（$192.168.0.1$）。

  2. **互联链路 CIDR 子网地址分析**：
     题干给出 R1 和 R2 之间的互联链路网络前缀为 `192.168.0.34/30`。
     子网前缀长度为 30 位，主机位长度为：
     
     $$ \text{32 - 30 = 2 \text{ 位}} $$
     
     总地址块大小为 $2^2 = 4$ 个地址。
     将地址最后一个字节 $34$ 转换为二进制：
     
     $$34 = (00100010)_2$$
     
     前缀占 6 位（$001000$$ \text{），主机位占后 2 位（} $$10$）。
     - **子网网络地址（主机位全 0）**：
       
       $$(00100000)_2 = 32 \implies 192.168.0.32$$
       
     - **子网广播地址（主机位全 1）**：
       
       $$(00100011)_2 = 35 \implies 192.168.0.35$$
       
     - **可用主机 IP 地址范围**：
       仅有两个可用地址，分别为 $192.168.0.33$$ \text{和} $$192.168.0.34$。
  3. **出口接口 IP 地址确认及选项排查**：
     该点对点链路上仅有两台路由器的互链接口。既然给定的接口之一分配了 $192.168.0.34$$ \text{，那么链路对端的有效主机地址必然是} $$192.168.0.33$。
     因此，R2 发送给 R1 的分组源 IP 必须是其出口可用接口地址：
     - 选项 A（$192.168.0.33$）：属于该子网唯一的另一个可用主机接口地址，正确。
     - 选项 B（$192.168.0.35$）：为该子网的直接广播地址，绝不能分配为主机或路由接口单播 IP，不可作为源 IP。
     - 选项 C（$192.168.0.1$）：为 R2 的内网 LAN 口地址，未经过 NAT 转换，不可在出境链路上路由。
     - 选项 D（$192.168.0.3$）：为主机 H 的原始内网地址，直接被 NAT 替换，不会出现在转发后的外网分组源地址中。

**A**

### 2020 年真题 · 第 47 题

#### 题目题干
某校园网有两个局域网，通过路由器 R1、R2 和 R3 互联后接入 Internet，S1 和 S2 为以太网交换机，局域网采用静态 IP 地址配置，路由器部分接口以及各主机的 IP 地址如图所示：

```text
                                  Internet
                                     │
                             ┌───────┴───────┐
                             │    路由器 R1   │
                             └───┬───────┬───┘
               203.10.2.1/30     │       │     203.10.2.5/30
                     ┌───────────┘       └───────────┐
       203.10.2.2/30 │                               │ 203.10.2.6/30
             ┌───────┴───────┐               ┌───────┴───────┐

     192.168.1.1 │                               │ 192.168.1.1

                 │                               │
             ┌───┴───┐                       ┌───┴───┐
             │ 交换机│ S1                    │ 交换机│ S2
             └───┬───┘                       └───┬───┘
        ┌────────┴────────┐             ┌────────┴────────┐
        │                 │             │                 │
     Web服务器          主机 H1       主机 H2           主机 H3
   192.168.1.2       192.168.1.3   192.168.1.2       192.168.1.3
```

假设 NAT 转换表结构为：
```text
+-----------------------+-----------------------+
|        外  网         |        内  网         |
+-----------+-----------+-----------+-----------+
|  IP 地址  |  端口号   |  IP 地址  |  端口号   |
+-----------+-----------+-----------+-----------+
```

请回答下列问题：
1. 为使 H2 和 H3 能够访问 Web 服务器（使用默认端口号），需要进行什么配置？
2. 若 H2 主动访问 Web 服务器时，将 HTTP 请求报文封装到 IP 数据报 P 中发送，则：
   - H2 发送 P 的源 IP 地址和目的 IP 地址分别是？
   - 经过 R3 转发后，P 的源 IP 地址和目的 IP 地址分别是？
   - 经过 R2 转发后，P 的源 IP 地址和目的 IP 地址分别是？

#### 逐步推导解析

##### 第一问：NAT 配置分析
- **场景痛点诊断**：
  观察拓扑图可见，LAN1 和 LAN2 均采用了完全相同的私网 IP 网段 `192.168.1.0/24`。Web 服务器和 H2 的内网 IP 均为 `192.168.1.2`，H1 和 H3 的内网 IP 均为 `192.168.1.3`。
  由于两端私网 IP 冲突，且私网地址在中间公网链路（R1 互联段）不可路由，H2/H3 绝对无法直接通过 `192.168.1.2` 访问 Web 服务器。
- **发布配置推导**：
  Web 服务器处于 R2 保护的内网中，外部网络访问该 Web 服务器必须访问 R2 的外网 WAN 口公网 IP 地址（即 `203.10.2.2`）。
  Web 服务器采用 HTTP 协议，默认熟知服务端口号为 **80**。
  为使外部请求能够准确路由并映射到内网 Web 服务器，必须在路由器 R2 上配置**静态端口映射表项（虚拟服务器）**：
  - 外网 IP 地址：填写 R2 的出口 WAN 口 IP，即 `203.10.2.2`。
  - 外网端口号：填写外部主机访问的端口号，默认对应 HTTP 服务的 `80`。
  - 内网 IP 地址：填写 Web 服务器在 LAN1 中的实际内部私网 IP，即 `192.168.1.2`。
  - 内网端口号：填写 Web 服务器应用程序实际监听的端口号，即 `80`。

R2 的 NAT 转换表配置如下：

```text
+-----------------------+-----------------------+
|        外  网         |        内  网         |
+-----------+-----------+-----------+-----------+
|  IP 地址  |  端口号   |  IP 地址  |  端口号   |
+-----------+-----------+-----------+-----------+
| 203.10.2.2|    80     |192.168.1.2|    80     |
+-----------+-----------+-----------+-----------+
```

*(注：由于题干未要求从外部访问 H1，因此 H1 的转换表项无需配置。)*

##### 第二问：数据报 P 在各转发阶段的 IP 地址逐跳追踪
H2 发起向 Web 服务器的 HTTP 请求，数据报 P 的转发经历“内网发出 $\to$$ \text{出境 R3 执行 SNAT} $$\to$$ \text{中转 R1 路由} $$\to$$ \text{入境 R2 执行 DNAT} $$\to$ 抵达 Web 服务器”的全过程：

1. **H2 发送 P 时（在 LAN2 内）**：
   - 源主机为 H2，其自身源 IP 地址为内网私网地址：`192.168.1.2`。
   - 目的端为主机访问的目标服务。如第一问所述，H2 必须访问 Web 服务器对外发布的公网 IP 地址，即 R2 的 WAN 口地址：`203.10.2.2`。
   - **源 IP 地址**：`192.168.1.2`；**目的 IP 地址**：`203.10.2.2`。

2. **经过 R3 转发后（在公网链路 R3-R1-R2 上）**：
   - 分组送达默认网关 R3，R3 开启 NAT 功能。
   - R3 执行源网络地址转换（SNAT），将私网源 IP 地址替换为 R3 自身的出口 WAN 口公网 IP 地址 `203.10.2.6`（并在 R3 的 NAT 动态表中建立端口映射项）。
   - 目的 IP 地址保持不变，依然指向目标公网地址 `203.10.2.2`。
   - **源 IP 地址**：`203.10.2.6`；**目的 IP 地址**：`203.10.2.2`。

3. **经过 R2 转发后（在 LAN1 内）**：
   - 数据报经由 R1 路由转发至 R2。R2 接收到目的 IP 为 `203.10.2.2` 且目的端口为 80 的分组。
   - R2 检索其第一问配置的静态 NAT 表，命中规则，执行目的网络地址转换（DNAT）：将目的 IP 地址替换为 Web 服务器的真实内网私网 IP `192.168.1.2`。
   - 源 IP 地址保持不变，依然记录为访问发起方的外网地址 `203.10.2.6`（保证 Web 服务器响应报文能原路回送给 R3）。
   - **源 IP 地址**：`203.10.2.6`；**目的 IP 地址**：`192.168.1.2`。

#### 【正确答案】
1. 需要在路由器 R2 中配置 NAT 转换表（端口映射）。配置表项为：
   - 外网 IP 地址：`203.10.2.2`，外网端口号：`80`
   - 内网 IP 地址：`192.168.1.2`，内网端口号：`80`
2. 各阶段源 IP 地址和目的 IP 地址如下：
   - **H2 发送 P 时**：源 IP 地址为 `192.168.1.2`，目的 IP 地址为 `203.10.2.2`。
   - **经过 R3 转发后**：源 IP 地址为 `203.10.2.6`，目的 IP 地址为 `203.10.2.2`。
   - **经过 R2 转发后**：源 IP 地址为 `203.10.2.6`，目的 IP 地址为 `192.168.1.2`。

##### 第一问：互联设备选型分析
- **广播域及子网划分**：

  - 设备 2 仅需互联 LAN1 内部的主机 H1、H2，且无需划分 VLAN，选择二层设备**以太网交换机**即可。
  - 设备 3 仅需互联 LAN2 内部的主机 H3、H4，同理选择二层设备**以太网交换机**。

- **需要配置 IP 的设备判定**：
  以太网交换机工作在数据链路层，在不具备管理功能的普通二层工作模式下接口透明传输数据帧，不需要为其接口配置 IP 地址。路由器工作在网络层，其每一个接口对应一个独立的物理子网（广播域），路由器的所有接口均必须配置 IP 地址。因此，**只有设备 1 的接口需要配置 IP 地址**。

  - **IF2 接口**：作为 LAN1（`192.168.1.0/26`）的默认网关，必须配置为主机 H1/H2 预设的网关 IP，即：

    $$ \text{IF3: } 192.168.1.65/26 \quad (\text{掩码 } 255.255.255.192) $$

    $$253 = (11111101)_2$$
    
    该子网网络地址为 `192.168.1.252`，直接广播地址为 `192.168.1.255`。
    可用主机 IP 仅有 `192.168.1.253` 和 `192.168.1.254`。
    由于 `192.168.1.253` 已经分配给路由器 R 的接口，因此设备 1 的 IF1 接口必须配置为：
    
    $$ \text{IF1: } 192.168.1.254/30 \quad (\text{掩码 } 255.255.255.252) $$
    

##### 第三问：核心网络服务判断
- 主机 H1~H4 分配的 IP 地址属于 `192.168.1.0/24` 网段，这属于 RFC 1918 规定的 **C 类私有 IP 地址**（`192.168.0.0/16`）。
- 私有 IP 地址在 Internet 核心公网中是不被路由的，任何公网路由器收到私网源地址的数据报都会直接丢弃。
- 路由器 R 拥有连接公网的合法全球 IP（`101.1.2.101`）。为使内部主机能够正常访问外部 Internet，路由器 R 必须提供**网络地址转换（NAT）服务**（或网络地址端口转换 NAPT 服务），将私网源地址转换为合法的公网 IP。

##### 第四问：广播报文隔离及接收主机判定
- 主机 H3 所在子网为 `192.168.1.64/26`。
- 子网掩码 `/26` 的主机位有 $32 - 26 = 6$ 位。
- 该子网的直接广播地址为主机位全 1 的地址：
  
  $$64 + (2^6 - 1) = 64 + 63 = 127 \implies 192.168.1.127$$
  
- 因此，目的地址为 `192.168.1.127` 的 IP 数据报是发往该子网的**直接广播数据报**。
- 交换机（设备 3）会在其整个广播域内泛洪该广播帧；
- 路由器（设备 1）具有**隔离广播域**的核心特性，默认绝不转发子网定向广播数据报到其他子网（LAN1），因此 LAN1 中的 H1 和 H2 绝对接收不到该广播；
- H3 是该数据报的发送方，网络中同处该广播域内的接收主机仅有 **H4**。

#### 【正确答案】
1. 设备 1 应选择**路由器**；设备 2 和设备 3 应选择**以太网交换机**。
2. 设备 1 的接口需要配置 IP 地址。具体配置为：
   - IF1 接口：`192.168.1.254/30`（或掩码 `255.255.255.252`）
   - IF2 接口：`192.168.1.1/26`（或掩码 `255.255.255.192`）
   - IF3 接口：`192.168.1.65/26`（或掩码 `255.255.255.192`）
3. 路由器 R 需要提供**网络地址转换（NAT / NAPT）**服务。
4. 网络中只有主机 **H4** 会接收该数据报。

## 四、 综合解答题深度拓展及大题考法联动

NAT 技术是 408 综合大题（尤其是第 47 题）中最常被采纳的“拓扑枢纽”。命题专家极度热衷于将 NAT 嵌入到企业网、校园网的出口位置，向下考察局域网规划，向上考察跨网路由及应用交互。

### 1. 跨层综合考法全景图

```text
               应用层 (HTTP / DNS)
                     │ 默认端口 (80/53) -> NAT 转换表内网端口匹配
                     ▼
               传输层 (TCP / UDP)
                     │ 源端口/目的端口替换 -> 伪首部发生变动 -> 重新计算校验和
                     ▼
               网络层 (IP / NAT / CIDR)
                     │ 替换源/目的 IP -> 重新计算 IP 校验和 -> TTL 递减 -> 路由表查找下一跳
                     ▼
               数据链路层 (以太网 / ARP)
                     │ 路由器每转发一跳，重新封装 MAC 首部 (源 MAC = 出接口 MAC, 目的 MAC = 下一跳 MAC)
                     ▼
               物理层 (传输介质)
```

### 2. 核心命题模型深度剖析

#### 模型一：私网主机访问公网服务器（SNAT + 动态端口映射）
- **核心逻辑**：
  1. 内网主机封装 IP 数据报：$$ \text{Src IP} = \text{私网 IP}, \text{Dst IP} = \text{公网服务器 IP} $$。
  2. 传输层封装：$$ \text{Src Port} = \text{临时端口}, \text{Dst Port} = \text{服务端口} $$。
  3. 经过 NAT 网关出境：
     - 源 IP 替换为网关公网 IP；
     - 源端口替换为 NAT 分配的外部临时端口；
     - 目的 IP 和目的端口保持不变；
     - 数据链路层帧头被重构：源 MAC 变为 NAT 出口网卡 MAC，目的 MAC 变为下一跳路由器 MAC（经 ARP 查询获得）。
  4. 回程数据报处理：
     - 目的 IP 为 NAT 网关公网 IP，目的端口为 NAT 外部临时端口；
     - NAT 网关查表逆向还原目的 IP 为内网主机私网 IP，目的端口还原为内网临时端口；
     - 源 IP 和源端口保持公网服务器信息不变。

#### 模型二：公网访问内网服务器（静态 DNAT / 虚拟服务器端口映射）
如 2020 年第 47 题所展现的经典模型。
- **解题关键口诀**：
  - **外访内，找映射**：外部无法直接路由到内部私网，外部访问的目标 IP 必定是 NAT 路由器的公网 IP。
  - **进门改目的，出门改源头**：
    - 外部请求进门经过 NAT 路由器时，执行 **DNAT**（修改目的 IP 为服务器真实内网 IP，修改目的端口为服务真实内部端口）；
    - 内部响应出门经过 NAT 路由器时，执行 **SNAT**（修改源 IP 为路由器公网 IP，修改源端口为外部服务端口）。

#### 模型三：相同私有网段互联互通（双 NAT 模型）
2020 年第 47 题中 LAN1 和 LAN2 均采用 `192.168.1.0/24`：
- **核心认知**：两个 LAN 处于不同的路由器背后，虽然各自内部 IP 冲突，但各自的出口路由器（R2 和 R3）均拥有全球唯一的外部公网 IP。
- 只要双方均通过访问对方出口路由器的公网 IP 进行通信，数据报在公网传输时其源 IP 和目的 IP 均为合法的公网 IP，完全符合标准路由规范，即可实现正常通信。

### 3. 大题规范答题采分点及失分陷阱

1. **陷阱一：混淆 NAT 转换表中“外网”及“内网”字段**：
   - 配置静态映射表时，务必审清表头。通常外网侧填“公网 IP + 公网暴露端口”，内网侧填“服务器实际私网 IP + 服务监听端口”。
2. **陷阱二：忽略路由器隔离广播域的铁律**：
   - 题目询问“某主机发送广播数据报，哪些主机会接收”时，切记**以太网交换机转发广播，路由器坚决阻隔广播**。只有处于同一物理子网/广播域内的其他主机才会接收，跨路由器的子网主机绝不会收到。
3. **陷阱三：误将广播地址或网络地址配置为接口 IP**：
   - CIDR `/30` 划分后，一共 4 个地址。首个全 0 地址为网络地址，末尾全 1 地址为广播地址，均不可配置在接口上。只有中间两个主机位才可配置。
4. **陷阱四：混淆逐跳 IP 替换及逐跳 MAC 替换的本质差异**：
   - 在 NAT 转发大题中，IP 地址仅在**经过 NAT 路由器**时才发生首部 IP 替换；普通路由器转发只改 TTL 和校验和，不改源/目的 IP。
   - 而数据链路层的源 MAC 和目的 MAC，**每经过任意一台路由器**都会被重新解封并重写为当前出接口 MAC 及下一跳入接口 MAC。

## 五、 考点速记清单

### 1. 核心解题口诀
```text
私网外访改源头，公网回包改目的地；
IP 端口动态配，连接四元写入表；
内网发布做映射，静态 DNAT 固端口；
外网 IP 端口变，伪首校验重算起；
路由隔离广播域，私网跨网靠网关。
```

### 2. 避坑防错八大关键事实
1. **RFC 1918 私网范围**：
   - A 类：`10.0.0.0/8`（10.0.0.0 ~ 10.255.255.255）
   - B 类：`172.16.0.0/12`（172.16.0.0 ~ 172.31.255.255，注意第二字节是 16 到 31）
   - C 类：`192.168.0.0/16`（192.168.0.0 ~ 192.168.255.255）
2. **NAPT 必改字段**：
   - 网络层：源 IP（出站）或目的 IP（入站）、TTL（减 1）、IP 首部校验和。
   - 传输层：源端口（出站）或目的端口（入站）、传输层校验和（TCP/UDP）。
3. **NAPT 不改字段**：
   - 目的端口号（出站时不改）、UDP 长度 / TCP 报头长度、传输层应用载荷数据。
4. **校验和必重算根源**：
   - UDP/TCP 校验和计算必须带入 **12 字节伪首部**。由于伪首部包含源 IP 和目的 IP，只要 IP 发生改变，即使传输层载荷完全未动，校验和也必须重新计算。
5. **外网无法主动向内网发起连接**：
   - 纯动态 NAPT 下，外网主机不能主动向内网主机建立连接；必须通过静态端口映射（DNAT）或 STUN/TURN 穿透协议。
6. **路由器接口 IP 配置合法性**：
   - 在 `/30` 点对点链路中，只有中间 2 个地址可用。如 `192.168.0.32/30` 中，网络号是 `.32`，广播号是 `.35`，可用接口 IP 仅有 `.33` 和 `.34`。
7. **广播包穿透性**：
   - 任何广播分组（受限广播 `255.255.255.255` 或直接子网广播）均被路由器阻隔，无法穿过 NAT 路由器。
8. **分层架构原则的破坏**：
   - NAPT 属于典型的网络层设备查看及修改传输层端口号的技术，打破了端到端通信透明性及严格分层体系。
