   - **网络物理设备的最高功能层定位**：考查中继器、集线器、交换机、路由器等网络设备所能解析和处理的最高协议层级（如 2016 年）。
3. **概念辨析极其细致**：命题擅长设置概念陷阱，重点考查“结点到结点”相比“端到端”的区别、面向连接及无连接模式在各层的实现策略差异等。

## 二、 具体考察内容

### 1. 计算机网络分层架构基础理论

计算机网络采用分层体系结构的核心动因在于降低系统设计和维护的复杂度。分层遵循“高内聚、低耦合”原则，使得各层功能相对独立，当下层技术革新时，只要层间接口保持稳定，上层系统无需重构。

```text
+-------------------------------------------------------------+
|                        (N+1) 实体                           |
+-------------------------------------------------------------+
                              | 服务调用 (Service Primitives)
                              v
+=============================================================+
|                      (N) 服务访问点 (SAP)                   |
+=============================================================+
|                          (N) 实体                           |
|       +---------------------------------------------+       |
|       |               (N) 协议控制逻辑              |       |
|       +---------------------------------------------+       |
+=============================================================+
                              | 服务调用
                              v
+=============================================================+
|                     (N-1) 服务访问点 (SAP)                  |
+=============================================================+
|                         (N-1) 实体                          |
+-------------------------------------------------------------+
```

#### 1.1 实体、协议及服务核心内涵
- **实体（Entity）**：指任何可发送或接收信息的硬件或软件进程。处于第 $n$$ \text{层的实体称为} $$(n)$ 实体。位于不同机器同一层次上的实体称为**对等实体（Peer Entities）**。
- **协议（Protocol）**：控制两个对等实体进行逻辑通信的一组规则的集合。协议定义了对等实体间交换数据的语法、语义和同步时序。**协议是“水平的”**，即协议仅存在于对等实体之间。
- **服务（Service）**：下层为相邻上层提供的功能支持。第 $n$$ \text{层实体利用第} $$n-1$$ \text{层提供的服务，并结合本层的协议控制逻辑，向第} $$n+1$ 层实体提供更高级别的服务。**服务是“垂直的”**，即服务只能自下而上单向提供。
- **服务访问点（SAP, Service Access Point）**：相邻两层实体交换信息的逻辑接口。上层实体通过下层 SAP 请求并获取下层服务。

#### 1.2 服务原语及服务分类体系
- **服务原语四部曲**：请求（Request）、指示（Indication）、响应（Response）、证实（Confirm）。
- **面向连接及无连接服务**：
  - 面向连接：通信前必须建立虚连接，数据传输期间按序传递，通信结束后释放连接（如电话通信）。
  - 无连接：通信前无需握手建链，每个报文独立寻找路由，尽力而为交付，不保证交付顺序和可靠性（如传统邮政通信）。
- **有确认及无确认服务**：
  - 有确认：接收端收到数据后必须向发送端返回显式确认（ACK），超时未确认需重传。
  - 无确认：接收端不返回确认信息，发送端不负责可靠性保证。

### 2. OSI 七层参考模型体系详解

国际标准化组织（ISO）提出的开放系统互连参考模型（OSI/RM, Open Systems Interconnection Reference Model）自底向上划分为七个功能层：

```text
+-----+--------------+--------------------------------------------------+---------------------+
| 层号| 层次名称     | 核心功能定位                                     | 典型协议 / 代表标准 |
+-----+--------------+--------------------------------------------------+---------------------+
|  7  | 应用层       | 直接为端用户的网络应用程序提供通信服务及接口     | HTTP, FTP, DNS, SMTP|
|  6  | 表示层       | 处理数据表示差异、字符转换、数据压缩、加解密     | JPEG, ASCII, ASN.1  |
|  5  | 会话层       | 建立、维护、管理进程会话，实现会话同步及断点管理 | RPC, PPTP, SQL 会话 |
|  4  | 传输层       | 提供端到端（进程到进程）的可靠/不可靠通信服务    | TCP, UDP            |
|  3  | 网络层       | 主机到主机的路由选择、分组转发、网际互联、拥塞控制| IP, ICMP, OSPF, BGP |
|  2  | 数据链路层   | 将物理比特流封装成帧，提供相邻结点间的无差错传输 | Ethernet, PPP, HDLC |
|  1  | 物理层       | 在物理介质上透明传输原始比特流，定义物理接口特性 | RS-232, RJ-45, 100BASE-T |
+-----+--------------+--------------------------------------------------+---------------------+
```

#### 2.1 物理层（Physical Layer）
- **传输单元**：比特（Bit）。
- **主要任务**：屏蔽具体传输介质及通信设备的物理差异，实现比特流在传输介质上的透明传输。
- **四大接口特性**：
  - *机械特性*：规定接口所用接线器的规格、引脚数目、排列形状等。
  - *电气特性*：规定接口引线上信号电压范围、阻抗匹配、传输速率上限。
  - *功能特性*：指明某条引线上出现的某一电平的物理意义（如信号线、地线、控制线的功能划分）。
  - *过程特性*：规定在不同引线上操作事件发生的合法动作时序及交互流程。

#### 2.2 数据链路层（Data Link Layer）
- **传输单元**：帧（Frame）。
- **主要任务**：将物理层提供的原始比特流传输通道，改造为逻辑上无差错的数据链路，实现**相邻结点间（Node-to-Node / Hop-to-Hop）**的无差错可靠传输。
- **核心功能**：
  - *成帧（Framing）*：确定帧界定符（首尾标志），提取有效数据载荷。
  - *差错控制*：循环冗余校验（CRC）、检错重传（ARQ）或前向纠错（FEC）。
  - *流量控制*：匹配相邻两个直接相连结点的发送速率和接收速率，防止接收缓冲区溢出。
  - *介质访问控制（MAC）*：在共享广播信道上协调多结点信道接入（如 CSMA/CD、CSMA/CA、令牌环）。

#### 2.3 网络层（Network Layer）
- **传输单元**：分组或数据报（Packet / Datagram）。
- **主要任务**：将分组从源端系统传输到目的端系统，提供**主机到主机（Host-to-Host）**的通信服务。
- **核心功能**：
  - *路由选择*：运行路由协议（RIP, OSPF, BGP），构建并动态维护路由表。
  - *分组转发*：路由器根据转发表将分组从输入端口交换到合适的输出端口。
  - *网际互连*：异构网络之间的协议转换和报文封装对接。
  - *拥塞控制及网络层流量控制*：网络层流量控制立足于整个通信子网全局，防止由于负荷过重导致子网性能崩溃。

#### 2.4 传输层（Transport Layer）
- **传输单元**：报文段（Segment，面向连接）或用户数据报（Datagram，无连接）。
- **主要任务**：自底向上**第一个提供端到端（End-to-End，即进程到进程）**通信服务的层次。
- **核心功能**：
  - *复用及分用*：通过端口号（Port）区分主机上的并发应用进程。
  - *端到端差错控制及流量控制*：通过滑动窗口协议、重传计时器实现进程级数据可靠性及接收端流量控制。
  - *连接管理*：维护传输层连接的状态机迁移（如 TCP 三次握手及四次挥手）。

#### 2.5 会话层（Session Layer）
- **主要任务**：管理和协调不同主机上各种应用进程之间的会话（对话）通信。
- **核心功能**：
  - *会话管理*：会话的建立、使用、释放，支持单工、半双工或全双工通信模式切换。
  - *会话同步及检查点设置*：在数据流中插入同步点（Synchronization Points / Checkpoints）。当网络突发中断后，仅需从最近的同步点重新传输，无需从头重传（断点续传机制的理论雏形）。

#### 2.6 表示层（Presentation Layer）
- **主要任务**：解决应用层交互数据在不同计算机内部存储格式及表示方式的差异，确保通信双方能正确解读数据含义。
- **核心功能**：
  - *数据格式转换*：不同字符编码体系之间的转换（如 ASCII 及 EBCDIC 互转）、整型数据的大端（Big-Endian）和小端（Little-Endian）字节序统一转换。
  - *数据压缩及解压缩*：减少传输比特总数，提高信道利用率（如文本压缩算法、图像音视频编码）。
  - *数据加密及解密*：在端到端应用数据层面实施保密性变换。

#### 2.7 应用层（Application Layer）
- **主要任务**：OSI 参考模型的最高层，直接面向用户的应用进程，提供各种分布式网络应用程序所需的标准通信接口及网络服务。
- **服务形态**：通过具体的应用层协议支持文件传输、电子邮件、远程登录、网页浏览等实际网络业务。

### 3. PDU 封装机制及传输有效率数学模型

#### 3.1 协议数据单元（PDU）结构拆解
在分层体系中，上层交付给下层的数据称为**服务数据单元（SDU, Service Data Unit）**；本层为了执行本层协议所增加的控制信息称为**协议控制信息（PCI, Protocol Control Information）**；二者合并即构成本层的**协议数据单元（PDU, Protocol Data Unit）**。

第 $N$$ \text{层的 PDU 在向下传递给第} $$N-1$$ \text{层时，直接作为第} $$N-1$ 层的 SDU：

$$PDU_N = SDU_N + PCI_N$$

$$SDU_{N-1} = PDU_N$$

```text
发送端逐层封装流程:
[应用层 SDU] 
     |
     v
[AH][     应用层数据载荷      ]                           (APDU)
     |
     v
[PH][        表示层 SDU       ]                           (PPDU)
     |
     v
[SH][        会话层 SDU       ]                           (SPDU)
     |
     v
[TH][        传输层 SDU       ]                           (TPDU / 报文段)
     |
     v
[NH][        网络层 SDU       ]                           (NPDU / 分组)
     |
     v
[DH][        数据链路层 SDU                     ][DT]     (DPDU / 帧)
     |                                             ^
     v                                             |
[ 物理层比特流: 010011010111000101011... ]         +-- 数据链路层附加帧尾(校验和)
```

> **特别注意**：
> 1. 大多数中间层仅添加协议首部（Header, PCI）；
> 2. **数据链路层既添加首部（Header），又添加尾部（Trailer, 如 FCS 帧校验序列）**；
> 3. 物理层仅将数据链路层的帧转换为比特流并在介质上传输，在纯理论模型中不引入数据层面的 PDU 头部（注：实际物理层协议如以太网前导码 Preamble 属于同步码，不计入 OSI 各层 PDU 封装开销标准考查范畴）。

#### 3.2 数据传输有效率数学推导
设应用层待传输的纯数据载荷长度为 $L_{\text{data}}$$ \text{（字节）。数据从第 7 层传递至第 2 层，各层分别添加协议开销} $$H_i$$ \text{（其中} $$i \in \{2, 3, 4, 5, 6, 7\}$$ \text{，且} $$H_2$ 包含帧首部和帧尾部）。

线路上最终传输的总报文字节长度 $L_{\text{total}}$ 为：

$$L_{\text{total}} = L_{\text{data}} + \sum_{i=2}^{7} H_i$$

应用层数据的**传输有效率（Efficiency）** $\eta$ 定义为纯应用层有效数据载荷在实际总传输数据量中的占比：

$$\eta = \frac{L_{\text{data}}}{L_{\text{total}}} \times 100\% = \frac{L_{\text{data}}}{L_{\text{data}} + \sum_{i=2}^{7} H_i} \times 100\%$$

若特定题目设定某些层不添加开销（如设物理层和应用层不增加开销），或者各层额外开销均为固定值 $H$$ \text{，则总开销简化为} $$k \times H$（$k$ 为增加首部的层次总数）。

### 4. 层间服务访问点（SAP）映射体系

下层通过服务访问点（SAP）向相邻上层提供服务，SAP 在逻辑上充当下层协议识别上层协议类型的“分流开关”：

```text
+-----------------------+-----------------------------+------------------------------------+
| 交互层次              | 服务访问点（SAP）形态       | 典型实例及数值                     |
+-----------------------+-----------------------------+------------------------------------+
| 物理层 / 数据链路层   | 网卡物理接口 / MAC 地址     | MAC 地址（如 00-1A-2B-3C-4D-5E）   |
| 数据链路层 / 网络层   | 帧首部“类型”字段 (EtherType)| 0x0800 (IPv4), 0x86DD (IPv6),      |
|                       | 或 LLC SAP (LSAP)           | 0x0806 (ARP)                       |
| 网络层 / 传输层       | IP 首部“协议”字段 (Protocol)| 6 (TCP), 17 (UDP), 1 (ICMP)        |
| 传输层 / 应用层       | 传输层“端口号” (Port Number)| 80 (HTTP), 443 (HTTPS), 53 (DNS)   |
+-----------------------+-----------------------------+------------------------------------+
```

### 5. 网络互联设备的工作层次划分

网络设备能够解析、识别并处理的协议层次，决定了其属于“第几层设备”。设备工作的最高功能层和转发决策依据紧密绑定：

```text
+----------------+------------+----------------------+-------------------------------------+
| 设备名称       | 最高功能层 | 转发/处理依据        | 核心工作机制                        |
+----------------+------------+----------------------+-------------------------------------+
| 中继器         | 物理层     | 无（纯信号电平整形） | 对电信号进行放大、整形并再生转发    |
| (Repeater)     | (Layer 1)  |                      | 扩大物理传输距离，不能隔离碰撞域    |
+----------------+------------+----------------------+-------------------------------------+
| 集线器         | 物理层     | 无（纯比特流多端口） | 多端口中继器，向除输入端口外的所有  |
| (Hub)          | (Layer 1)  | 广播转发             | 端口盲目广播，不能隔离碰撞域和广播域|
+----------------+------------+----------------------+-------------------------------------+
| 网桥           | 数据链路层 | MAC 地址             | 存储转发帧，根据 MAC 地址表选择性   |
| (Bridge)       | (Layer 2)  | (源学习，目的转发)   | 过滤和转发，隔离碰撞域，不隔离广播域|
+----------------+------------+----------------------+-------------------------------------+
| 以太网交换机   | 数据链路层 | MAC 地址             | 多端口网桥，支持并行无碰撞传输，    |
| (Switch)       | (Layer 2)  | 硬件线速转发         | 隔离碰撞域，默认不隔离广播域        |
+----------------+------------+----------------------+-------------------------------------+
| 路由器         | 网络层     | IP 目的地址          | 检查 IP 首部，查询路由表并转发分组，|
| (Router)       | (Layer 3)  | 跨网络选路转发       | 既隔离碰撞域，又隔离广播域          |
+----------------+------------+----------------------+-------------------------------------+
| 网关           | 传输层     | 传输层端口 /         | 实现高层异构协议转换（如邮件网关、  |
| (Gateway)      | 及以上层   | 应用层命令载荷       | 协议代理转换服务器）                |
+----------------+------------+----------------------+-------------------------------------+
```

> **重要规则判定**：
> 1. 设备工作在第 $N$$ \text{层，意味着该设备**必须完整实现第 1 层至第} $$N$ 层的全部功能**。
> 2. 例如，路由器作为网络层设备，其内部物理硬件接口必须具备物理层收发功能以及数据链路层成帧/校验功能，但在路由决策和转发处理时，其解析并处理的最高协议字段位于网络层（IP 头部）。

### 6. 核心易混淆机制深度对比剖析

#### 6.1 流量控制在各层的职责范畴差异
流量控制是网络体系中的高频陷阱点，数据链路层、网络层和传输层均涉及流量控制，但控制范围和实施主体完全不同：

```text
+------------------+------------------------------+------------------------------------+
| 层次             | 控制范围                     | 核心控制目标                       |
+------------------+------------------------------+------------------------------------+
| 数据链路层       | 相邻两个直接相连的通信结点间 | 防止发送结点发送过快导致直接接收   |
| (Data Link Layer)| (Hop-to-Hop / Node-to-Node)  | 结点的物理接收缓存溢出             |
+------------------+------------------------------+------------------------------------+
| 网络层           | 整个通信子网全局             | 防止过多分组注入通信子网引起路由器 |
| (Network Layer)  | (Subnet-wide)                | 拥塞崩溃，属于网络全局拥塞控制     |
+------------------+------------------------------+------------------------------------+
| 传输层           | 最终端系统之间的应用程序对   | 防止发送端应用进程发送过快导致目的 |
| (Transport Layer)| (End-to-End / Process-to-Proc)| 端主机的传输层接收窗口溢出         |
+------------------+------------------------------+------------------------------------+
```

#### 6.2 通信主体的三级逻辑粒度辨析
- **结点到结点（Node-to-Node）**：物理层及数据链路层的通信范畴。此处的“结点”涵盖了主机、交换机、路由器等一切物理网络结点。
- **主机到主机（Host-to-Host）**：网络层的通信范畴。网络层只负责把分组从源主机送达目的主机，不区分主机内部的哪个应用程序。
- **进程到进程（Process-to-Process / End-to-End）**：传输层及高层的通信范畴。通过端口号寻址，直接绑定具体应用进程，这才是严格意义上的“端到端”。

#### 6.3 面向连接及无连接模式在 OSI 和 TCP/IP 体系中的对比
这是考研真题极其青睐的“对照哲学”命题点：

```text
+-----------------------+-----------------------------+-----------------------------+
| 体系模型              | 网络层 (Network Layer)      | 传输层 (Transport Layer)    |
+-----------------------+-----------------------------+-----------------------------+
| OSI 参考模型          | 同时支持面向连接及无连接    | 仅支持面向连接              |
|                       | (虚电路 vs 数据报服务)      |                             |
+-----------------------+-----------------------------+-----------------------------+
| TCP/IP 参考模型       | 仅支持无连接                | 同时支持面向连接及无连接    |
|                       | (不可靠的数据报尽力而为交付)| (TCP 面向连接, UDP 无连接)  |
+-----------------------+-----------------------------+-----------------------------+
```

> **设计哲学深度剖析**：
> - **OSI 设计哲学**：继承了传统电信网络的思维模式，认为底层通信子网必须具备可靠性保障（因此网络层提供面向连接服务），而端系统传输层建立在虚电路基础之上，确保强可靠性。
> - **TCP/IP 设计哲学**：基于“端到端原则（End-to-End Principle）”。认为通信子网应当保持极度简单、高效且具备高鲁棒性，网际层仅提供无连接的尽力而为（Best-Effort）数据报服务；所有关于可靠性、流控、差错控制的复杂状态均由外围端系统的传输层（TCP）来自主保证。

### 1. 2022 年 408 统考真题第 33 题

#### 【题目展示】
在 ISO/OSI 参考模型中，实现两个相邻结点间流量控制功能的是（ ）。  
A. 物理层  
B. 数据链路层  
C. 网络层  
D. 传输层  

#### 【深入剖析】
1. **审题关键切入点**：题干的核心限定词为“**两个相邻结点间**”和“**流量控制**”。
2. **机制范围逐层排查**：
   - **物理层（A 选项）**：物理层仅负责在传输介质上透明传输比特流，不识别数据帧或报文结构，不具备任何差错控制或流量控制机制。
   - **数据链路层（B 选项）**：数据链路层负责管理相邻结点之间的点到点通信链路。其流量控制机制（如停止-等待协议、滑动窗口协议）旨在使发送结点的发送速率不超过接收结点的接收能力，且作用范围严格限定在相邻两个直连物理结点之间。故 B 选项完全符合题意。
   - **网络层（C 选项）**：网络层面向主机到主机的通信，其流量控制和拥塞控制立足于整个通信子网全局，旨在防止网络中路由器过载，并非针对单一相邻结点。
   - **传输层（D 选项）**：传输层面向端到端（进程到进程）的通信，其流量控制（如 TCP 滑动窗口）是端系统发送进程和接收进程之间的速率匹配，跨越了中间所有的路由结点。

#### 【正确答案】
**B**

### 2. 2021 年 408 统考真题第 33 题

#### 【题目展示】
在 TCP/IP 参考模型中，由传输层相邻的下一层实现的主要功能是（ ）。  
A. 对话管理  
B. 路由选择  
C. 端到端报文段传输  
D. 结点到结点流量控制  

#### 【深入剖析】
1. **定位目标层次**：
   - TCP/IP 参考模型自顶向下依次为：应用层、传输层、网际层（网络互联层）、网络接口层。
   - 题目询问的是“**传输层相邻的下一层**”，即**网际层（网络层，IP 层）**。
2. **选项逐项判别**：
   - **A 选项（对话管理）**：在 OSI 体系中，建立、管理和终止应用程序对话属于第 5 层会话层的功能；在 TCP/IP 中由应用层自行负责，并非网际层功能。
   - **B 选项（路由选择）**：网际层使用 IP 协议将数据报跨越异构网络从源主机路由转发到目的主机，其核心职责正是运行路由选择算法构建路由表，并根据目的 IP 地址为分组选择最优路由。B 选项正确。
   - **C 选项（端到端报文段传输）**：传输层自下而上第一个实现端到端进程通信，报文段（Segment）是传输层的 PDU，端到端传输是传输层自身的功能，而非其下一层网际层的功能。
   - **D 选项（结点到结点流量控制）**：TCP/IP 模型的网际层基于尽力而为交付的无连接不可靠设计原则，不保证分组的有序以及可靠到达，也不提供结点到结点的流量控制。

#### 【正确答案】
**B**

### 4. 2017 年 408 统考真题第 33 题

#### 【题目展示】
假设 OSI 参考模型的应用层欲发送 400B 的数据（无拆分），除物理层和应用层之外，其他各层在封装 PDU 时均引入 20B 的额外开销，则应用层数据传输效率约为（ ）。  
A. 80%  
B. 83%  
C. 87%  
D. 91%  

#### 【深入剖析】
1. **系统层次及开销结构分析**：
   - OSI 参考模型共有 7 个功能层次：物理层（1）、数据链路层（2）、网络层（3）、传输层（4）、会话层（5）、表示层（6）、应用层（7）。
   - 题设明确指出：
     - 应用层发送有效数据：$L_{\text{data}} = 400 \text{ B}$；
     - 物理层和应用层不引入额外开销；
     - 其余各层在封装 PDU 时均引入 $20 \text{ B}$ 的额外开销。
2. **计算引入额外开销的层次集合**：
   - 引入开销的中间层次包括：表示层、会话层、传输层、网络层、数据链路层。
   - 层次数量统计：
     $$ \text{N_{\text{overhead}} = 7 - 2 = 5 \text{ 层}} $$
3. **计算网络传输的总数据量**：
   - 协议控制信息总开销：
     $$L_{\text{overhead}} = 5 \times 20 \text{ B} = 100 \text{ B}$$
   - 线路上最终传输的总报文长度：
     $$L_{\text{total}} = L_{\text{data}} + L_{\text{overhead}} = 400 \text{ B} + 100 \text{ B} = 500 \text{ B}$$
4. **计算应用层有效传输效率**：
   $$\eta = \frac{L_{\text{data}}}{L_{\text{total}}} = \frac{400 \text{ B}}{500 \text{ B}} = 80\%$$

#### 【正确答案】
**A**

### 5. 2016 年 408 统考真题第 33 题

#### 【题目展示】
在 OSI 参考模型中，R1、Switch、Hub 实现的最高功能层分别是（ ）。  
A. 2、2、1  
B. 2、2、2  
C. 3、2、1  
D. 3、2、2  

#### 【深入剖析】
1. **分析物理网络设备的工作定位**：

2. **对照排列顺序**：
   - R1 对应 3；
   - Switch 对应 2；
   - Hub 对应 1。
   - 最终序列为 3、2、1。

#### 【正确答案】
**C**

- 会话层为第 5 层，其直接下层是第 4 层（传输层）。因此直接为会话层提供底层通信服务的是传输层。

#### 6.2 2013 年 408 统考真题第 33 题

A. 对话管理

C. 路由选择  
D. 可靠数据传输  

**【解析】**  
- 应用层为第 7 层，其相邻层为其直接下层——第 6 层表示层。

C. 会话层  
D. 应用层  

**【解析】**

## 四、 综合解答题深度拓展

在 408 统考的综合解答大题（第 47 题）中，计算机网络通常以跨层联合分析拓扑的形式出现。虽然第 47 题常以 IP 路由、TCP 流量控制或 Wireshark 抓包报文分析为表象，但其核心分析骨架完全依托于 OSI/RM 和 TCP/IP 分层封装理论。

### 1. 跨层报文封装解封装生命周期全流程

考研大题最经典的综合考法是：主机 $A$$ \text{（经由局域网交换机、默认网关路由器} $$R$$ \text{）向外网服务器} $$B$ 发起 Web 请求（HTTP GET）。

```text
Host A (PC)                 Switch                     Router (R)                 Server B
  [应用层: HTTP]
        | (封装)
  [传输层: TCP]
        | (封装)
  [网络层: IP]
        | (封装)
  [链路层: MAC] ---------> [链路层: MAC] 
                              | (仅查MAC表转发)
                              +---------------------> [链路层: MAC] (解封装)
                                                            |
                                                      [网络层: IP] (查路由表选路)
                                                            | (重新封装新MAC)
                                                      [链路层: MAC] ------------> ...
```

#### 1.1 各层头部关键字段的大题拆解标准
- **应用层**：生成 HTTP GET 请求报文，其在传输层中被视为应用层有效载荷（Payload）。
- **传输层**：
  - 添加 TCP 首部（固定 20 字节，若含可选字段则更长）；
  - 核心字段：源端口（随机高位端口）、目的端口（如 80 或 443）、序号（Seq）、确认号（Ack）、SYN/ACK/FIN 控制标志位。
- **网络层**：
  - 添加 IP 首部（固定 20 字节）；
  - 核心字段：源 IP 地址（Host A 的 IP）、目的 IP 地址（Server B 的 IP）、协议字段（Protocol = 6，指明上层为 TCP）、TTL（经过路由器减 1）。
- **数据链路层**：
  - 添加以太网帧首部（14 字节：目的 MAC 6B + 源 MAC 6B + 类型 2B）及帧尾部（4 字节 FCS）；
  - **核心踩分点**：当报文经过路由器转发时：
    - **IP 首部的源 IP 和目的 IP 保持不变**（不考虑 NAT 场景）；
    - **以太网帧首部的源 MAC 和目的 MAC 每经过一跳路由器都必须被重新改写**！目的 MAC 变为下一跳路由器的入端口 MAC，源 MAC 变为当前路由器出端口的 MAC。

#### 1.2 链路 MTU 及分片计算联动
- 数据链路层的最大传输单元（MTU, Maximum Transmission Unit）限制了数据链路层有效载荷（即上层 IP 分组）的最大长度（标准以太网 MTU = 1500 字节）。
- 若传输层 TCP 想要避免网络层 IP 分片，其最大报文段长度（MSS, Maximum Segment Size）的理论上限推导：
  $$ \text{MSS = MTU

- \text{IP Header Length}

- \text{TCP Header Length} = 1500

- 20

- 20 = 1460 \text{ 字节}} $$

```text
|  2   | 数据链路层 | 帧 (Frame)        | 交换机 / 网桥  | 相邻结点间无差错传输、成帧、介质控制|
|  1   | 物理层     | 比特 (Bit)        | 集线器 / 中继器| 在介质上透明传输原始比特流          |
+------+------------+-------------------+----------------+-------------------------------------+
```

### 2. 核心公式及参数速查

### 3. 十大经典避坑防错要点

1. **端到端服务的起点**：传输层是自底向上**第一个**提供端到端（进程到进程）服务的层次；网络层提供的是**主机到主机**的通信，切忌混淆。
2. **流量控制范围判定**：
   - 相邻结点之间 $\implies$ 数据链路层；
   - 通信子网全局 $\implies$ 网络层；
   - 进程对（端到端）之间 $\implies$ 传输层。
3. **两套体系连接特性反差**：
   - OSI：网络层支持面向连接和无连接，传输层**仅支持面向连接**；
   - TCP/IP：网际层**仅支持无连接**，传输层支持面向连接（TCP）和无连接（UDP）。
4. **数据链路层的特殊性**：只有数据链路层的 PDU 封装既增加首部（Header）又增加尾部（Trailer，用于 CRC 差错校验）。
5. **网络设备层次判定基准**：设备属于哪一层，取决于它**最高能解封装并依据哪一层的协议头部**进行转发。集线器（1层）、交换机（2层）、路由器（3层）。
6. **物理层设备不隔离碰撞域**：中继器和集线器属于物理层，不能隔离碰撞域，也不能隔离广播域；交换机可隔离碰撞域但不能隔离广播域；路由器既隔离碰撞域又隔离广播域。
7. **表示层及会话层定位**：
   - 只要看到“数据格式转换”、“加密解密”、“字符编码压缩”，直接锁定**表示层**；
   - 只要看到“对话管理”、“同步检查点”、“建立维护终止会话”，直接锁定**会话层**。
8. **SAP 及协议号区分**：
   - IP 协议首部中的 Protocol 字段是传输层访问网络层的 SAP；
   - 常见的协议号记忆：ICMP=1，IGMP=2，TCP=6，UDP=17，OSPF=89。
9. **以太网封装额外开销基数**：
   - Ethernet II 帧结构：目的 MAC (6B) + 源 MAC (6B) + 类型 (2B) + FCS (4B) = 18 字节开销。
   - 最小帧长为 64 字节，故有效载荷最小为 $64 - 18 = 46$ 字节。
10. **报文传输过程中的地址变化规律**：
    - 在没有 NAT 的典型网络中，跨路由转发时，IP 数据报的**源 IP 和目的 IP 始终保持不变**；
    - 数据链路层帧头部的**源 MAC 和目的 MAC 每经过一次路由器转发都被重新改写**。
