## 一、 考情档案

### 1. 考查频次及命题特点

在全国硕士研究生统一考试（计算机学科专业基础 408）中，网络互联设备是贯穿物理层、数据链路层以及网络层的核心枢纽考点。该知识点不仅在单项选择题中频繁考查设备的工作层次、冲突域及广播域的隔离特性，还在综合解答题（第 47 题）中作为网络拓扑构建、数据帧转发路径追踪和跨网段通信分析的物理载体。

近十年（2016~2025 年）该考点共考查 3 次单项选择题，历史统考中亦多次深入考查（如 2010 年第 38 题）。

命题特点呈现出如下鲜明规律：
1. **层次定位精准**：考查各网络互联设备在 OSI 参考模型和 TCP/IP 体系中所实现的最高功能层（如 2016 年第 33 题）。
2. **域边界判定量化**：结合网络拓扑图，精准计算网络中冲突域（Collision Domain）和广播域（Broadcast Domain）的独立数量（如 2020 年第 35 题）。
3. **数据转发机制微观追踪**：考察交换机的自学习算法、MAC 地址表构建过程，以及结合集线器的物理广播特性，判定物理层及数据链路层信号的可达范围（如 2016 年第 35 题）。
4. **综合大题拓扑联动**：在大题中，交换机、路由器常和子网划分、默认网关配置、ARP 协议解析以及 IP 数据报跨网段传输时的 MAC 地址更替紧密交织。

## 二、 具体考察内容

### 1. 网络互联设备分层体系及协议数据单元（PDU）处理能力

在分层网络架构中，网络设备被定义为其所能够理解并处理的**最高协议功能层**。设备工作在某一层，意味着该设备实现了该层及其以下所有层的功能。

```text
OSI 参考模型层次结构及对应互联设备映射：
+-----------------------+-----------------------+-----------------------+
| OSI 体系层次          | 协议数据单元 (PDU)    | 典型网络互联设备      |
+-----------------------+-----------------------+-----------------------+
| 应用层 (Application)  | 报文 / 报文段 (APDU)  | 应用层网关 (ALG)      |
| 表示层 (Presentation) | 表示层 PDU (PPDU)     | 网关 (Gateway)        |
| 会话层 (Session)      | 会话层 PDU (SPDU)     | 网关 (Gateway)        |
| 传输层 (Transport)    | 报文段 (Segment/TPDU) | 四层交换机 / 传输网关 |
| 网络层 (Network)      | 分组 / 数据报(Packet) | 路由器 / 三层交换机   |
| 数据链路层 (Data Link)| 帧 (Frame)            | 网桥 / 二层交换机     |
| 物理层 (Physical)     | 比特流 (Bit)          | 中继器 / 集线器 (Hub) |
+-----------------------+-----------------------+-----------------------+
```

#### 1.1 设备解封装深度及头部字段处理机制
1. **物理层设备（中继器、集线器）**：
   - 处理对象：纯模拟电信号或光信号（比特流）。
   - 处理行为：不解析任何协议头部，仅执行物理信号的放大、整形及再生。对数据链路层的帧格式完全透明。
2. **数据链路层设备（网桥、以太网交换机）**：
   - 处理对象：MAC 数据帧（Frame）。
   - 处理行为：接收物理信号并还原为二层 MAC 帧；解封装并检查帧头中的源 MAC 地址（用于转发表自学习）和目的 MAC 地址（用于查表转发）；计算并校验帧尾循环冗余校验码（CRC/FCS）。它不解析网络层 IP 头部。
3. **网络层设备（路由器、三层交换机）**：
   - 处理对象：IP 数据报（Packet / 分组）。
   - 处理行为：必须完全剥离二层 MAC 帧头及帧尾，提取出 IP 数据报；检查 IP 首部检验和；读取目的 IP 地址进行路由表最长前缀匹配；递减生存时间（TTL）并重新计算 IP 首部检验和；若分组长度超过下一跳链路 MTU 则执行分片；最后重新封装全新的下一跳链路层 MAC 帧头（改写源 MAC 和目的 MAC）及帧尾校验和发送。
4. **高层设备（网关）**：
   - 处理对象：高层报文（APDU）。
   - 处理行为：将数据逐层解封装至传输层或应用层，进行不同协议体系之间的语义翻译及格式转换（如 IPv4 和 IPv6 转换网关、邮件传输网关等）。

### 2. 物理层互连设备：中继器和集线器

#### 2.1 中继器（Repeater）
1. **工作原理及核心功能**：
   - 信号在物理传输介质（如双绞线、同轴电缆）上传播时，由于介质阻抗、集肤效应及电磁干扰，幅度衰减且波形发生畸变。
   - 中继器并非简单的线性放大器。线性放大器会将衰减的信号和叠加的噪声一同放大；而中继器属于**数字信号再生放大设备**，它对输入波形进行整形（Regenerating）及重新定时（Retiming），还原为规整的矩形脉冲数字信号再发射出去。
2. **以太网“5-4-3 规则”（10Base5 / 10Base2 传统以太网）**：
   - 在经典以太网总线拓扑中，为了保证 CSMA/CD 碰撞检测机制正常运作（即争用期 $2\tau$$ \text{必须大于等于传输最小帧} $$64\text{ B}$ 的时延），中继器的级联数量受到严格限制：
     - **5**：最多允许连接 5 个网段（Segments）；
     - **4**：在任意两台主机之间最多只能经过 4 个中继器（Repeaters）；
     - **3**：5 个网段中最多只能有 3 个网段可以挂接用户主机（Populated segments），其余 2 个网段仅用作中继连接链路。
   - 现代以太网已全面转向点对点双绞线星形拓扑及交换式网络，5-4-3 规则在百兆、千兆网络中已不再沿用，但其蕴含的“物理层扩展必然增加端到端传播时延，进而威胁碰撞检测有效性”的底层原理仍是 408 核心考点。

#### 2.2 集线器（Hub）
1. **本质属性**：
   - 集线器实质上是一个**多端口中继器**（Multiport Repeater）。
   - 逻辑结构为**总线型拓扑**，物理结构为**星形拓扑**。
2. **工作机制**：
   - 集线器内部采用电气共享总线架构。当某个端口接收到电信号后，集线器将其放大并整形，随后向除接收端口之外的**所有其他端口同时转发（广播）**该电信号。
   - 集线器不具备任何寻址能力、内部缓存或帧校验功能。
3. **共享介质和半双工限制**：
   - 连接在同一个集线器上的所有节点共享信道总带宽。若一个 $100\text{ Mbps}$$ \text{的集线器连接了 8 台主机，则 8 台主机平均分配} $$100\text{ Mbps}$ 传输速率。
   - 同一时刻只允许一台主机发送数据。若两台或更多主机同时发送，电信号将在集线器内部总线上发生碰撞（Collision），导致整个冲突域瘫痪。因此，集线器连接的网络**只能工作在半双工（Half-Duplex）模式**，必须依赖 CSMA/CD 协议解决信道争用。
4. **域隔离能力**：
   - **不能隔离冲突域**：集线器所有端口构成了同一个冲突域。
   - **不能隔离广播域**：广播帧或单播帧均会被集线器无差别转发，所有端口处于同一个广播域。

### 3. 数据链路层互连设备：网桥和以太网交换机

#### 3.1 网桥（Bridge）
1. **定义及工作机制**：
   - 网桥工作在数据链路层（MAC 子层），根据 MAC 帧的目的物理地址对帧进行过滤（Filter）及转发（Forward）。
   - 网桥将一个大的冲突域分割为多个小的冲突域。
2. **网桥分类**：
   - **透明网桥（Transparent Bridge，IEEE 802.1D）**：站点对于网桥的存在完全不知情，网桥通过“自学习算法”自动构建及维护转发表。
   - **源路由网桥（Source Route Bridge，IEEE 802.5）**：发送帧的源主机负责探明最佳路由，源主机首先发送一个发现帧（Discovery Frame），探寻到目的地的路径后，将完整路径信息填入帧头中的源路由字段。

#### 3.2 以太网交换机（Switch）
以太网交换机实质上是一个**多端口的透明网桥**。每个端口都可以直接连接一台主机或连接一个集线器。

```text
以太网交换机自学习及转发处理逻辑流图：
                 [ 交换机端口接收到 MAC 帧 ]
                             |
                             v
               [ 读取源 MAC 地址及接入端口号 ]
                             |
                             v
               [ 登记/更新 MAC 地址转发表项 ]
               [ 重置该条目的老化计时器 (Aging) ]
                             |
                             v
                     [ 提取目的 MAC 地址 ]
                             |
               +-------------+-------------+
               |                           |
         [ 目的 MAC 是广播/组播 ]     [ 目的 MAC 是单播地址 ]
               |                           |
               |                           v
               |               [ 查询 MAC 地址转发表 ]
               |                           |
               |                +----------+----------+
               |                |                     |
               |             [ 未命中 ]             [ 命中 ]
               |                |                     |
               |                |             [ 目的端口 == 入端口? ]
               |                |                     |
               |                |            +--------+--------+
               |                |            |                 |
               |                |         [ 是 (同一网段) ]   [ 否 ]
               |                |            |                 |
               |                |            v                 v
               v                v         [ 丢弃该帧 ]    [ 精确单播转发 ]
          [ 向除入端口外的所有端口广播泛洪 (Flooding) ]
```

##### 3.2.1 交换机转发表自学习算法（Self-Learning Algorithm）
以太网交换机初始上电时，其 MAC 地址转发表（CAM 表）完全为空。交换机通过监听每个端口流入的数据帧来动态学习拓扑：
1. **源地址学习**：当交换机从端口 $P_i$$ \text{接收到一个 MAC 帧时，提取该帧的**源 MAC 地址**} $$S$$ \text{。交换机将映射关系} $$(S, P_i, \text{Timestamp})$ 写入转发表；若该条目已存在，则更新时间戳并刷新端口。
2. **老化机制（Aging）**：为防止网络拓扑发生变动（如主机更换网卡、拔插网线或移动到新端口）时转发表产生错误指引，转发表中的每个表项均设置有一个老化定时器（典型默认值为 $300\text{ s}$$ \text{）。若在老化时间内未再收到来自源 MAC} $$S$ 的数据帧，该条目将被自动删除。
3. **目的地址查表转发**：
   - **明确单播转发（Filtering / Forwarding）**：若目的 MAC 地址 $D$$ \text{是单播地址，且在转发表中命中映射} $$(D, P_j)$：
     - 若 $P_j = P_i$（目的端口就是流入端口），表明目的主机与源主机位于同一个网段（通常通过集线器共用端口接入），目的主机已在物理介质上直接收到了该信号，交换机执行**过滤并丢弃（Filter / Drop）**；
     - 若 $P_j \neq P_i$$ \text{，交换机将该帧**精确转发（Unicast Forward）**到指定端口} $$P_j$。
   - **未知单播泛洪（Flooding）**：若目的 MAC 地址 $D$$ \text{在转发表中不存在，交换机向除入端口} $$P_i$ 之外的所有处于转发状态的端口发送该帧。
   - **广播/组播泛洪**：若目的 MAC 地址为广播地址（$\text{FF-FF-FF-FF-FF-FF}$）或多播地址，交换机直接向除入端口之外的所有其他端口泛洪。

##### 3.2.2 交换模式及数据转发时延数学推导
以太网交换机主要存在两种主流交换转发模式：

1. **存储转发交换模式（Store-and-Forward）**：
   - **工作流程**：交换机必须完整接收整个 MAC 帧并存入高速缓存中，读取帧尾进行 32 位 CRC 校验。若校验无误且帧长度在有效区间（$64 \sim 1518\text{ B}$$ \text{）内，才查询转发表进行转发；若校验出错或属于残帧（Runt Frame，} $$< 64\text{ B}$），则直接丢弃。
   - **优点**：可靠性极高，能够过滤网络中的冲突碎片和损坏帧；支持不同速率端口（如 $100\text{ Mbps}$$ \text{与} $$1\text{ Gbps}$）之间的速率匹配。
   - **缺点**：转发时延较大，时延与帧长成正比。
   - **时延数学推导**：
     设数据帧长度为 $L$$ \text{比特，交换机端口速率为} $$C$$ \text{（单位：} $$\text{bps}$$ \text{），交换机内部处理时延为} $$\tau_{\text{proc}}$$ \text{，物理链路传播时延为} $$\tau_{\text{prop}}$。
     若一个帧通过单台存储转发交换机从源节点传送到目的节点（经过两段链路）：
     
     $$T_{\text{Store-and-Forward}} = \frac{L}{C} + \tau_{\text{proc}} + \frac{L}{C} + 2\tau_{\text{prop}} = 2\frac{L}{C} + \tau_{\text{proc}} + 2\tau_{\text{prop}}$$

2. **直通交换模式（Cut-Through）**：
   - **工作流程**：交换机不缓存整个数据帧，一旦接收到以太网帧头部的**前 6 字节目的 MAC 地址**（共 $48\text{ bits}$），交换硬件立即执行转发表匹配，并在目的端口空闲时立刻将后续比特流直接流向输出端口。
   - **优点**：极低转发时延，时延大小与帧长无关。
   - **缺点**：不进行 CRC 校验，会将损毁的误码帧和碰撞碎片（Collision Fragment）扩散到后续网络；无法支持输入与输出端口速率不匹配的场景。
   - **时延数学推导**：
     直通交换机在接收到前导码（8 字节，若计算在内）及目的 MAC 地址（6 字节，即 48 比特）后即刻开始输出。
     设目的 MAC 接收时长为 $t_{\text{header}} = \frac{48\text{ bits}}{C}$$ \text{，内部查表时延为} $$\tau_{\text{lookup}}$：
     
     $$T_{\text{Cut-Through}} = \frac{L}{C} + \frac{48}{C} + \tau_{\text{lookup}} + 2\tau_{\text{prop}}$$
     
     显著可见，直通交换相比存储转发减少了几乎整整一个帧的发送时延 $\frac{L}{C}$。

3. **碎片隔离交换模式（Fragment-Free / Modified Cut-Through）**：
   - 折中方案：以太网碰撞碎片通常发生在传输的前 64 字节内。该模式在缓存并检查接收到前 $$ \text{64\text{ 字节}} $$ 后开始转发，既保证了过滤碰撞碎片，又显著降低了长帧的传输时延。

##### 3.2.3 环路风险及生成树协议（STP）
- 为了提高局域网的可靠性，网络设计中常引入物理链路冗余。然而，物理环路的存在会导致以太网广播帧在交换机之间无休止地循环复制与放大，形成**广播风暴（Broadcast Storm）**，引发 MAC 地址转发表震荡以及网络彻底瘫痪。
- IEEE 802.1D 规范定义了**生成树协议（Spanning Tree Protocol, STP）**。交换机之间通过交互网桥协议数据单元（BPDU），动态选举根网桥（Root Bridge），将环路拓扑在逻辑上阻塞（Blocking）冗余端口，剪枝为一棵无环路的生成树；当活动链路故障时，自动激活备份端口恢复通信。

##### 3.2.4 交换机的域隔离能力
- **隔离冲突域**：交换机的每一个端口都是一个独立的冲突域。每个端口具有独立的 MAC 控制器和缓存，通常工作在全双工模式下，彻底消除了 CSMA/CD 碰撞。
- **不隔离广播域**：交换机所有端口默认属于同一个广播域。广播帧会泛洪到交换机所有端口。只有通过划分虚拟局域网（VLAN），交换机才能在逻辑上切分广播域。

### 4. 网络层互连设备：路由器

#### 4.1 路由器的体系结构
路由器是工作在网络层的分组交换设备，在逻辑上可划分为两大功能平面：

```text
路由器的微观体系结构划分：
+---------------------------------------------------------------+
|                    控制平面 (Control Plane)                   |
|  - 路由选择处理器 (Routing Processor)                         |
|  - 运行路由协议 (OSPF, BGP, RIP)，执行分布式路由算法          |
|  - 构建及动态维护路由表 (Routing Table)                       |
+-------------------------------+-------------------------------+
                                | 路由信息下发 (FIB 生成)
                                v
+---------------------------------------------------------------+
|                     数据平面 (Data Plane)                     |
|                                                               |
|  +----------------+     +---------------+     +------------+  |
|  | 输入端口队列   | --> | 高速交换结构  | --> | 输出端口   |  |
|  | (查表及转发)   |     | (Crossbar/总线|     | 调度队列   |  |
|  +----------------+     +---------------+     +------------+  |
+---------------------------------------------------------------+
```

1. **控制平面（Control Plane / 软件实现）**：
   - 核心组件：路由选择处理器（CPU）。
   - 功能职责：运行路由选择协议（如 RIP, OSPF, BGP），根据网络拓扑变化动态计算最佳路径，生成**路由表（Routing Table）**。路由表的更新属于秒级或分钟级的较慢时间尺度。
2. **数据平面（Data Plane / 硬件 ASIC 实现）**：
   - 核心组件：物理输入端口、高速交换结构（Switch Fabric，如共享内存、共享总线、Crossbar 交叉开关矩阵）、物理输出端口。
   - 功能职责：根据控制平面下发的**转发表（Forwarding Information Base, FIB）**，执行硬件线速查找，将到达输入端口的 IP 数据报以纳秒级时间尺度搬移到正确的输出端口。

#### 4.2 跨网段分组转发核心处理流程
当路由器某个端口接收到一个数据帧时，必须严格执行以下处理链条：
1. **链路层校验及解封装**：验证接收帧尾的 CRC 校验码。若正确，剥去二层帧头（源/目的 MAC 地址）和帧尾，将 IP 数据报递交给网络层；
2. **网络层报头校验**：检查 IP 首部检验和，若损坏则直接丢弃；
3. **生存时间处理**：将 IP 首部中的 TTL 字段减 1。若 $\text{TTL} \le 0$，丢弃该分组并向源主机发送 ICMP 超时差错报文；
4. **重新计算首部检验和**：由于 TTL 发生变化，利用增量算法重新计算 IP 首部检验和并填入；
5. **路由匹配**：读取目的 IP 地址，在转发表中执行**最长前缀匹配（Longest Prefix Match）**算法，确定下一跳 IP 地址及输出接口；
6. **分片检测**：对比 IP 数据报总长度与输出接口链路的 MTU（最大传输单元）。若总长度大于 MTU 且 DF 标志位为 0，则按 MTU 切分为多个 IP 分片；若 DF=1 则丢弃并发送 ICMP 终点不可达报文；
7. **链路层重封装**：通过 ARP 协议解析出下一跳 IP 地址对应的目的 MAC 地址。封装全新的链路层首部（**源 MAC 填入路由器本输出端口的 MAC 地址，目的 MAC 填入下一跳路由器或目的主机的 MAC 地址**），重新计算 CRC 并从输出端口发送出去。

#### 4.3 抑制广播风暴
- **彻底隔离冲突域**：每个路由器端口连接一个独立的冲突域。
- **天然隔离广播域**：路由器阻断二层广播帧（MAC 地址为 $\text{FF-FF-FF-FF-FF-FF}$$ \text{）和网络层定向广播包（如子网受限广播} $$255.255.255.255$）。路由器的每个物理接口代表一个独立的广播域（即一个独立的 IP 子网）。

### 5. 高层互连设备：三层交换机和网关

#### 5.1 三层交换机（Layer 3 Switch）
1. **技术驱动背景**：
   - 传统局域网中，不同 VLAN 之间的通信必须依赖外部单臂路由器（Router-on-a-Stick）进行三层转发。由于路由器基于通用 CPU 进行软件查表，转发速率远落后于二层交换机的硬件 ASIC 线速转发，形成了“路由器瓶颈”。
2. **工作机制：“一次路由，多次交换”**：
   - **首包路由**：当 VLAN 10 的主机向 VLAN 20 的主机发送第一个数据包时，三层交换机内部的路由处理模块（三层引擎）执行常规路由表查询，确定下一跳、出端口并解析 ARP，随后由硬件 ASIC 芯片记录该数据流的源/目的 IP、源/目的 MAC 与出端口的映射关系，生成快速转发表项（Cache）；
   - **后续包交换**：该数据流后续的所有数据包不再经过 CPU 软件路由查找，直接由硬件 ASIC 芯片根据缓存的二层重写信息执行线速硬件转发（MLS / CEF 机制）。
3. **三层交换机对比传统路由器之差异**：
   - 三层交换机专为高性能局域网内部不同 VLAN 间的高速互连设计，路由接口类型单一（主要为以太网接口），NAT、VPN、复杂策略路由功能相对简单；
   - 路由器用于企业边界及广域网互连，支持多样化的 WAN 接口（如 POS、串行接口、ATM 等），具备完善的防火墙、QoS、复杂流量工程和 NAT 功能。

#### 5.2 网关（Gateway）
- 网关在传统定义中指工作在传输层及以上的高层协议转换设备。
- **协议转换能力**：不同于路由器仅仅在相同的网络层协议（如 IP）下互连异构物理网段，网关能够实现两种完全不同的高层协议体系之间的翻译（如 SNA 网络和 TCP/IP 网络互联、POP3 邮件网关、SIP 和 H.323 语音网关）。
- **注意概念区分**：在日常主机网络配置中填写的“默认网关（Default Gateway）”，实际上专指主机所在子网连接外部网络的**路由器接口 IP 地址**（网络层边界设备），切勿混淆两者的语境。

#### 7.2 直通式交换和存储转发式交换对比

```text
+----------------------+---------------------------------+---------------------------------+
| 比较维度             | 直通式交换 (Cut-Through)        | 存储转发式交换 (Store-and-Fwd)  |
+----------------------+---------------------------------+---------------------------------+
| 转发判决时机         | 仅接收前 6 字节目的 MAC 即转发   | 必须完整接收并校验整帧后转发    |
| 转发时延大小         | 极小 (数十纳秒级，固定不随帧增) | 较大 (依赖帧长度 L/C，随帧增大) |

+----------------------+---------------------------------+---------------------------------+
```

#### 7.3 二层交换机、三层交换机和路由器功能边界辨析
- **二层交换机**：基于硬件 MAC 查表，负责在**同一个广播域（同一个子网/同一个 VLAN）内部**进行高速数据帧交换，无法跨越不同的子网。
- **三层交换机**：本质是“二层线速交换 + 硬件化三层路由”。主要面向企业级大型局域网内部**跨 VLAN 的高速线速通信**，主要依据 FIB 表和邻接表进行转发，硬件转发吞吐量极大。
- **路由器**：具备复杂的软件协议栈和广域网接口，面向**异构网络互连和广域网边界接入**，提供强大的安全策略、NAT 转换、QoS 保障和复杂的广域网路由计算。

### 1. 2020 年 408 统考真题第 35 题

#### 【题目展示】
在下图所示的网络中，冲突域和广播域的个数分别是（ ）。

```text
                     +------------+
                     |   路由器   |
                     +-----+------+
                           |
        +------------------+------------------+
        | 接口 1                              | 接口 2
        v                                     v
+-------+--------+                   +--------+-------+
|  以太网交换机  |                   |  100Base-T     |
+---+----+---+---+                   |    集线器      |
    |    |   |                       +----+---+---+---+
    |    |   +-----------+                |   |   |
    |    |               |                |   |   |
   H1    H2       [集线器/主机分支]      H3  H4  H5
```

*注：拓扑中路由器拥有两个活动接口，分别连接左侧的以太网交换机和右侧的 100Base-T 集线器。交换机共向下连接主机及直连分支，集线器共连接多台主机。*

A. 2，2  
B. 2，4  
C. 4，2  
D. 4，4  

#### 【深入推导及逐项解析】
本题的核心考点是利用不同层次网络设备对**冲突域（Collision Domain）**和**广播域（Broadcast Domain）**的隔离能力进行量化判定。

**步骤一：分析广播域（Broadcast Domain）的个数**
1. 广播域由网络层及以上设备进行物理阻断。路由器是网络层设备，其核心特性是默认不转发链路层广播帧（广播地址为 $\text{FF-FF-FF-FF-FF-FF}$）和受限广播分组。
2. 题目拓扑中存在 **1 台路由器**，该路由器使用了 **2 个网络接口**：
   - 接口 1 连接左侧子网（包含以太网交换机及其下连的所有终端）；
   - 接口 2 连接右侧子网（包含 100Base-T 集线器及其下连的所有终端）。
3. 由于以太网交换机和集线器均无法隔离广播域，左侧交换机连接的所有设备处于同一个广播域中；右侧集线器连接的所有设备亦处于同一个广播域中。
4. 路由器将左右两侧的网络彻底分隔为 **2 个互不相通的广播域**。因此，广播域个数为 **2**。

**步骤二：分析冲突域（Collision Domain）的个数**
1. 冲突域由物理层共享介质所限定，能够被数据链路层设备（交换机、网桥）和网络层设备（路由器）所隔离：
   - **以太网交换机**：每个端口是一个独立的冲突域。交换机内部能够隔离冲突，不同端口之间的通信互不产生电气碰撞。
   - **100Base-T 集线器**：属于物理层设备，内部采用共享电气总线，既不隔离冲突域，也不具备缓存过滤功能。连接在同一个集线器上的所有节点及该集线器上联的链路，**全部处于同一个冲突域内**。
   - **路由器端口**：作为独立的数据链路层节点，每个路由器接口也作为一个冲突域的边界。
2. 依据拓扑统计各部分的冲突域分布：
   - **左侧子网（交换机部分）**：
     - 冲突域 1：路由器接口 1 到以太网交换机上联端口之间的点对点链路；
     - 冲突域 2：以太网交换机连接主机 H1 的端口链路；
     - 冲突域 3：以太网交换机连接主机 H2 的端口链路；
     （即交换机连接的每个活动端口均形成一个独立的冲突域，在原题标准拓扑分配中，交换机侧共隔离出 3 个独立的冲突域）。
   - **右侧子网（集线器部分）**：
     - 冲突域 4：路由器接口 2 连接到 100Base-T 集线器，且集线器同时下挂主机 H3、H4、H5。由于集线器是共享介质设备，无法隔离冲突，因此路由器接口 2、集线器本身、以及所有连接在集线器上的主机共同处于**同一个冲突域**中。
3. 统计全网冲突域总数：
   
   $$ \text{冲突域总数} = 3 \text{ (交换机侧)} + 1 \text{ (集线器侧)} = 4 \text{ 个} $$

综上所述，该网络中冲突域和广播域的个数分别是 **4** 和 **2**。

#### 【正确答案】
**C**

### 2. 2016 年 408 统考真题第 33 题

#### 【题目展示】
在 OSI 参考模型中，R1、Switch、Hub 实现的最高功能层分别是（ ）。  
A. 2、2、1  
B. 2、2、2  
C. 3、2、1  
D. 3、2、2  

#### 【深入推导及逐项解析】
本题重点考查典型网络互联设备在 OSI 七层参考模型中的归属和最高实现层次。

1. **R1（路由器 Router）**：
   - 路由器工作在**网络层（第 3 层）**。
   - 路由器的基本功能是路由选择和分组转发，其工作依赖于网络层 IP 地址。路由器实现了 OSI 参考模型由下至上的下三层协议栈，即物理层（第 1 层）、数据链路层（第 2 层）和网络层（第 3 层）。因此，R1 实现的最高功能层是**网络层（即 3）**。
2. **Switch（以太网交换机）**：
   - 传统以太网交换机本质上是多端口网桥，工作在**数据链路层（第 2 层）**。
   - 交换机能够解析并识别 MAC 数据帧，根据目的 MAC 地址进行查表转发和帧过滤，并具备 MAC 地址自学习功能。它实现了物理层和数据链路层。因此，Switch 实现的最高功能层是**数据链路层（即 2）**。
3. **Hub（集线器）**：
   - 集线器实质上是多端口中继器，工作在**物理层（第 1 层）**。
   - 集线器对接收到的信号仅进行电气层面的整形和放大，并将其广播到所有其他端口。集线器对数据链路层的帧格式完全无知，不具备任何 MAC 寻址和帧解析能力。因此，Hub 实现的最高功能层是**物理层（即 1）**。

因此，R1、Switch、Hub 实现的最高功能层分别为 3、2、1。

#### 【正确答案】
**C**

### 3. 2016 年 408 统考真题第 35 题

#### 【题目展示】
某网络拓扑如下图所示，Switch 为以太网交换机，Hub 为 100Base-T 集线器。若主机 H2 向主机 H4 发送 1 个数据帧，主机 H4 向主机 H2 立即发送一个确认帧，则除 H4 外，从物理层上能够收到该确认帧的主机还有（ ）。

```text
                     +-------------------+
                     |    路由器 R1      |
                     +---------+---------+
                               |
                   +-----------+-----------+
                   |  以太网交换机 Switch  |
                   +----+------+------+----+
                        |      |      |
                        |      |      +----------------+
                        |      |                       |
                       H1     H2               +-------+-------+
                                               | 100Base-T Hub |
                                               +-------+-------+
                                                       |       |
                                                      H3      H4
```

A. 仅 H2  
B. 仅 H3  
C. 仅 H1、H2  
D. 仅 H2、H3  

#### 【深入推导及逐项解析】
本题是 408 历年考题中将**以太网交换机的自学习机制**和**集线器的物理广播特性**结合得最为巧妙的经典试题。解题的关键在于分阶段微观追踪数据流在物理层和数据链路层的传播路径以及设备动态反应。

**阶段一：H2 向 H4 发送数据帧过程**
1. **主机 H2 发出数据帧**：帧的源 MAC 地址为 $\text{MAC}_{H2}$$ \text{，目的 MAC 地址为} $$\text{MAC}_{H4}$。
2. **交换机 Switch 接收并执行自学习**：
   - 帧从连接 H2 的端口进入 Switch；
   - Switch 读取帧头的源 MAC 地址 $\text{MAC}_{H2}$，在其 MAC 转发表中记录或更新条目：
     
     $$ \text{条目}: (\text{MAC}_{H2} \to \text{连接 H2 的端口}) $$
     
   - 此时 Switch 无论其转发表中是否存在 $\text{MAC}_{H4}$，该数据帧最终都会被送达连接 Hub 的端口并输出；
3. **集线器 Hub 接收和广播**：
   - 帧进入 Hub 后，由于 Hub 处于物理层，它将电信号无条件向其连接的所有端口转发；
   - 连接在 Hub 上的主机 H3 和 H4 都在物理层接收到该数据帧；
   - H3 的网卡在链路层检查目的 MAC，发现不是自身且非广播地址，遂丢弃该帧；H4 检查目的 MAC 与自身匹配，接收该帧。

**阶段二：H4 立即向 H2 发送确认帧过程（核心追踪）**
1. **主机 H4 发出确认帧**：帧的源 MAC 地址为 $\text{MAC}_{H4}$$ \text{，目的 MAC 地址为} $$\text{MAC}_{H2}$。
2. **确认帧首先到达集线器 Hub**：
   - Hub 作为一个物理层多端口中继器，不解析 MAC 地址，也不维护转发表。
   - Hub 的物理工作特性是：**将从某端口接收到的信号，向除该端口以外的所有其他端口进行电气广播**。
   - 因此，从 Hub 的物理连线来看，该确认帧被同时广播发送到了：
     - **主机 H3**；
     - **以太网交换机 Switch 的对应端口**。
   - **判定 1**：主机 H3 从物理介质上直接收到了代表该确认帧的电信号。尽管 H3 在数据链路层检查帧头发现目的 MAC 是 $\text{MAC}_{H2}$ 而最终会丢弃该帧，但题干设问的是**“从物理层上能够收到该确认帧”**，因此 **H3 必然能够收到**。
3. **确认帧进入以太网交换机 Switch**：
   - Switch 从连接 Hub 的端口接收到该确认帧；
   - Switch 首先自学习：记录 $\text{MAC}_{H4}$ 与连接 Hub 端口的映射关系；
   - 紧接着，Switch 检索 MAC 转发表以决定如何转发该帧：
     - 查询目的 MAC 地址：$\text{MAC}_{H2}$；
     - 在阶段一中，Switch 已经学习到了 $\text{MAC}_{H2}$ 位于连接主机 H2 的端口；
     - 因此，Switch 执行**明确单播转发（Unicast Forwarding）**，仅将该确认帧从连接 H2 的端口精准发送出去，**绝不会向连接 H1 或其他端口泛洪**！
   - **判定 2**：主机 H2 从交换机端口接收到了该确认帧，**H2 必然能够收到**。
   - **判定 3**：主机 H1 连接在交换机的另一个独立端口上，由于交换机隔离了冲突域且已知目的端口，H1 所在端口没有电信号输出，因此 **H1 在物理层根本接收不到该帧**。

**阶段三：综合汇总**
除发送方 H4 外，在物理层上能够接收到该确认帧的主机包括：
- 受到集线器物理广播波及的 **H3**；
- 受到交换机精准单播送达的 **H2**。

因此，除 H4 外，从物理层上能够收到该确认帧的主机为**仅 H2、H3**。

#### 【正确答案】
**D**

### 4. 历史经典真题拓展：2010 年 408 统考真题第 38 题

#### 【题目展示】
下列网络设备中，能够抑制广播风暴的是（ ）。  
I. 中继器  
II. 集线器  
III. 网桥  
IV. 路由器  

A. 仅 I 和 II  
B. 仅 III  
C. 仅 III 和 IV  
D. 仅 IV  

#### 【深入推导及逐项解析】
广播风暴（Broadcast Storm）是指过量的广播数据帧充斥网络，导致网络带宽耗尽、主机 CPU 因频繁响应中断而严重过载甚至网络彻底瘫痪的现象。广播风暴的扩散范围由**广播域（Broadcast Domain）**的物理边界决定。

1. **中继器（I）和集线器（II）**：工作在物理层，对接收到的信号盲目放大和广播转发，既不能隔离冲突域，更无法隔离广播域，完全无法抑制广播风暴。
2. **网桥（III）和以太网交换机**：工作在数据链路层，能够基于 MAC 地址隔离冲突域。但在面对广播帧（目的 MAC 为 $\text{FF-FF-FF-FF-FF-FF}$）时，根据透明网桥的规范算法，网桥必须向除接收端口外的所有端口无条件泛洪。因此，网桥连接的所有端口仍处于同一个广播域内，**无法抑制广播风暴**。
3. **路由器（IV）**：工作在网络层。路由器以 IP 子网为边界划分广播域。路由器内部的路由表基于 IP 寻址，当路由器接口收到二层广播帧或受限广播报文时，默认直接丢弃，绝不会向其他网络接口转发。因此，路由器能够切断广播蔓延的路径，**是唯一能够天然抑制广播风暴的互联设备**。

综上所述，只有路由器能够抑制广播风暴。

#### 【正确答案】
**D**

### 2. 综合大题核心采分点及规范答题法则

在历年 408 综合大题中，涉及设备特性的高频设问与标准得分要点如下：

1. **子网掩码及默认网关判别**：
   - 设问：“主机 H1 的默认网关应该配置为哪个地址？”
   - **答题规范**：必须填写与该主机处于同一子网的**路由器直连接口的 IP 地址**。若题目未显式分配，应选取该网段中预留的第一个（如 `.1`）或最后一个可用主机 IP 地址。
2. **跨路由数据传输的 MAC/IP 地址变迁表**：
   - 设问：“写出数据帧在各链路上传输时，源 IP、目的 IP、源 MAC、目的 MAC 的取值。”
   - **采分法则**：
     - 在无 NAT（网络地址转换）环境下，**源 IP 地址和目的 IP 地址全过程始终保持不变**；
     - **源 MAC 地址和目的 MAC 地址每经过一个路由器接口就会彻底改写一次**。源 MAC 必须变为当前转发路由器的出接口 MAC，目的 MAC 必须变为下一跳路由器入接口 MAC 或目的主机 MAC。
3. **网络设备冲突域和广播域计算设问**：
   - 设问：“若将图中的集线器全部替换为以太网交换机，网络中的冲突域和广播域数量如何变化？”
   - **标准推导模板**：
     - **广播域判定**：广播域由路由器接口划分。只要路由器接口数量及 VLAN 划分未改变，**广播域数量保持不变**；
     - **冲突域判定**：原集线器下挂的多个节点由共享 1 个冲突域，变为交换机的每个端口独立占用 1 个冲突域。若原集线器连接了 $N$$ \text{台主机和 1 个上联链路，替换为交换机后，该局域网的冲突域数量增加} $$(N + 1) - 1 = N$ 个。

## 五、 考点速记清单

### 1. 核心判据速记口诀

```text
物理层 Hub/中继器：信号放大只管传，同处一个冲突域，广播风暴更是难。
链路层 Switch/网桥：端口独占冲突完，二层地址自学习，遇到广播全端口翻。
网络层 Router/路由：隔绝冲突斩断广播，IP 选路逐跳换，MAC 变迁 IP 贯穿。
```

### 2. 网络设备特性全景速查表

| 设备名称     | 归属层次 | 隔离冲突 | 隔离广播 | 核心工作依据     | 典型传输时延模式 |

### 3. 经典避坑防错要点

1. **“物理层接收”对比“链路层接收”边界辨析（谨防 2016#35 陷阱）**：
   - 若题目询问“从**物理层**上能够收到该帧的主机”，只要主机所连介质上有电信号/光信号流过（例如通过集线器广播扩散到达），该主机物理层就算接收到！
   - 若题目询问“从**数据链路层**上能够接收”，则只有目的 MAC 与自身网卡 MAC 匹配，或是广播帧（$\text{FF-FF-FF-FF-FF-FF}$）时，主机的网卡才会接收并递交给操作系统，否则在链路层被静默丢弃。
2. **交换机自学习的“源地址和目的地址”异步处理机制**：
   - 交换机**根据数据帧的源 MAC 地址来学习**端口映射条目；
   - 交换机**根据数据帧的目的 MAC 地址来决定**是精确单播、泛洪还是丢弃。
   - 收到单播帧但目的 MAC 未知时，交换机执行**泛洪（Flooding）**而非丢弃！
3. **路由器接口的双重身份**：
   - 路由器的每个物理接口既是一个**独立的广播域**边界，其本身也是连接该网段的**一个独立的冲突域**节点。
   - 路由器隔离广播域，因此跨路由器的两个网段**绝对不可能属于同一个 IP 子网**。
4. **共享带宽和独占带宽之性能辨析**：
   - $N$$ \text{端口、速率为} $$C$$ \text{的集线器，全网所有端口共享带宽，单端口平均理论带宽为} $$\frac{C}{N}$；
   - $N$$ \text{端口、速率为} $$C$$ \text{的以太网交换机，每个端口独占带宽} $$C$$ \text{。若工作在全双工模式下，交换机总的理论背板数据吞吐能力上限为} $$2 \times N \times C$。
