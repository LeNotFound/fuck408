## 二、 具体考察内容

### 1. 自动重传请求（ARQ）核心概念及物理本质

在计算机网络通信中，不可靠物理信道存在信号衰减、热噪声、电磁干扰等缺陷，会导致比特差错（0变成1或1变成0）乃至整帧丢失。差错控制技术主要分为两类：
- **前向纠错（FEC, Forward Error Correction）**：发送端在数据中加入足够的冗余纠错码（如海明码、Reed-Solomon码），接收端不仅能发现差错，还能直接纠正差错。缺点是冗余开销大，在信道质量良好时造成严重带宽浪费。
- **自动重传请求（ARQ, Automatic Repeat reQuest）**：发送端采用检错码（如 CRC 循环冗余码）。接收端检测到差错后丢弃该帧，并通过控制报文反馈通知发送端；若发送端在规定时间内未收到确认，则自动重新发送该帧。

ARQ 机制通过**检错重传**代替前向纠错，以极低的头部冗余开销换取了复杂信道上的绝对可靠传输。

#### ARQ 协议三要素
1. **帧序号（Sequence Number, Seq）**：发送端为每个发出的数据帧打上唯一编号，解决帧丢失、帧乱序、帧重复问题。
2. **确认应答（Acknowledgment, ACK）及否定应答（Negative ACK, NAK）**：
   - 肯定确认（ACK）：接收端通知发送端特定数据帧已正确接收。
   - 否定确认（NAK）：接收端通知发送端特定数据帧损坏，请求立即重传。
   - 捎带确认（Piggybacking）：在双向数据传输中，ACK 信息不通过专用控制帧发送，而是直接嵌入到反向发送的数据帧首部的确认序号字段中，大幅节省链路开销。
3. **超时重传定时器（Retransmission Timer）**：发送端发送数据帧时启动定时器。若在重传超时时间（RTO, Retransmission TimeOut）内未收到对应的 ACK，发送端判定该帧在信道中丢失或损坏，主动触发重传。

### 2. 三大 ARQ 协议机制及工作流程

依据发送窗口大小 $W_T$$ \text{（Transmit Window）和接收窗口大小} $$W_R$（Receive Window）的不同取值，ARQ 协议分为三大经典形态：

```
                    ┌───────────────── ARQ 协议分类 ─────────────────┐
                    │                                                │
          停等协议 (Stop-and-Wait)                         连续 ARQ 协议 (Pipelined)
            WT = 1, WR = 1                                           │
                                            ┌────────────────────────┴────────────────────────┐
                                            │                                                 │
                                 后退 N 帧协议 (GBN)                               选择重传协议 (SR)
                               WT > 1, WR = 1                                    WT > 1, WR > 1
```

#### （1）停等协议（Stop-and-Wait ARQ）
- **窗口参数**：$W_T = 1$，$W_R = 1$。
- **工作机制**：发送方每次只发送 1 个数据帧，然后停止发送并等待接收方的 ACK。只有收到确认后，才允许发送下一个数据帧。
- **四大典型时序场景分析**：
  1. **正常无差错**：发送帧 0 $\to$$ \text{接收方收到并回送 ACK0} $$\to$ 发送方收到 ACK0，滑动窗口，发送帧 1。
  2. **数据帧丢失**：发送帧 0 途中丢失 $\to$$ \text{接收方未收到，不发 ACK} $$\to$ 发送方定时器超时，重新发送帧 0。
  3. **确认帧丢失**：发送帧 0 $\to$$ \text{接收方收到并回送 ACK0，但 ACK0 途中丢失} $$\to$$ \text{发送方超时重发帧 0} $$\to$ 接收方再次收到帧 0，通过序号发现重复，果断丢弃重复帧，但**必须重发一次 ACK0**（否则发送方将永久陷入超时重发死锁）。
  4. **确认帧超时迟到**：发送帧 0 $\to$$ \text{ACK0 遭遇严重网络排队迟到} $$\to$$ \text{发送方超时重发帧 0} $$\to$$ \text{接收方收到重复帧 0 丢弃并重发 ACK0} $$\to$$ \text{发送方先收到迟到的 ACK0，发送帧 1} $$\to$ 随后收到重发的 ACK0，发送方检测到重复 ACK 直接丢弃。
- **1 比特编号机制**：由于停等协议中同一时刻信道上最多只有 1 个处于未确认状态的数据帧，帧序号只需区分“当前帧”和“相邻的前后帧”。因此只需 1 个比特对帧进行交替编号（0 和 1），对应的 ACK 帧也只需 0 和 1。

#### （2）后退 N 帧协议（Go-Back-N ARQ）
- **窗口参数**：$1 < W_T \le 2^n - 1$，$W_R = 1$$ \text{（其中} $$n$ 为帧序号编码比特数）。
- **发送端工作机制**：
  - 发送端允许连续发送最多 $W_T$ 个数据帧，无需每发一帧就停下来等待。
  - 发送端维护一个发送窗口，窗口下界为最早未被确认的帧（$SendBase$$ \text{），窗口上界为允许发送的最大序号（} $$SendBase + W_T - 1$）。
  - 发送端仅维护**单一的重传定时器**，对应最早未确认的帧（$SendBase$$ \text{）。每当收到一个有效 ACK 导致窗口向前滑动，定时器就重启并对准新的} $$SendBase$；若窗口内所有帧均已被确认，则停止定时器。
- **接收端工作机制及累积确认**：
  - 接收窗口尺寸固定为 $W_R = 1$$ \text{。接收端维护期望接收的帧序号} $$RcvBase$。
  - **累积确认（Cumulative Acknowledgment）**：接收端返回的 ACK 序号 $k$$ \text{表示“期望接收第} $$k$$ \text{号帧”，这一语义直接标明：**编号为} $$k-1$ 及之前的所有数据帧均已按序完整、正确接收**。
  - **乱序丢弃策略**：若接收端收到序号不等于 $RcvBase$$ \text{的帧（哪怕内容完全无误），接收端直接丢弃该失序帧，绝不缓存，并重新发送对最后一个按序到达帧的确认（即重复发送期望序号为} $$RcvBase$ 的 ACK）。
- **超时重传风暴（后退 N 帧本质）**：
  - 若编号为 $i$$ \text{的帧在传输中丢失，即使后续编号为} $$i+1, i+2, \dots$$ \text{的帧均成功到达接收端，也会因为不满足} $$RcvBase = i$ 而被全数丢弃。
  - 最终发送端针对帧 $i$$ \text{的定时器超时，发送端必须将从帧} $$i$ 开始直到窗口当前已发出的所有后续帧全部重新发送一遍，即所谓“Go-Back-N”（后退 N 步重发）。
  - **优势**：接收端实现极其简单，无需乱序重组缓冲区；单个 ACK 丢失不会造成致命后果（后续更高序号的 ACK 可以覆盖挽救前面的丢失 ACK）。
  - **劣势**：信道误码率较高时，会引发大量正确帧的无效重传，导致网络有效吞吐率断崖式下跌。

#### （3）选择重传协议（Selective Repeat ARQ）
- **窗口参数**：$W_T \le 2^{n-1}$，$W_R \le 2^{n-1}$$ \text{，且满足} $$W_T + W_R \le 2^n$$ \text{（工程设计通常取对称窗口} $$W_T = W_R = 2^{n-1}$）。
- **逐帧独立确认机制**：
  - 接收端对每一个正确到达的数据帧进行**逐帧独立确认（Individual ACK / Selective ACK）**。
  - ACK 序号 $k$$ \text{仅代表第} $$k$ 号数据帧本身已被正确接收，完全不包含对其前面帧的任何累积确认含义。
- **接收端工作机制及失序缓存**：
  - 接收端维护尺寸大于 1 的接收窗口 $[RcvBase, RcvBase + W_R - 1]$，并开辟接收缓冲区。
  - 若到达的数据帧落在接收窗口内且之前未收到过：
    - 若其序号恰好等于 $RcvBase$$ \text{，接收端将其放入缓冲区，随后将从} $$RcvBase$ 开始的一连串连续数据帧一并向上层协议交付，接收窗口大幅向前滑动。
    - 若其序号大于 $RcvBase$（乱序到达），接收端将其暂存于接收缓冲区中，并向发送端回送对应的独立 ACK，接收窗口暂时不滑动。
- **发送端独立定时器机制**：
  - 发送端为**每一个已发送但未收到确认的数据帧独立配置一个重传定时器**。
  - 当某个数据帧的定时器超时，发送端**仅重传该单一超时帧**，绝不牵连后续已成功发送或已被对方确认的帧。
  - **优势**：极大降低了信道高误码率下的无谓重传开销，信道利用率更稳定。
  - **劣势**：收发双方均需开辟大容量缓冲存储区，且逻辑控制、定时器管理开销较高。

### 3. 窗口尺寸约束条件的严谨数学推导

在 408 考研中，关于 $n$ 比特帧序号下窗口尺寸取值范围的考查是常考题型。下面给出严格的无二义性数学推导。

#### （1）滑动窗口协议通用约束定理：$W_T + W_R \le 2^n$

> **定理**：在帧序号采用 $n$$ \text{比特二进制编码（即序号空间为模} $$2^n$$ \text{，序号取值集合为} $$\{0, 1, 2, \dots, 2^n - 1\}$$ \text{）的任意滑动窗口协议中，为彻底避免由于信道丢包、重传导致的“新老数据帧序号二义性混淆”，发送窗口大小} $$W_T$$ \text{及接收窗口大小} $$W_R$ 必须满足：
> $$W_T + W_R \le 2^n$$

**反证法及状态机二义性严格推导**：
1. **初始状态设定**：
   设通信初始时刻，发送方的发送窗口下界为序号 $s$$ \text{，窗口范围为} $$[s, (s + W_T - 1) \bmod 2^n]$。
   接收方的接收窗口下界同样为序号 $s$$ \text{，窗口范围为} $$[s, (s + W_R - 1) \bmod 2^n]$。
2. **极限场景构造（极端确认丢失）**：
   - 发送方将当前发送窗口内的所有 $W_T$$ \text{个数据帧（序号为} $$s, s+1, \dots, s + W_T - 1$）全部发射完毕。
   - 极其幸运地，这 $W_T$ 个数据帧完好无损地跨越物理信道，全部准时到达接收方。
   - 接收方接收这 $W_T$$ \text{个数据帧后，将数据向上层递交，接收窗口随之向前全速滑动} $$W_T$ 格。
   - 此时，接收方的新接收窗口下界变为 $(s + W_T) \bmod 2^n$，其新窗口的序号覆盖区间在非回绕的实整数轴上展开为：
     $$ \text{新接收窗口区间} = [s + W_T, \; s + W_T + W_R - 1] $$
   - 接收方针对这 $W_T$ 个数据帧逐一发回了确认帧（ACK）。
   - **极端故障发生**：由于反向信道遭遇严重突发干扰，接收方发回的所有确认帧在传输途中**全部丢失**。
3. **二义性冲突推演**：
   - 发送方因为迟迟收不到任何 ACK，针对最早发出的帧 $s$ 的重传定时器发生超时。
   - 发送方判定帧 $s$$ \text{未能成功送达，于是触发重传机制，重新将帧} $$s$ 发送进物理信道。
   - 当这个重传的旧帧 $s$ 到达接收端时，接收方必须能够百分之百明确判断：“该帧是一个旧帧（冗余重传帧），应该丢弃并补发 ACK”，而**绝不能**误判为“这是一个跨越了序号模回绕之后的全新数据帧并将其接收存入”。
4. **数学不等式锁定**：
   - 接收方判断一个到达帧是否为“新帧”的唯一依据是：**该帧的序号是否落在当前的接收窗口区间内**。
   - 重传的旧帧 $s$$ \text{在经过一轮} $$2^n$$ \text{模回绕后，其在下一个周期对应的等价序号为} $$s + 2^n$。
   - 要保证重传的旧帧 $s$ 绝对不会被当作新一轮的帧接收，接收方当前的新接收窗口上界必须严格小于旧帧的下一个周期序号：
     $$s + W_T + W_R - 1 < s + 2^n$$
   - 不等式两边同时消去基序号 $s$：
     $$W_T + W_R - 1 < 2^n$$
   - 由于窗口尺寸均为正整数，上式等价于：
     $$W_T + W_R \le 2^n$$
   - 定理得证。若 $W_T + W_R > 2^n$$ \text{，新接收窗口的最右端将重叠覆盖旧帧序号} $$s$，接收方将把重传的旧数据当作新数据入队，造成严重的协议逻辑崩溃及数据损毁。

#### （2）停等协议特化推导
在停等协议中，发送窗口及接收窗口均固定为 1：
$$W_T = 1, \quad W_R = 1$$
代入通用约束不等式：
$$W_T + W_R = 1 + 1 = 2 \le 2^n \implies 2^n \ge 2 \implies n \ge 1$$
**结论**：停等协议至少需要 $n = 1$ 比特的帧序号（即采用 0 和 1 交替编号），即可完全杜绝数据帧及确认帧丢失引起的二义性。

#### （3）后退 N 帧（GBN）协议特化推导
GBN 协议接收端采用严格单调按序接收，绝不缓存任何乱序帧，因此接收窗口尺寸恒等于 1：
$$W_R = 1$$
将 $W_R = 1$ 代入通用约束定理：
$$W_T + 1 \le 2^n \implies W_T \le 2^n - 1$$
**物理意义直观反证**：
- 设 $n = 3$$ \text{，则序号空间为} $$0 \sim 7$$ \text{（共 8 个序号）。此时若强行令} $$W_T = 2^3 = 8$：
  1. 发送方发送 0~7 号帧。
  2. 接收方全部正确接收，期望序号变为下一轮的 0 号帧。
  3. 若所有 ACK 丢失，发送方超时重传上一轮的 0 号帧。
  4. 接收方当前正在期待 0 号帧，看到到达的帧序号正是 0，误以为发送方发来了全新的一帧 0，欣然接收！
  5. 结果：上层应用接收到了重复的数据块，协议崩溃。
- 因此 GBN 协议中发送窗口的最大值必须为 $2^n - 1$$ \text{。即} $$1 \le W_T \le 2^n - 1$。

#### （4）选择重传（SR）协议特化推导
在 SR 协议中，接收方引入了乱序接收缓存，$W_R > 1$。
- 根据通用约束：$W_T + W_R \le 2^n$。
- 为了最大化信道传输效能，避免发送方发得太快而接收方窗口太小造成人为拥塞，工程实践及协议标准（如 RFC 等）中通常令收发窗口大小对称：
  $$W_T = W_R$$
- 代入通用定理可得：
  $$W_T + W_T \le 2^n \implies 2 W_T \le 2^n \implies W_T \le 2^{n-1}, \quad W_R \le 2^{n-1}$$
**物理意义反证**：
- 设 $n = 3$$ \text{，序号空间为} $$0 \sim 7$$ \text{（模为 8）。若设置} $$W_T = W_R = 5 > 2^{3-1} = 4$：
  1. 发送方发射帧 0, 1, 2, 3, 4。
  2. 接收方接收这 5 个帧，窗口由 $[0, 4]$$ \text{顺次滑动至} $$[5, 1]$（即包含序号 5, 6, 7, 0, 1，共 5 个槽位）。
  3. 接收端发回的 ACK0~ACK4 全部在网络中丢失。
  4. 发送端针对帧 0 定时器超时，重传旧帧 0。
  5. 接收端查看自己的当前窗口 $[5, 1]$，惊愕地发现序号 0 赫然在列！接收端判定其为新数据，存入缓冲区。
- 只有满足 $W_T \le 2^{n-1}$$ \text{且} $$W_R \le 2^{n-1}$，接收窗口滑动后的新范围及先前发送未确认的旧序号区间才能够完全互斥，彻底杜绝混叠。

### 4. 信道利用率及吞吐率数学模型

信道利用率（Channel Utilization）及吞吐率（Throughput）是衡量网络传输效能的基石指标，也是 408 考研计算大题的最主要命题点。

#### （1）物理时延要素精细化定义
设信道的数据传输速率（带宽）为 $C$（单位：bps 或 b/s）：
1. **数据帧发送时延（Transmission Delay）**：
   $$T_D = \frac{L_{\text{data}}}{C}$$
   其中 $L_{\text{data}}$ 为数据帧的二进制总比特长度（包含首部、载荷及尾部校检码）。
2. **确认帧发送时延**：
   $$T_A = \frac{L_{\text{ack}}}{C}$$
   其中 $L_{\text{ack}}$$ \text{为控制确认帧的二进制比特长度。若题目明确说明“忽略确认帧长度/传输延时”，则取} $$T_A = 0$$ \text{；若题目采用“双向捎带确认”，则确认信息随反向数据帧一并发送，} $$T_A = T_D$。
3. **单向物理传播时延（Propagation Delay）**：
   $$\tau = \frac{D}{V}$$
   其中 $D$$ \text{为传输介质物理距离（单位：m 或 km），} $$V$$ \text{为电磁波在介质中的传播速率（光纤中约为} $$2.0 \times 10^8\text{ m/s}$$ \text{，真空中或无线电卫星链路约为} $$3.0 \times 10^8\text{ m/s}$）。
4. **往返传播时延（Round-Trip Time, RTT）**：
   $$RTT = 2\tau$$
5. **处理时延（Processing Delay）** $T_P$$ \text{及 **排队时延（Queuing Delay）**} $$T_Q$$ \text{：考研大题通常假设节点处理速度极快且无拥塞排队，即} $$T_P \approx 0, T_Q \approx 0$。

#### （2）通信基本周期（Transmission Cycle）
一个完整通信基本周期定义为：**发送端从开始发送第一个比特起，到发送端完全接收到针对该数据帧的确认帧为止所需的总物理时间**。
$$T_{\text{cycle}} = T_D + \tau + T_P + T_A + \tau = T_D + RTT + T_A$$

```
发送端 ──┬──[ 发送数据帧 TD ]───────────────┐
         │                                   │ 传播时延 τ
         ▼                                   ▼
接收端 ──────────────────────[ 接收数据帧 ]──┬──[ 发送确认帧 TA ]──────┐
                                             │                         │ 传播时延 τ
                                             ▼                         ▼
发送端 ──────────────────────────────────────────────────[ 接收确认帧 ]
         ├──────────────────── 一个完整发送周期 Tcycle ────────────────┤
```

#### （3）停等协议信道利用率公式
停等协议在每一个周期内只能且仅能发送 1 个数据帧：
$$ \text{U_{\text{SW}} = \frac{\text{发送端忙于发送有效数据的净时间}}{\text{整个通信周期时间}} = \frac{T_D}{T_D + RTT + T_A} = \frac{T_D}{T_D + 2\tau + T_A}} $$

#### （4）连续 ARQ 协议（GBN / SR）信道利用率公式
连续 ARQ 协议允许发送端在收到前一帧的确认之前，连续发射至多 $W_T$ 个数据帧：
- 在单个通信周期 $T_{\text{cycle}}$$ \text{内，发送端用于发射数据帧的累计总时间为} $$W_T \times T_D$。
- **欠饱和状态（$W_T \cdot T_D < T_{\text{cycle}}$）**：发送窗口内的数据全部发完后，确认帧尚未飞回，发送端被迫暂停发送进入空闲等待。此时：
  $$U = \frac{W_T \times T_D}{T_D + RTT + T_A}$$
- **过饱和/流水线全满状态（$W_T \cdot T_D \ge T_{\text{cycle}}$$ \text{）**：发送端发完第} $$W_T$ 帧之前，针对第 1 帧的 ACK 已经飞回，发送窗口立即滑动，发送端始终处于发射状态，信道无任何空闲气泡，信道利用率达到极限值 100%：
  $$U = 100\% = 1.0$$
- **通用数学闭式表达**：
  $$U = \min\left(1, \; \frac{W_T \times T_D}{T_D + RTT + T_A}\right)$$

#### （5）实际数据传输吞吐率（Throughput）
吞吐率是指单位时间内信道上成功传送的有效数据比特数（扣除协议空闲）：
$$\text{Throughput} = U \times C = \min\left(C, \; \frac{W_T \times L_{\text{data}}}{T_D + RTT + T_A}\right)$$

#### （6）信道利用率达到 100% 的最小发送窗口尺寸
若要使连续流水线不发生断流，必须保证在第一个帧的 ACK 返回前，发送端能够不间断地持续发送数据帧：
$$W_T \times T_D \ge T_D + RTT + T_A \implies W_T \ge \frac{T_D + RTT + T_A}{T_D} = 1 + \frac{RTT + T_A}{T_D}$$
由于窗口尺寸必须为正整数，故最小发送窗口为向上取整：
$$W_{\min} = \left\lceil \frac{T_D + RTT + T_A}{T_D} \right\rceil = 1 + \left\lceil \frac{RTT + T_A}{T_D} \right\rceil$$

#### （7）时延带宽积及管道容量模型
- **时延带宽积（BDP, Bandwidth-Delay Product）**：
  $$\text{BDP} = C \times RTT = C \times 2\tau$$
  BDP 的物理本质是：**当数据充满整个双向物理链路管道时，信道中所能容纳的飞行中（In-flight）最大比特总数**。
- 若将 BDP 折算为数据帧帧数（管道容量）：
  $$N_{\text{pipe}} = \frac{\text{BDP}}{L_{\text{data}}} = \frac{C \times RTT}{L_{\text{data}}} = \frac{RTT}{T_D}$$
- 当忽略确认帧时延（$T_A \approx 0$$ \text{）时，满载窗口尺寸恰好等于} $$1 + N_{\text{pipe}}$。这体现了网络链路及滑动窗口尺寸在物理容量层面的统一。

### 5. 关键机制及易混概念对比辨析

为了在解答 408 概念判断题及综合设计题时不出现混淆，特对核心机制进行横向对比剖析。

#### （1）累积确认机制 vs 逐帧独立确认机制
- **累积确认（Cumulative ACK，典型代表：GBN 协议、TCP 协议默认机制）**：
  - ACK 报文携带的确认号 $y$$ \text{表示“序号小于} $$y$$ \text{的所有数据帧都已正确接收，当前期待接收序号为} $$y$ 的帧”。
  - **抗信道丢包能力**：如果 ACK1 丢失，但 ACK2 顺利到达发送端，则发送端直接推知帧 0 和帧 1 均已成功交付，ACK1 的丢失被完全平蔽，无需重传。
  - **副作用**：无法指示中间个别帧的丢失。一旦中间某帧掉损，后续所有到达的优质帧均无法被向上递交，引发无差别全量重传。
- **逐帧独立确认（Individual ACK / Selective ACK，典型代表：SR 协议、TCP SACK 选项）**：
  - ACK 报文携带的确认号 $y$$ \text{仅仅表示“序号等于} $$y$ 的那个特定帧已经被正确接收”。
  - **抗信道丢包能力**：ACK 报文之间彼此孤立，互不连带。若 ACK1 丢失，哪怕后续的 ACK2、ACK3 均到达，发送端依然判定帧 1 超时未被确认，从而精准重传帧 1。
  - **开销**：每个帧都需要精准反馈，信道信令密度更高。

#### （2）单一定时器机制 vs 逐帧独立多定时器机制
- **GBN 采用单一定时器**：发送端只需维护一个硬件或逻辑定时器，该定时器永远绑定在发送窗口中**最早未被确认的帧（$SendBase$$ \text{）**上。只要收到新 ACK 推进了窗口下界，就重置定时器。开销极低，算法复杂度为} $$O(1)$。
- **SR 采用独立多定时器**：发送端必须为窗口内**处于在途未决状态的每一个数据帧分别启动独立的定时器**。一旦某个特定的定时器到期，仅将该定时器所绑定的数据帧塞入重发队列。实现复杂度及系统调度开销较高。

#### （3）发送缓冲区 vs 接收缓冲区开销
- **停等协议**：发送方仅需缓冲 1 个帧，接收方无需缓存（随到随交）。
- **GBN 协议**：发送方需要开辟容纳 $W_T$ 个帧的发送缓冲区，以备超时重发；接收方窗口为 1，完全不需要接收缓冲区，失序帧直接丢弃。
- **SR 协议**：发送方必须具备 $W_T$$ \text{个帧的发送缓冲区；接收方必须具备} $$W_R$ 个帧的接收缓冲区，用于吸收和暂存失序到达的帧，直到空洞被填补后按序提交。

#### （4）独立控制帧确认 vs 捎带确认（Piggybacking）
- **独立控制帧确认**：接收端每收到数据，单独组装一个仅含头部的短控制帧（ACK 帧）返回。优点是反应迅捷，缺点是首部开销占比大、消耗信道分组处理率。
- **捎带确认**：在双向均有数据传输的对称全双工链路上，接收端将确认号写入本端即将发出的反向数据帧首部的“确认序号字段”中。显著提高链路总效率，但若反向没有数据待发，接收端必须设置捎带延迟定时器，若超时仍无反向数据，则必须强行退化发送独立 ACK 帧，防止对端超时。

#### （5）三大 ARQ 协议多维深度综合对照表

| 比较维度 | 停等协议 (Stop-and-Wait) | 后退 N 帧协议 (GBN) | 选择重传协议 (SR) |
| :--- | :--- | :--- | :--- |
| **发送窗口尺寸 $W_T$** | $W_T = 1$ | $1 < W_T \le 2^n - 1$ | $1 < W_T \le 2^{n-1}$（常用） |
| **接收窗口尺寸 $W_R$** | $W_R = 1$ | $W_R = 1$ | $1 < W_R \le 2^{n-1}$（常用） |
| **通用窗口关系约束** | $W_T + W_R \le 2^n$ | $W_T + W_R \le 2^n$ | $W_T + W_R \le 2^n$ |
| **最小帧序号位数 $n$$ \text{** | 1 比特（0 和 1） |} $$\ge \lceil \log_2(W_T + 1) \rceil$ | $\ge \lceil \log_2(W_T + W_R) \rceil$ |
| **确认方式** | 逐帧确认（单帧） | 累积确认（期望下一帧） | 独立确认/选择确认 |
| **重传定时器数量** | 1 个 | 1 个（绑定最早未确认帧） | $W_T$ 个（每帧独立） |
| **接收端乱序处理** | 无法接收乱序帧 | 丢弃所有乱序帧，不缓存 | 缓存有效窗口内的乱序帧 |
| **重传策略** | 超时重传当前单个帧 | 超时后退重传窗口内所有帧 | 仅重传超时单个出错帧 |
| **硬件/存储开销** | 极低 | 发送端需缓存 $W_T$ 帧 | 收发双方均需开辟大缓存 |
| **恶劣信道适应能力** | 吞吐极低但不会拥塞 | 易发生重传风暴，效能暴跌 | 效能稳健，重传代价最小 |
| **最大信道利用率** | $\frac{T_D}{T_D + RTT + T_A}$ | $\min\left(1, \frac{W_T \cdot T_D}{T_D + RTT + T_A}\right)$ | $\min\left(1, \frac{W_T \cdot T_D}{T_D + RTT + T_A}\right)$ |

## 三、 近十年真题精讲（2016~2025）

### 1. 2025 年统考 408 真题第 47 题（综合解答大题 · 9分）

#### 【题目题干】
某工程部网络拓扑结构及相关参数如下图所示。
- 卫星轨道高度为 $36000\text{ km}$$ \text{，电磁波在真空中的传播速度为} $$300000\text{ km/s}$。
- TR1 和 TR2 为全双工调制解调设备，卫星链路为路由器 R1 和 R2 之间提供对称全双工物理信号，每个方向的数据传输速率均为 $200\text{ kbps}$。
- 工程部网络内部通过交换机 S1 连接三个子网：作业区子网、生活区子网、管理区子网。主机 H 属于管理区子网，其 IP 地址已配置为 `10.10.10.33/26`。

```
[工程部内部局域网]
 ├── 作业区子网
 ├── 生活区子网
 └── 管理区子网 ── S1 ── 主机 H (10.10.10.33/26)
        │
       [R1] ── TR1 <====== 对称全双工卫星链路 (200 kbps, 36000 km) ======> TR2 ── [R2] ── [Internet] ── [总部服务器]
```

请回答下列问题：
1. 忽略卫星信号中继以及 TR1、TR2 的调制解调开销，则 R1 到 R2 之间的卫星链路单向传播时延是多少？主机 H 向总部服务器传输数据时可达到的最大吞吐量是多少？若忽略各层协议首部开销以及以太网的传播时延，则主机 H 向总部服务器上传一个 $4000\text{ B}$ 的文件，至少需要多长时间？
2. 基于后退 N 帧（GBN）机制为卫星链路设计单向可靠链路层协议 SLP，支持由 R1 向 R2 发送数据。SLP 数据帧长度固定为 $1500\text{ B}$$ \text{，忽略 ACK 帧长度（即} $$T_A = 0$$ \text{）。要求 SLP 协议的单向信道利用率不低于} $$80\%$，则发送窗口大小至少为多少？SLP 帧序号字段至少需要多少比特？
3. 总部给工程部分配的 IP 地址空间为 `10.10.10.0/24`，要求划分为 3 个子网：管理区子网、生活区子网、作业区子网。已知管理区子网内某主机 IP 为 `10.10.10.33/26`。若生活区子网要求容纳不少于 120 个可分配 IP 地址，作业区子网和管理区子网各要求容纳不少于 60 个可分配 IP 地址。请问作业区子网和生活区子网的网络地址各是多少？

#### 【逐步推导及详尽解析】

**第一问解析**：
1. **卫星链路单向传播时延计算**：
   - 卫星通信为“地面站 R1 $\to$$ \text{通信卫星} $$\to$ 地面站 R2”的双段物理跳跃结构。
   - 地面站到同步轨道卫星距离 $D = 36000\text{ km}$$ \text{，电磁波在真空中速度} $$V = 300000\text{ km/s}$。
   - 因此信号从地面站 R1 发射至卫星，再由卫星转发至地面站 R2 的总传播距离为：
     $$D_{\text{total}} = 2 \times D = 2 \times 36000\text{ km} = 72000\text{ km}$$
   - 单向物理传播时延 $\tau$ 为：
     $$\tau = \frac{D_{\text{total}}}{V} = \frac{72000\text{ km}}{300000\text{ km/s}} = 0.24\text{ s} = 240\text{ ms}$$
2. **最大吞吐量分析**：
   - 数据通路上各段链路中，以太网通常为 $100\text{ Mbps}$$ \text{或更大，而卫星链路带宽仅为} $$200\text{ kbps}$。
   - 整个端到端通信路径的吞吐量严格受限于木桶的最短板（瓶颈链路带宽）。
   - 因此，主机 H 向总部服务器传输数据时所能达到的最大吞吐量为卫星链路带宽：$200\text{ kbps}$。
3. **上传 $4000\text{ B}$ 文件所需最短时间计算**：
   - 根据分组交换理论及时延分析，在忽略以太网传播时延、排队时延及各层报文头部开销时，文件传输总时延由**卫星链路发送时延**及**卫星链路传播时延**构成。
   - 文件大小 $L = 4000\text{ B} = 4000 \times 8\text{ bit} = 32000\text{ bit}$。
   - 发送时延（传输时延）为：
     $$T_{\text{trans}} = \frac{L}{C} = \frac{32000\text{ bit}}{200 \times 10^3\text{ bps}} = 0.16\text{ s} = 160\text{ ms}$$
   - 传播时延已经求出：$\tau = 0.24\text{ s}$。
   - 上传所需的最短总时间为：
     $$T_{\text{total}} = T_{\text{trans}} + \tau = 0.16\text{ s} + 0.24\text{ s} = 0.40\text{ s} = 400\text{ ms}$$

**第二问解析**：
1. **SLP 单帧发送时延计算**：
   - 数据帧长 $L_{\text{data}} = 1500\text{ B} = 1500 \times 8\text{ bit} = 12000\text{ bit}$。
   - 卫星链路带宽 $C = 200\text{ kbps} = 200000\text{ bps}$。
   - 单个数据帧的发送时延 $T_D$ 为：
     $$T_D = \frac{12000\text{ bit}}{200000\text{ bps}} = 0.06\text{ s} = 60\text{ ms}$$
2. **通信往返时间及总周期计算**：
   - 往返传播时延 $RTT = 2 \times \tau = 2 \times 0.24\text{ s} = 0.48\text{ s} = 480\text{ ms}$。
   - 题目给定“忽略 ACK 帧长度”，故确认帧发送时延 $T_A = 0$。
   - 发送一个帧到收到其确认的基本周期为：
     $$T_{\text{cycle}} = T_D + RTT + T_A = 0.06\text{ s} + 0.48\text{ s} + 0 = 0.54\text{ s}$$
3. **根据信道利用率不等式求解发送窗口 $W_T$**：
   - GBN 协议信道利用率计算公式为：
     $$U = \frac{W_T \times T_D}{T_{\text{cycle}}} = \frac{W_T \times 0.06}{0.54} = \frac{W_T}{9}$$
   - 题目要求单向信道利用率不低于 $80\%$$ \text{（即} $$U \ge 0.8$）：
     $$\frac{W_T}{9} \ge 0.8 \implies W_T \ge 9 \times 0.8 = 7.2$$
   - 由于发送窗口大小 $W_T$ 必须为正整数，向上取整得到：
     $$W_T \ge \lceil 7.2 \rceil = 8$$
   - 因此，发送窗口至少为 **8**。
4. **求解帧序号比特数 $k$**：
   - 在后退 N 帧（GBN）协议中，发送窗口尺寸 $W_T$$ \text{及帧序号比特数} $$k$ 必须满足：
     $$W_T \le 2^k - 1 \implies 2^k \ge W_T + 1$$
   - 将最小发送窗口 $W_T = 8$ 代入上式：
     $$2^k \ge 8 + 1 = 9$$
   - 当 $k = 3$$ \text{时，} $$2^3 = 8 < 9$（不满足要求）；
   - 当 $k = 4$$ \text{时，} $$2^4 = 16 \ge 9$（满足要求）。
   - 因此，SLP 帧序号字段至少需要 **4 比特**。

**第三问解析**：
1. **各子网地址容量需求分析**：
   - 给定总地址块为 `10.10.10.0/24`，共有 $2^{32-24} = 256$ 个 IP 地址。
   - **生活区子网**：可分配 IP 地址不少于 120 个。设主机位为 $h_1$$ \text{，可分配 IP 数量为} $$2^{h_1} - 2$（减去网络地址和广播地址）。
     $$2^{h_1} - 2 \ge 120 \implies 2^{h_1} \ge 122 \implies h_1 \ge 7$$
     主机位取 7 位，网络前缀长度为 $32 - 7 = 25$$ \text{位（`/25`），地址块大小为} $$2^7 = 128$ 个地址。
   - **作业区子网**：可分配 IP 地址不少于 60 个。设主机位为 $h_2$：
     $$2^{h_2} - 2 \ge 60 \implies 2^{h_2} \ge 62 \implies h_2 \ge 6$$
     主机位取 6 位，网络前缀长度为 $32 - 6 = 26$$ \text{位（`/26`），地址块大小为} $$2^6 = 64$ 个地址。
   - **管理区子网**：主机 H 的 IP 为 `10.10.10.33/26`，子网掩码为 26 位，其所在地址块大小为 64。
2. **管理区子网空间定位**：
   - 掩码 `/26` 将 256 个地址均匀分为 4 个块，步长为 64：
     - 块 0：`10.10.10.0 ~ 10.10.10.63`（网络地址 `10.10.10.0/26`）
     - 块 1：`10.10.10.64 ~ 10.10.10.127`（网络地址 `10.10.10.64/26`）
     - 块 2：`10.10.10.128 ~ 10.10.10.191`（网络地址 `10.10.10.128/26`）
     - 块 3：`10.10.10.192 ~ 10.10.10.255`（网络地址 `10.10.10.192/26`）
   - 因为主机 H 的 IP 为 `10.10.10.33`，位于区间 $[0, 63]$ 内，所以**管理区子网的网络地址必然是 `10.10.10.0/26`**。
3. **分配生活区和作业区子网**：
   - 剩余可用空间为 `10.10.10.64 ~ 10.10.10.255`（连续 192 个地址）。
   - **生活区子网**需要连续的 128 个地址块（`/25`），其在 `10.10.10.0/24` 中合法的 128 边界只能是前半段（0~127）或后半段（128~255）。
   - 前半段已被管理区子网（0~63）占用，因此生活区子网只能分配后半段：
     - **生活区子网地址为**：`10.10.10.128/25`（包含地址 `10.10.10.128 ~ 10.10.10.255`）。
   - 此时中间空闲出来的地址块恰好是 `10.10.10.64 ~ 10.10.10.127`（共 64 个地址），正好满足**作业区子网**（`/26`）的需求：
     - **作业区子网地址为**：`10.10.10.64/26`。

#### 【标准答案】
1. 卫星链路单向传播时延是 **0.24 s**（或 **240 ms**）；主机 H 向总部服务器传输数据时可达到的最大吞吐量是 **200 kbps**；上传该文件至少需要 **0.4 s**（或 **400 ms**）。
2. 发送窗口至少为 **8**；SLP 帧序号至少需要 **4 比特**。

### 3. 2023 年统考 408 真题第 35 题（单项选择题 · 2分）

#### 【题目题干】
假设通过同一信道，数据链路层分别采用停等协议、GBN 协议和 SR 协议（发送窗口和接收窗口相等）传输数据，三个协议数据帧长相同，忽略确认帧长度，帧序号位数为 3 比特。若对应三个协议的发送方最大信道利用率分别是 $U_1$、$U_2$$ \text{和} $$U_3$$ \text{，则} $$U_1$、$U_2$$ \text{和} $$U_3$ 满足的关系是（ ）。

A. $U_1 \le U_2 \le U_3$  
B. $U_1 \le U_3 \le U_2$  
C. $U_2 \le U_3 \le U_1$  
D. $U_3 \le U_2 \le U_1$  

#### 【逐步推导及详尽解析】
1. **信道利用率通式对比**：
   题目给出同一信道、数据帧长相同（$T_D$$ \text{相同）、忽略确认帧长（} $$T_A = 0$$ \text{）、传播时延相同（} $$RTT$ 相同）。
   对于发送窗口为 $W_T$ 的 ARQ 协议，其信道利用率满足：
   $$U = \min\left(1, \; \frac{W_T \times T_D}{T_D + RTT}\right)$$
   因为 $\frac{T_D}{T_D + RTT}$$ \text{为固定常数，所以在未达到 100% 满负荷前，信道利用率} $$U$$ \text{随最大发送窗口尺寸} $$W_T$ 呈严格单调递增关系；即使信道饱和，较大窗口对应的利用率上限也必定大于等于较小窗口。
2. **计算三个协议的最大发送窗口尺寸**：
   - 题目给定帧序号位数为 $n = 3$$ \text{比特，序号模空间大小为} $$2^3 = 8$。
   - **停等协议**：发送窗口大小恒为 $W_1 = 1$。
   - **GBN 协议**：接收窗口 $W_R = 1$$ \text{。发送窗口尺寸满足} $$1 \le W_T \le 2^n - 1$。
     因此 GBN 协议的最大发送窗口为：
     $$W_2 = 2^3 - 1 = 7$$
   - **SR 协议**：题目明确“发送窗口和接收窗口相等”，即 $W_T = W_R$$ \text{。根据无二义性约束条件} $$W_T + W_R \le 2^n$：
     $$2 W_T \le 2^3 = 8 \implies W_T \le 4$$
     因此 SR 协议的最大发送窗口为：
     $$W_3 = 2^{3-1} = 4$$
3. **横向比较窗口大小及利用率**：
   - 三者的最大发送窗口尺寸关系为：
     $$W_1 (1) < W_3 (4) < W_2 (7)$$
   - 因此其对应的最大信道利用率必然满足：
     $$U_1 \le U_3 \le U_2$$

#### 【正确答案】
**B**

### 4. 2020 年统考 408 真题第 36 题（单项选择题 · 2分）

#### 【题目题干】
假设主机甲采用停等协议向主机乙发送数据帧，数据帧长和确认帧长均为 $1000\text{ B}$$ \text{。数据传输速率是} $$10\text{ kbps}$$ \text{，单向传播延时是} $$200\text{ ms}$。则甲的最大信道利用率是（ ）。

A. 80%  
B. 66.7%

2. **确认帧发送时延计算**：
   题目特别强调“确认帧长亦为 $1000\text{ B}$”，故确认帧发送时延不可忽略：
   $$T_A = \frac{8000\text{ bit}}{10000\text{ bps}} = 0.8\text{ s} = 800\text{ ms}$$
3. **单向传播时延及周期计算**：
   单向传播延时 $\tau = 200\text{ ms}$。

   $$T_{\text{cycle}} = T_D + \tau + T_A + \tau = 800\text{ ms} + 200\text{ ms} + 800\text{ ms} + 200\text{ ms} = 2000\text{ ms}$$
4. **计算信道利用率**：
   $$U = \frac{T_D}{T_{\text{cycle}}} \times 100\% = \frac{800\text{ ms}}{2000\text{ ms}} \times 100\% = 40\%$$

### 5. 2019 年统考 408 真题第 35 题（单项选择题 · 2分）

对于滑动窗口协议，如果分组序号采用 3 比特编号，发送窗口大小为 5，则接收窗口最大是（ ）。

A. 2  
B. 3  
C. 4  
D. 5  

#### 【逐步推导及详尽解析】
1. **应用滑动窗口根本性约束定理**：
   在任意滑动窗口协议中，设序号位数为 $n$$ \text{比特，则序号空间总容量为} $$2^n$。
   为保证接收端在“所有确认帧全部在网络中丢失、发送端全窗口超时重发”的极端恶劣情况下，不把重传的旧帧混淆误认为新一轮序号的新数据，必须严格满足窗口尺寸之和不得超越序号空间容量：
   $$W_T + W_R \le 2^n$$
2. **代入数值计算**：
   - 题目给定序号采用 $n = 3$$ \text{比特编号，故序号空间容量} $$2^n = 2^3 = 8$。
   - 发送窗口大小 $W_T = 5$。
   - 代入不等式：
     $$5 + W_R \le 8 \implies W_R \le 8 - 5 = 3$$
3. **结论**：接收窗口的最大取值为 **3**。若接收窗口大于 3（例如取 4），接收窗口推进后右边缘将覆盖下一轮的序号，导致重传帧 0 落在新窗口中产生二义性错误。

**B**

  - 序号 1 对应甲方发射的第二个帧 $S_{1,0}$；
  - 序号 2 对应甲方发射的第三个帧 $S_{2,0}$。
- 因此，甲方可百分之百断定乙方正确接收了 **3** 个数据帧，具体为 **$S_{0,0}, S_{1,0}, S_{2,0}$**。

**第二问解析**：
1. **计算甲方发送窗口最大尺寸**：
   序号字段为 3 比特，序号空间为模 $2^3 = 8$$ \text{（序号为} $$0 \sim 7$）。
   后退 N 帧协议中，最大发送窗口尺寸为：
   $$W_T = 2^n - 1 = 2^3 - 1 = 7$$
2. **分析 $t_1$ 时刻处于未确认状态的帧**：
   - 甲方迄今为止一共发送了 5 个帧：$S_{0,0}, S_{1,0}, S_{2,0}, S_{3,0}, S_{4,1}$。
   - 乙方返回的最新确认号为 3（表示帧 0, 1, 2 均已被确认）。
   - 因此，甲方发送窗口中已发出但尚未得到确认的数据帧只有 **2 个**：即序号为 3 的帧（$S_{3,0}$$ \text{）和序号为 4 的帧（} $$S_{4,1}$）。
3. **计算最多还可以发送的新帧数量**：
   - 窗口总容量为 7，已占用 2 个槽位。
   - 故在不超时且无新确认返回的前提下，甲方还允许连续发射的新数据帧数量为：
     $$ \text{可用额度} = W_T - \text{已发未确认帧数} = 7 - 2 = 5 \text{ 个} $$
4. **确定这 5 个帧的发送序号及确认序号（$S_{x,y}$）**：
   - **发送序号 $x$**：甲方此前最新发出的帧序号为 4，因此接下来连续发送的 5 个新帧，其序号按模 8 顺序推进：**5、6、7、0、1**。
   - **确认序号 $y$$ \text{**：甲方在} $$t_1$$ \text{之前收到的乙方最新数据帧为} $$R_{1,3}$$ \text{（乙方发送序号为 1）。这说明甲方已经按序正确接收了乙方的 0 号帧和 1 号帧。因此甲方接下来期望接收乙方的下一帧序号为 **2**。甲方采用捎带确认，其向乙方发射的所有帧中的确认号字段} $$y$ 均应填入 **2**。
   - 顺次排开这 5 个帧：
     - 第 1 个帧为 **$S_{5,2}$**
     - 第 2 个帧为 $S_{6,2}$
     - 第 3 个帧为 $S_{7,2}$
     - 第 4 个帧为 $S_{0,2}$
     - 第 5 个（即最后一个）帧为 **$S_{1,2}$**

**第三问解析**：
1. **分析图 (b) 在 $t_1$ 时刻的状态**：
   - 甲方在 $t_0 \sim t_1$$ \text{期间陆续发送了：} $$S_{0,0}, S_{1,0}, S_{2,0}, S_{3,2}, S_{4,2}$。
   - 甲方收到了乙方的 $R_{0,1}, R_{1,2}, R_{2,2}$。
   - 注意乙方最新发回的帧 $R_{2,2}$$ \text{，其确认号} $$y = 2$$ \text{。这表明乙方仅确认了甲方的 0 号和 1 号帧（} $$S_{0,0}, S_{1,0}$$ \text{），而甲方的 2 号帧（} $$S_{2,0}$）尚未得到确认！
   - 随后，甲方针对数据帧 **$S_{2,0}$ 的重传定时器发生超时**！
2. **应用 GBN 超时重发规则确定重发帧数**：
   - 在 GBN 协议中，一旦某帧（2 号帧）超时，发送方必须后退并**重传从该帧开始直到当前窗口内已发出的所有未确认帧**。
   - 甲方此前在 2 号帧之后已经发出了 3 号帧（$S_{3,2}$$ \text{）和 4 号帧（} $$S_{4,2}$）。
   - 因此甲方必须重传序号为 2、3、4 的全部数据帧，共需重发 **3 个数据帧**。
3. **确定重发的首个数据帧格式（$S_{x,y}$）**：
   - 重发的第一帧的发送序号自然是 $x = 2$。
   - 确认号 $y$$ \text{：甲方在} $$t_1$$ \text{之前收到的乙方最后一个数据帧是} $$R_{2,2}$，该帧的发送序号为 2。这说明甲方已经正确接收了乙方序号为 0、1、2 的数据帧，甲方当前殷切期望接收乙方的下一个帧是序号 3。
   - 因此甲方重发时捎带的确认号必须更新为 $y = 3$。
   - 重发的第一个数据帧为 **$S_{2,3}$**。

**第四问解析**：
1. **单帧发送时延计算**：
   帧长 $L = 1000\text{ B} = 8000\text{ bit}$$ \text{，带宽} $$C = 100\text{ Mbps} = 10^8\text{ bps}$。
   $$T_d = \frac{8000\text{ bit}}{10^8\text{ bps}} = 8 \times 10^{-5}\text{ s} = 0.08\text{ ms}$$
2. **确认帧时延及单周期总时延计算**：
   题目特别说明“双方始终采用捎带确认，帧长均为 $1000\text{ B}$”。
   因此反向捎带确认帧本身也是一个完整数据帧，其发送时延 $T_a = T_d = 0.08\text{ ms}$。
   往返时延 $RTT = 0.96\text{ ms}$。
   发送一帧到收到确认的基本通信周期为：
   $$T_{\text{cycle}} = T_d + RTT + T_a = 0.08\text{ ms} + 0.96\text{ ms} + 0.08\text{ ms} = 1.12\text{ ms}$$
3. **计算最大信道利用率**：
   GBN 协议最大发送窗口尺寸为 $W_{\max} = 7$。
   在单个周期 $T_{\text{cycle}}$ 内，甲方最多能够持续发送 7 个数据帧，有效传输数据的时间为：
   $$T_{\text{busy}} = W_{\max} \times T_d = 7 \times 0.08\text{ ms} = 0.56\text{ ms}$$
   由于 $T_{\text{busy}} = 0.56\text{ ms} < T_{\text{cycle}} = 1.12\text{ ms}$，信道未饱和，利用率为：
   $$U = \frac{T_{\text{busy}}}{T_{\text{cycle}}} \times 100\% = \frac{0.56\text{ ms}}{1.12\text{ ms}} \times 100\% = 50\%$$

#### 【标准答案】
1. 甲方可以断定乙方已正确接收的数据帧数是 **3** 个，分别是 **$S_{0,0}, S_{1,0}, S_{2,0}$**。
2. 最多还可以发送 **5** 个数据帧。其中第一个帧是 **$S_{5,2}$$ \text{**，最后一个帧是 **} $$S_{1,2}$**。
3. 甲方需要重发 **3** 个数据帧。重发的第一个帧是 **$S_{2,3}$**。
4. 甲方可以达到的最大信道利用率是 **50%**。

### 8. 附录：历年统考经典真题拓展精选（2009~2014）

为了给考生提供全景式的命题演化视野，特精选近十年之前的 4 道经典真题作深度点拨：

#### 【2014 年第 36 题】
- **题干**：主机甲向主机乙使用后退 N 帧协议（GBN）传输数据，甲的发送窗口尺寸为 1000，数据帧长为 1000 字节，信道带宽为 100 Mbps，乙每收到一个数据帧立即利用一个短帧（忽略其传输延迟）进行确认，若甲乙之间的单向传播延迟是 50 ms，则甲可以达到的最大平均数据传输速率约为（ ）。  
  A. 10 Mbps \quad B. 20 Mbps \quad C. 80 Mbps \quad D. 100 Mbps
- **精析**：
  $T_D = \frac{1000 \times 8}{100 \times 10^6} = 0.08\text{ ms}$$ \text{。往返时延} $$RTT = 2 \times 50\text{ ms} = 100\text{ ms}$。
  周期 $T_{\text{cycle}} = T_D + RTT = 100.08\text{ ms} \approx 100\text{ ms} = 0.1\text{ s}$。
  发送窗口 $W = 1000$$ \text{。在一个往返周期内，甲最多可发射数据量为} $$1000 \times 1000\text{ B} = 1\text{ MB} = 8\text{ Mb}$。
  受滑动窗口制约的数据率上限为 $\frac{8\text{ Mb}}{0.1\text{ s}} = 80\text{ Mbps}$。
  物理信道带宽为 $100\text{ Mbps}$$ \text{。实际速率取两者的瓶颈极小值：} $$\min(80, 100) = 80\text{ Mbps}$。
- **答案**：**C**

#### 【2012 年第 36 题】
- **题干**：两台主机之间的数据链路层采用后退 N 帧协议（GBN）传输数据，数据传输速率为 16 kbps，单向传播时延为 270 ms，数据帧长度范围是 128~512 字节，接收方总是以同数据帧等长的短帧进行确认。为使信道利用率达到最高，帧序号的比特数至少为（ ）。  
  A. 5 \quad B. 4 \quad C. 3 \quad D. 2
- **精析**：
  要使信道利用率达到最高（即 100%），所需的窗口尺寸必须能够填满整个往返周期管道。为了求出最苛刻情况下的最小帧序号位数，应按**最短帧长**计算（帧长越短，单帧发送时延越小，一个 RTT 周期内需要容纳的帧数越多，对窗口尺寸要求越高）。
  取最短帧长 $L = 128\text{ B} = 1024\text{ bit}$。
  $T_D = T_A = \frac{1024\text{ bit}}{16000\text{ bps}} = 0.064\text{ s} = 64\text{ ms}$。
  $RTT = 2 \times 270\text{ ms} = 540\text{ ms}$。
  通信周期 $T = T_D + RTT + T_A = 64 + 540 + 64 = 668\text{ ms}$。
  流水线满负荷所需的窗口尺寸 $W \ge \frac{T}{T_D} = \frac{668}{64} \approx 10.4375 \implies W \ge 11$。
  在 GBN 中，$W \le 2^n - 1 \implies 2^n \ge W + 1 \ge 11 + 1 = 12$。
  解得最小整数 $n = 4$$ \text{（因为} $$2^3 = 8 < 12, 2^4 = 16 \ge 12$）。
- **答案**：**B**

#### 【2011 年第 35 题】
- **题干**：数据链路层采用选择重传协议（SR）传输数据，发送方已发送了 0～3 号数据帧，现已收到 1 号帧的确认，而 0、2 号帧依次超时，则此时需要重传的帧数是（ ）。  
  A. 1 \quad B. 2 \quad C. 3 \quad D. 4
- **精析**：
  选择重传（SR）协议采用逐帧独立确认及独立定时器机制。接收方收到 1 号帧并不代表 0 号帧已接收（无累积确认效应）。发送端针对 0 号和 2 号帧的定时器发生超时，发送端只重传超时的帧，即只重传 0 号和 2 号共 2 个帧；3 号帧未超时，无需重传。
- **答案**：**B**

#### 【2009 年第 35 题】
- **题干**：数据链路层采用后退 N 帧（GBN）协议，发送方已经发送了编号为 0~7 的帧。当计时器超时时，若发送方只收到 0、2、3 号帧的确认，则发送方需要重发的帧数是（ ）。  
  A. 2 \quad B. 3 \quad C. 4 \quad D. 5
- **精析**：
  GBN 采用累积确认机制。收到 3 号帧的确认表示“3 号及以前的所有帧（0, 1, 2, 3）均已被对端按序完整接收”（1 号确认的缺失仅仅说明该 ACK 在途中丢失，但已经被后续的 ACK3 隐式挽救）。
  因此截至超时时刻，只有 4, 5, 6, 7 这 4 个数据帧未被确认。定时器超时后，发送方需要重传 4, 5, 6, 7 共 4 个数据帧。
- **答案**：**C**

## 四、 综合解答题深度拓展（或大题考法联动）

综合解答题（大题）是 408 试卷中拉开分差的关键阵地。从 2017 年第 47 题到 2025 年第 47 题，ARQ 协议的考查已经彻底打破了单一学科知识点的藩篱，呈现出“物理层信道参数 $\to$$ \text{链路层滑动窗口控制} $$\to$$ \text{网络层 IP 编址规划} $$\to$ 传输层可靠端到端传输”的立体网状结构。

#### （1）链路层 ARQ 和传输层 TCP 滑动窗口机制对照：同构映射及深度异同
考研大题极易借题发挥，将链路层 ARQ 的设计思想和传输层 TCP 进行对比设问。二者的本质异同体现在：
1. **序号的颗粒度**：
   - 数据链路层 ARQ 针对的是离散的**数据帧（Frame）**，序号按帧计数（如 0, 1, 2, 3... 帧）。
   - 传输层 TCP 针对的是连续的**字节流（Byte Stream）**，序号按单个字节顺序编号（Sequence Number 为数据段中首字节在字节流中的位置偏移）。
2. **窗口尺寸的决定因素**：
   - 数据链路层通常是点到点直接物理链路，收发两端硬件处理能力固定，窗口大小 $W_T$ 在协议配置时通常作为**静态常量**设定。
   - 传输层 TCP 面对的是跳数不可知、极其复杂的整网拥塞环境，其发送窗口由“接收端流量控制”和“网络拥塞控制”动态共同决定：
     $$W_{\text{TCP}} = \min(cwnd, \; rwnd)$$
3. **确认机制的演化**：
   - 基础 GBN 对应 TCP 传统的累积确认（ACK 确认号为期望收到的下一个字节序号）。
   - 基础 SR 对应 TCP 的选择确认（SACK, Selective ACK）扩展选项。通过在 TCP 选项字段携带未收到的字节块边界，避免重传已被正确接收的失序报文段。

#### （2）长肥网络（LFN, Long Fat Networks）及卫星信道特性
2025 年第 47 题所给出的卫星通信链路即典型的“长肥管道”：
- 传播时延极大（往返传播达数百毫秒，$RTT = 0.48\text{ s}$）。
- 时延带宽积 $BDP = C \times RTT$ 巨大。
- **解题精髓**：若在长肥管道上采用停等协议，由于信道中大部分时间没有数据在流动，信道利用率往往不足 1%；要提升利用率，必须采用连续 ARQ 并配置足够大的发送窗口 $W_T$。

### 2. 408 综合大题三大解题核心技法

#### 技法一：时延链路“时间轴切分法”
遇到计算文件上传总时间、传输时延及利用率的大题，必须严格遵循四步切分法，避免混淆概念：
1. **第一步：定单双向**。审题确认题目给出的距离是单程还是往返，介质速度是光纤（$2 \times 10^8\text{ m/s}$$ \text{）还是真空电磁波（} $$3 \times 10^8\text{ m/s}$$ \text{）。卫星链路一定要注意“地面} $$\to$$ \text{卫星} $$\to$$ \text{地面”传播距离需翻倍（} $$2 \times 36000\text{ km}$）。
2. **第二步：算两类核心时延**：
   - 发送时延（传输时延）：$$ \text{T_D = \frac{\text{分组比特数}}{\text{链路带宽}}} $$（发送时延同物理距离完全无关！）。
   - 传播时延：$$ \text{\tau = \frac{\text{物理距离}}{\text{电磁波传播速率}}} $$（传播时延同带宽完全无关！）。
3. **第三步：定确认帧开销**：
   - 若题目写明“忽略确认帧长”，则 $T_A = 0$。
   - 若题目说明“双向捎带确认且帧长相同”，则 $T_A = T_D$。
   - 若题目给出确认帧长度（如 2020 年真题），则 $$ \text{T_A = \frac{\text{确认帧长}}{\text{反向带宽}}} $$。
4. **第四步：组装通信周期**：
   $$T_{\text{cycle}} = T_D + \tau + T_A + \tau = T_D + RTT + T_A$$

#### 技法二：滑动窗口指针动态追踪法
遇到双向传输、捎带确认、重发追踪的大题（如 2017 年第 47 题），草稿纸上必须维护收发双方的三个指针变量：
- $SendBase$：当前发送窗口的下界（最早发出的未确认帧）。
- $NextSeqNum$：发送端下一个即将发送的新帧序号。
- $RcvBase$：接收端当前期待收到的按序帧序号。
- **状态转移判定**：
  - 每发射一帧：$NextSeqNum \leftarrow (NextSeqNum + 1) \bmod 2^n$。
  - 每收到一个合法确认号 $y$：
    - 在 GBN 模式下，直接将 $SendBase$$ \text{滑动至} $$y$。
    - 此时窗口剩余可用额度为 $W_T - (NextSeqNum - SendBase)$。
  - 一旦发生超时：
    - GBN 重传从 $SendBase$$ \text{开始至} $$NextSeqNum - 1$ 的所有帧。
    - SR 仅重传超时的那个孤立帧。

#### 技法三：双向捎带确认解耦法
面对符号 $S_{x,y}$$ \text{和} $$R_{x,y}$，解题时切忌把两个下标混在一起，必须强行在草稿纸上将两端的数据流和控制流剥离：
- 拆解符号：对于甲发出的帧 $S_{x,y}$$ \text{，左侧} $$x$$ \text{代表“甲方自己发送数据的序列号”，右侧} $$y$ 代表“甲方顺路捎带给乙方的确认号（即甲方此时此刻期望从乙方收到的下一帧）”。
- 顺藤摸瓜：
  - 要看“乙方是否已收到甲方的帧”，只看乙方发来的帧 $R_{a,b}$$ \text{中的**右侧确认号} $$b$**！
  - 要确定“甲方发帧时 $y$$ \text{应该填什么”，只看甲方最近一次收到的按序乙方帧} $$R_{a,b}$$ \text{中的**左侧发送号} $$a$$ \text{**，甲方的期望号即为} $$(a + 1) \bmod 2^n$！

### 3. 典型踩分点及规范答题模板

在历年统考大题阅卷中，考生常因为格式不规范、步骤遗漏导致冤枉扣分。特整理标准答题模板规范：

#### 规范模板一：信道利用率及最小窗口求解题型
```
【标准解题步骤书写规范】
解：
1. 依据题意计算单个数据帧发送时延 TD：
   TD = 数据帧长度 / 链路传输速率 = [代入数值] = ... s
```

## 五、 考点速记清单

### 1. 核心解题口诀
- **窗口约束总纲**：收发窗口加起来，绝不超越序号排（$W_T + W_R \le 2^n$）。
- **GBN 协议特性**：GBN 接收窗为一，发送窗口 $2^n - 1$；累积确认管一片，一人超时全重传。
- **SR 协议特性**：SR 接收大过一，收发对称对半劈（$2^{n-1}$）；独立确认单定时，谁坏重发谁自己。
- **利用率饱和法则**：利用率算发送比周期，窗口填满管道达第一（$W_T \ge \lceil T_{\text{cycle}} / T_D \rceil$）。

---

### 2. 经典避坑指南（8 大高频失分陷阱）

1. **传播时延单程及往返混淆**：
   题目给出“单向传播时延”时，算周期必须乘以 2（往返）；若题目给出“RTT”，则本身已经是往返时延，严禁再次乘以 2！
2. **卫星链路距离单程翻倍陷阱**：
   地面两端通过同步通信卫星中继传输时，电磁波必须先“上行”飞到卫星（$36000\text{ km}$$ \text{），再“下行”折返飞向地面（} $$36000\text{ km}$$ \text{），单向传播物理距离必须按} $$72000\text{ km}$ 计算！
3. **确认帧发送时延遗漏陷阱**：
   审题务必看清是“忽略确认帧长”（$T_A = 0$$ \text{）、给出具体控制帧长度（} $$T_A = L_{\text{ack}} / C$$ \text{）、还是“双方双向捎带确认”（} $$T_A = T_D$$ \text{）。切忌惯性思维默认} $$T_A = 0$。
4. **窗口计算向上取整及向下取整混淆**：
   - 求解“信道利用率不低于某百分比时的**最小发送窗口**”时，必须**向上取整**（例如 $7.2 \to 8$）。
   - 求解“给定发送窗口下信道能达到的**最大吞吐率**”时，必须取信道带宽的瓶颈值（$\min(U \cdot C, \; C)$）。
5. **GBN 发送窗口等于模空间容量陷阱**：
   GBN 发送窗口**绝对不能等于 $2^n$$ \text{**！必须严格小于等于} $$2^n - 1$！例如 3 比特序号，发送窗口最大是 7，绝不是 8。
6. **SR 发送窗口越界陷阱**：
   SR 协议收发窗口相等时，最大窗口尺寸**绝对不能超过 $2^{n-1}$**！例如 3 比特序号，SR 最大窗口是 4，绝不是 7，也不是 8。
7. **GBN 累积确认跳跃认知陷阱**：
   收到针对 3 号帧的 ACK，意味着 0, 1, 2, 3 号帧全部确认；若中间的 1 号 ACK 丢失，只要 3 号 ACK 到达，无需重发 1 号帧！
8. **单位换算十进制及二进制混淆陷阱**：
   - 带宽传输速率 $C$$ \text{：按十进制换算（} $$1\text{ kbps} = 10^3\text{ bps}$，$1\text{ Mbps} = 10^6\text{ bps}$）。
   - 存储及帧长：按二进制换算（$1\text{ B} = 8\text{ bit}$，$1\text{ KB} = 1024\text{ B}$$ \text{，但考研大题通常明确指定} $$1000\text{ B}$，以题目显式数值为准）。

### 3. 高频核心公式速查表

| 指标 / 参数名称 | 数学计算公式 | 适用场景及关键说明 |
| :--- | :--- | :--- |
| **数据帧发送时延** | $T_D = \frac{L_{\text{data}}}{C}$ | $L_{\text{data}}$$ \text{为数据帧长（bit），} $$C$ 为信道带宽（bps） |
| **单向传播时延** | $\tau = \frac{D}{V}$ | $D$$ \text{为介质距离，} $$V$ 为电磁波在介质中传播速度 |
| **往返传播时延** | $RTT = 2\tau$ | 物理往返传播时间 |
| **单帧传输总周期** | $T_{\text{cycle}} = T_D + RTT + T_A$$ \text{| 若忽略确认帧时延取} $$T_A = 0$$ \text{；捎带确认取} $$T_A = T_D$ |
| **时延带宽积 (BDP)** | $\text{BDP} = C \times RTT$ | 充满双向信道管道的最大飞行比特数 |
| **管道数据帧容量** | $N_{\text{pipe}} = \frac{C \times RTT}{L_{\text{data}}} = \frac{RTT}{T_D}$ | 管道中最多能容纳的在途数据帧个数 |
| **停等协议利用率** | $U = \frac{T_D}{T_D + RTT + T_A}$ | 每周期仅发射 1 帧 |
| **连续 ARQ 利用率** | $U = \min\left(1, \; \frac{W_T \times T_D}{T_D + RTT + T_A}\right)$ | 适用于 GBN 和 SR 协议 |
| **实际平均吞吐率** | $\text{Throughput} = U \times C$ | 链路有效传输速率 |
| **100%利用率最小窗口**| $W_{\min} = \left\lceil \frac{T_D + RTT + T_A}{T_D} \right\rceil$ | 向上取整，消除信道空闲气泡 |
| **滑动窗口通用约束**| $W_T + W_R \le 2^n$$ \text{| 序号空间} $$n$ 比特，杜绝一切序号混淆二义性 |
| **GBN 发送窗口极值** | $1 \le W_T \le 2^n - 1$$ \text{| 接收窗口恒为} $$W_R = 1$ |
| **SR 对称窗口极值** | $W_T = W_R \le 2^{n-1}$ | 收发两端窗口对称设计 |
| **GBN 最小序号位数** | $k \ge \lceil \log_2(W_T + 1) \rceil$ | 由发送窗口逆推最小所需序号编码位数 |
| **SR 最小序号位数** | $k \ge \lceil \log_2(2 W_T) \rceil = \lceil \log_2(W_T) \rceil + 1$$ \text{| 当} $$W_T = W_R$ 时成立 |
