## 二、 具体考察内容

### 1. 802.11 无线局域网无法使用 CSMA/CD 的物理成因

以太网（IEEE 802.3）采用 CSMA/CD（载波监听多路访问/碰撞检测）机制，其核心前提是发送站点在发送信号的同时具备检测信道中是否存在碰撞的能力（边发边听）。然而，在无线局域网（IEEE 802.11）环境中，物理特性决定了 CSMA/CD 无法有效运行，主要原因如下：

#### (1) 硬件物理特性的限制（发射功率远超接收灵敏度）
无线通信依靠空间电磁波传播，信号衰减与距离平方甚至高次方成正比。站点在发射信号时的功率远大于其天线接收到的微弱信号。发射信号的电平往往高出接收信号电平 $60 \sim 100 \text{ dB}$（信号功率相差 $10^6 \sim 10^{10}$ 倍）。如果站点在发送信号的同时尝试监听信道，强烈的本地发射信号会彻底淹没任何来自其他站点的微弱碰撞信号。在技术成本上，制造能够实现“边发边听”的全双工硬件极为昂贵且难以普及。

#### (2) 碰撞检测的局限性（信道空间特异性）
碰撞只在接收站点的天线处产生破坏性干扰才有实际意义。由于多径效应、障碍物衰减以及电磁波的空间发散，即使发送站点在本地天线处未检测到碰撞，接收站点处也可能由于两个异地发射源的信号同时到达而引发碰撞破坏；反之，发送端检测到噪声，接收端却可能接收良好。

#### (3) 隐蔽站和暴露站问题
无线介质没有固定的物理边界，每个站点的无线电覆盖范围有限，导致物理载波监听失灵，形成了经典的隐蔽站和暴露站现象。

### 2. 隐蔽站和暴露站机制分析

#### (1) 隐蔽站问题（Hidden Terminal Problem）

* **物理拓扑模型**：

```text
    站点 A                接入点 AP / 站点 B              站点 C
   ( [A] )                       [B]                      ( [C] )
      |                           |                          |
      +---- A的覆盖范围 ----+      |                          |
      |                           +---- C的覆盖范围 ----+     |
      |                                                 |     |
      v                                                 v     v
   A 能听到 B                  B 能听到 A 和 C               C 能听到 B
   A 听不到 C                                              C 听不到 A
```

* **冲突场景推导**：
  1. 站点 A 欲向站点 B 发送数据帧，执行物理载波监听，因 C 处于 A 的传输范围之外，A 检测信道为空闲；
  2. 与此同时，站点 C 亦欲向站点 B 发送数据帧，监听介质后同样判断信道为空闲；
  3. 站点 A 和站点 C 同时向站点 B 发射数据帧，两路电磁波在站点 B 处叠加产生碰撞，导致接收彻底失败。
* **本质**：A 和 C 互为隐蔽站（彼此外界不可见），物理载波监听在此失效。
* **解决方案**：引入基于信道预约的 **RTS/CTS 握手机制**。

#### (2) 暴露站问题（Exposed Terminal Problem）

* **物理拓扑模型**：

```text
    站点 A            站点 B            站点 C            站点 D
      [A] <--------- [B]                [C] ----------> [D]
       ^              ^                  ^               ^
       |-- B的范围 ---|                  |--- C的范围 ---|
                      +---- 互能监听 ----+
```

* **问题推导**：
  1. 站点 B 正在向站点 A 发送数据；
  2. 站点 C 欲向位于其右侧覆盖范围内的站点 D 发送数据，C 进行载波监听；
  3. C 监听到 B 正在发射信号，误认为信道处于繁忙状态，被迫进入退避等待；
  4. 事实上，C 向 D 发射信号完全不会干扰 A 对 B 信号的接收（因 A 处于 C 的干扰范围之外）。
* **本质**：站点 C 因监听到相邻节点的发送而过度抑制了自身合法的发送需求，降低了信道空间复用效率。

### 3. RTS/CTS 握手机制及虚拟载波监听（NAV）

为解决隐蔽站碰撞并实现信道预约，IEEE 802.11 引入了 RTS/CTS（Request to Send / Clear to Send）握手协议以及网络分配向量（NAV, Network Allocation Vector）机制。

```text
发送站 A           AP / 接收站 B          隐蔽站 C
   |                     |                   |
   |--- RTS (预约时间) ->|                   |  (C 听不到 RTS)
   |                     |                   |
   |                     |--- CTS (预约时间) ->|  (C 收到 CTS，更新 NAV)
   |                     |                   |  ====== NAV 冻结期 ======
   |<-- CTS -------------|                   |  [C 静默禁止发射]
   |                                         |
   |--- DATA (数据帧) ---------------------->|
   |                                         |
   |<-- ACK (确认帧) ------------------------|
   |                     |                   |  ====== NAV 计数器到期 ==
   |                     |                   |  (恢复竞争信道)
```

#### (1) RTS/CTS 报文控制流程
1. **发送 RTS**：源站 A 获得信道访问权后，先向目的站 B 发送一个短控制帧 RTS（Request to Send）。RTS 帧头部包含一个 16 位的**持续期（Duration）**字段，标明本次事务后续所需传输时间的总和。
2. **广播 CTS**：目的站 B 收到 RTS 后，等待一个短帧间间隔（SIFS），向全向广播允许发送帧 CTS（Clear to Send）。CTS 同样携带 Duration 字段，通知信道预约的具体时长。
3. **数据和确认**：源站 A 收到 CTS 后等待 SIFS，发射数据帧（DATA）；目的站 B 成功接收后，等待 SIFS 并回复确认帧（ACK）。

#### (2) 虚拟载波监听与 NAV 计算
* **物理载波监听及虚拟载波监听之配合**：
  - **物理载波监听**：由物理层执行能量检测（ED）与载波检测（CS）；
  - **虚拟载波监听**：由 MAC 层维护一个逻辑计数器，即**网络分配向量（NAV）**。
* **NAV 工作机理**：
  隐蔽站 C 虽未侦测到 A 发出的 RTS，但必然能收到 AP（B）广播的 CTS 帧。C 提取 CTS 报文头部的 Duration 字段，将其装入自身的 NAV 计数器中。在 NAV 倒计时归零前，即使物理信道检测显示电平为空闲，C 仍必须强制判定信道处于占用状态，严禁向外发射任何帧。

#### (3) RTS/CTS 中的 Duration 数值计算推导

* **RTS 帧携带的 Duration 计算**：
  RTS 意在预约从 CTS 开始至该数据传输事务彻底完成的时长：
  $$\text{Duration}_{\text{RTS}} = \text{SIFS} + t_{\text{CTS}} + \text{SIFS} + t_{\text{DATA}} + \text{SIFS} + t_{\text{ACK}}$$
* **CTS 帧携带的 Duration 计算（NAV 设置基准）**：
  CTS 意在预约从数据帧开始至事务最终确认完成的时长。隐蔽站收到 CTS 时设置的 NAV 值为：
  $$\text{NAV} = \text{Duration}_{\text{CTS}} = \text{SIFS} + t_{\text{DATA}} + \text{SIFS} + t_{\text{ACK}}$$
  其中：
  - $t_{\text{DATA}} = \dfrac{\text{数据帧比特长度}}{\text{数据传输速率}}$
  - $t_{\text{ACK}} = \dfrac{\text{ACK 帧比特长度}}{\text{控制帧传输速率}}$

### 4. 帧间间隔（IFS）优先级体系及退避算法

IEEE 802.11 规定在发送任何一帧前，站点必须在信道空闲后持续监听一段固定时长，即帧间间隔（IFS, Inter-Frame Space）。**帧间间隔越短，优先级越高**，从而在无集中仲裁的情况下依靠时延差异实现优先访问。

```text
+--------------------------------------------------------------------------+
| 帧间间隔分类及优先级排布                                                 |
|                                                                          |
| 时延长度:    SIFS  <  PIFS  <  DIFS                                      |
| 访问优先级:  SIFS  >  PIFS  >  DIFS                                      |
+--------------------------------------------------------------------------+
```

#### (1) 三种典型帧间间隔特性

1. **SIFS（Short IFS，短帧间间隔）**：
   - **特点**：时长最短，信道抢占优先级最高；
   - **用途**：专用于需要即刻响应的控制交互，包括 **ACK 帧**、**CTS 帧**、分片后续帧以及回答 AP 轮询的响应帧。
   - **机制考量**：确保正在进行的一轮多步交互（如 RTS-CTS-DATA-ACK）不被任何其他外来异步竞争帧打断。
2. **PIFS（Point Coordination IFS，点协调帧间间隔）**：
   - **特点**：时长居中，优先级次之；
   - **用途**：用于 PCF（点协调功能）集中控制模式，AP 获取信道控制权并轮询各站点。
3. **DIFS（Distributed Coordination IFS，分布式协调帧间间隔）**：
   - **特点**：时长最长，优先级最低；
   - **用途**：用于 DCF（分布式协调功能）下所有普通异步数据帧和 RTS 帧的首次竞争接入。

#### (2) CSMA/CA 完整退避机制及时间演变

当信道从繁忙变为空闲时，若允许多个等待站点同时发送，必然导致即时碰撞。因此，802.11 强制引入**二进制指数退避算法**。

```text
信道状态: [   忙   ]  | <--- DIFS ---> | <--- 退避时槽 Slot ---> | 发送帧
                      |                | [1] | [2] | [3] | ... |
站点状态: [挂起等待]  |  空闲检测计时   | 随机倒计时: 计数器减 1  | 归零发射
```

* **退避启动的四种法定情形**：
  1. 站点在发送数据帧前，监听到信道处于繁忙状态；
  2. 站点重传之前（因碰撞或未收到 ACK）；
  3. 站点成功发送完一个数据帧后，为保证竞争信道的公平性，强制执行一次退避。
* **退避窗口计算公式**：
  退避时间由离散的退避时隙（SlotTime）构成：
  $$\text{退避时延} = \text{SlotTime} \times r$$
  其中随机整数 $r$ 服从均匀分布：
  $$r \in [0, CW - 1]$$
  - 初始状态下竞争窗口 $CW = CW_{\min}$；
  - 每次重传失败（未收到 ACK），竞争窗口翻倍扩张：$CW_{\text{new}} = 2 \times (CW_{\text{old}} + 1) - 1$，直到达到上限 $CW_{\max}$；
  - 传输成功后，竞争窗口立即恢复为初始值 $CW_{\min}$。
* **退避计数器“冻结”及恢复机制**：
  - 站点在信道空闲时，退避计数器每经过一个 SlotTime 减 1；
  - 一旦物理或虚拟载波监听发现信道变忙，退避计数器立即**冻结（挂起）**，保持当前数值不变；
  - 信道恢复空闲并重新持续稳定一个 DIFS 后，退避计数器在原先冻结的残余数值基础上继续倒计时。这保证了已等待较长时间的站点享有更高的信道捕获概率，兼顾系统公平性。

### 5. 802.11 MAC 帧结构及寻址机制（四地址系统）

IEEE 802.11 帧头包含多达 4 个 48 位（6 字节）MAC 地址字段。其具体含义完全由帧控制字段中的两个核心控制位 **`To DS`** 和 **`From DS`**（DS 为分布式系统/有线骨干网，Distribution System）决定。

#### (1) 四种寻址组合定义表

| To DS | From DS | 地址 1（RA） | 地址 2（TA） | 地址 3 | 地址 4 | 应用场景 |
| :---: | :---: | :---: | :---: | :---: | :---: | :--- |
| **0** | **0** | DA（目的） | SA（源） | BSSID | 未使用 | 独立自组网（IBSS，Ad-hoc 无 AP 模式） |
| **1** | **0** | **AP 的 MAC（RA）** | **源主机 MAC（SA）** | **目的网关 MAC（DA）** | 未使用 | **站点上行发往 AP（To AP）** |
| **0** | **1** | **目的主机 MAC（DA）** | **AP 的 MAC（TA）** | **源路由器 MAC（SA）** | 未使用 | **AP 下行发往站点（From AP）** |
| **1** | **1** | RA（接收 AP） | TA（发射 AP） | DA（终极目的） | SA（最初始源） | 无线网桥/骨干中继（WDS 模式） |

#### (2) 考研寻址速记法则
* **地址 1（Receiver Address, RA）**：当前无线跳的**直接物理接收方**；
* **地址 2（Transmitter Address, TA）**：当前无线跳的**直接物理发射方**；
* **地址 3**：**过滤与路由衔接端**。若数据发往有线网（To AP），由 AP 负责剥离 802.11 头并将数据转发给目的网关，故地址 3 为最终目的 DA；若数据来自有线网（From AP），由 AP 下发给无线主机，地址 3 记载骨干网发来的初始源 SA。

## 三、 近十年真题精讲（2016~2025）

### 2024 年全国统考 408 计算机联考第 36 题

#### 1. 真题原题
在采用 CSMA/CA 的 802.11 无线局域网中，$\text{DIFS} = 120\ \mu\text{s}$，$\text{SIFS} = 28\ \mu\text{s}$，RTS、CTS 和 ACK 帧的传输时延分别是 $3\ \mu\text{s}$、$2\ \mu\text{s}$ 和 $2\ \mu\text{s}$，忽略信号传播时延。若主机 A 欲向 AP 发送一个总长度为 $1998\ \text{B}$ 的数据帧，无线链路带宽为 $54\ \text{Mb/s}$，则隐藏站 B 收到 AP 发送的 CTS 帧时，设置的网络分配向量 NAV 的值是（ ）。

A. $326\ \mu\text{s}$  
B. $354\ \mu\text{s}$  
C. $385\ \mu\text{s}$  
D. $513\ \mu\text{s}$  

#### 2. 深度推导过程
* **第一步：明确网络分配向量（NAV）的物理定义**  
  NAV 是节点根据接收到的控制帧（RTS 或 CTS）中所标明的“持续期（Duration）”字段设定的静默时间计数器。当隐藏站 B 收到 AP 广播的 CTS 帧时，其 NAV 需覆盖从 CTS 发送结束直至整个通信过程彻底结束（即接收到最后的 ACK 帧）所持续的时间。
* **第二步：分析 CTS 之后信道占用的时序链条**  
  根据 CSMA/CA 机制的时序规范，CTS 发送完毕后，信道将依次经历以下四个连续阶段：
  1. 间隔等待阶段 1：等待一个短帧间间隔 SIFS；
  2. 数据帧发送阶段：主机 A 向 AP 发送长度为 $1998\ \text{B}$ 的数据帧；
  3. 间隔等待阶段 2：等待一个短帧间间隔 SIFS；
  4. 确认帧发送阶段：AP 向主机 A 回复 ACK 帧。  
  其对应的时序结构方程为：
  $$\text{NAV} = \text{SIFS} + t_{\text{DATA}} + \text{SIFS} + t_{\text{ACK}}$$
* **第三步：代入具体数值严密演算**  
  1. 计算数据帧的传输时延 $t_{\text{DATA}}$：
     $$t_{\text{DATA}} = \frac{1998\ \text{B} \times 8\ \text{b/B}}{54\ \text{Mb/s}} = \frac{15984\ \text{bit}}{54 \times 10^6\ \text{bit/s}} = 296 \times 10^{-6}\ \text{s} = 296\ \mu\text{s}$$
  2. 汇总各项时延成分：
     $$\text{NAV} = 28\ \mu\text{s} + 296\ \mu\text{s} + 28\ \mu\text{s} + 2\ \mu\text{s} = 354\ \mu\text{s}$$

#### 3. 陷阱规避分析
* **常见误区一**：将 DIFS 混入 NAV 中。DIFS 是开始竞争信道前等待的间隔，并不属于本次预约保护的传输事务持续期。
* **常见误区二**：错误计入 RTS 时延。题目明确指出是**收到 CTS 帧时**设置 NAV，RTS 与 CTS 此时均已在空中传输完毕，后续需要保护的仅为数据传输与 ACK。

#### 4. 正确答案
**B**

### 2020 年全国统考 408 计算机联考第 37 题

#### 1. 真题原题
某 IEEE 802.11 无线局域网中主机 H 与 AP 之间发送或接收 CSMA/CA 帧的过程如下图所示，在 H 或 AP 发送帧前所等待的帧间间隔时间（IFS）中最长的是（ ）。

```text
       +-----+       +-----+       +------+       +-----+
主机 H | RTS |       |     |       | DATA |       |     |
       +-----+       |     |       +------+       |     |
          |          |     |          |           |     |
AP        |          | CTS |          |           | ACK |
          |          +-----+          |           +-----+
       ---+----------+-----+----------+-----------+-----+---> 时间
         IFS1         IFS2          IFS3         IFS4
```

A. IFS1  
B. IFS2  
C. IFS3  
D. IFS4  

#### 2. 深度推导过程
* **第一步：判定各个 IFS 所对应的帧间间隔类型**  
  - **IFS1**：主机 H 产生向外发送 RTS 帧的意愿，开始在信道中竞争访问，必须首先监听到信道空闲持续一个分布式协调帧间间隔，因此 $\text{IFS1} = \text{DIFS}$。
  - **IFS2**：AP 在收到主机 H 的 RTS 帧后，必须在短时间内锁定信道予以确认，以防被其他节点插足竞争，因此采用最高优先级的短帧间间隔，即 $\text{IFS2} = \text{SIFS}$。
  - **IFS3**：主机 H 收到 CTS 帧后，立即发送预先准备好的数据帧 DATA，同属于当前事务的连续交互步骤，因此 $\text{IFS3} = \text{SIFS}$。
  - **IFS4**：AP 成功接收数据帧后，迅速向主机 H 回复确认帧 ACK，同样必须使用短帧间间隔，即 $\text{IFS4} = \text{SIFS}$。
* **第二步：对比各类帧间间隔的长度属性**  
  在 IEEE 802.11 协议标准中，各类帧间间隔设计原则为：**优先级越高，等待时间越短**。
  其持续时间满足严格单调递增关系：
  $$\text{SIFS} < \text{PIFS} < \text{DIFS}$$
  因此，在上述四个间隔中，$\text{IFS1}$ 为 DIFS，时长最长；$\text{IFS2}$、$\text{IFS3}$、$\text{IFS4}$ 均为 SIFS，时长最短。

#### 3. 正确答案
**A**

### 2018 年全国统考 408 计算机联考第 35 题

#### 1. 真题原题
IEEE 802.11 无线局域网的 MAC 协议 CSMA/CA 进行信道预约的方法是（ ）。

A. 发送确认帧  
B. 采用二进制指数退避  
C. 使用多个 MAC 地址  
D. 交换 RTS 与 CTS 帧  

#### 2. 深度推导过程
* **选项 A 解析**：确认帧（ACK）用于数据链路层的可靠传输服务（停止-等待 ARQ 机制），目的是在发生丢包或误码时告知发送方触发超时重传，并不具有预留信道资源的功能，故 A 错误。
* **选项 B 解析**：二进制指数退避是当介质繁忙或发生碰撞重传时，各站点离散随机等待时延以降低二次冲突概率的退避防拥塞机制，属于冲突化解策略，而非信道预约手段，故 B 错误。
* **选项 C 解析**：802.11 帧中包含多个 MAC 地址字段（源地址、目的地址、接入点地址等）是为了解决多跳无线中继及分布式系统转发中的路由匹配问题，与介质预约无关，故 C 错误。
* **选项 D 解析**：CSMA/CA 机制正是通过源站发送请求发送帧（RTS）与目的站广播允许发送帧（CTS）所携带的 Duration 字段，使全网侦听节点配置自身的 NAV 虚拟载波监听定时器，从而完成对物理信道未来一段时间的排他性预约，故 D 正确。

#### 3. 正确答案
**D**

### 2017 年全国统考 408 计算机联考第 35 题

#### 1. 真题原题
在下图所示的网络中，若主机 H 发送一个封装访问 Internet 的 IP 分组的 IEEE 802.11 数据帧 F，则帧 F 的地址 1、地址 2 和地址 3 分别是（ ）。

```text
       主机 H                           接入点 AP                        路由器 R
(00-12-34-56-78-9a)              (00-12-34-56-78-9b)              (00-12-34-56-78-9c)
       [H]                               [AP]                             [R]
        |                                 |                                |
        +========== 802.11 无线链路 ======>+======== 802.3 有线以太网 ======>+
                       帧 F                                                 |
                                                                        [Internet]
```

A. 00-12-34-56-78-9a, 00-12-34-56-78-9b, 00-12-34-56-78-9c  
B. 00-12-34-56-78-9b, 00-12-34-56-78-9a, 00-12-34-56-78-9c  
C. 00-12-34-56-78-9b, 00-12-34-56-78-9c, 00-12-34-56-78-9a  
D. 00-12-34-56-78-9a, 00-12-34-56-78-9c, 00-12-34-56-78-9b  

#### 2. 深度推导过程
* **第一步：判定通信拓扑模式与控制标志位**  
  主机 H 通过无线接入点 AP 访问外部 Internet，该通信需要先经由 AP 桥接送入有线分布式系统（DS）。
  因此，该数据帧 F 属于**上行传输（To AP 模式）**。
  其对应的帧控制字段取值为：$\text{To DS} = 1, \text{From DS} = 0$。
* **第二步：解析各地址字段的职责分工**  
  在 $\text{To DS} = 1, \text{From DS} = 0$ 的封装模式下，IEEE 802.11 数据帧前三个地址的定义如下：
  1. **地址 1（接收端地址 RA）**：由于数据帧直接由主机 H 通过无线信号发射给 AP，直接物理接收方是 AP，因此地址 1 为 AP 的无线网卡 MAC 地址：`00-12-34-56-78-9b`；
  2. **地址 2（源地址 SA）**：产生该数据帧的真正源始节点是主机 H，因此地址 2 为主机 H 的 MAC 地址：`00-12-34-56-78-9a`；
  3. **地址 3（目的地址 DA）**：AP 作为二层网桥设备，在收到帧 F 后会将其转换为以太网 802.3 帧格式，并转发给下一跳网关设备路由器 R。因此在有线网络中的目的终端是路由器 R 的接口，地址 3 必须指明最终目的 MAC，即路由器 R 的 MAC 地址：`00-12-34-56-78-9c`。
* **第三步：核对选项匹配结果**  
  - 地址 1：`00-12-34-56-78-9b`（AP）
  - 地址 2：`00-12-34-56-78-9a`（H）
  - 地址 3：`00-12-34-56-78-9c`（R）  
  完全匹配选项 B。

#### 3. 正确答案
**B**

## 四、 综合解答题深度拓展及大题考法联动

在 408 计算机考研的历年综合应用题（第 47 题）中，网络拓扑正由单纯的“路由器 + 交换机”向包含“无线主机 + AP + 交换机 + 路由器”的跨介质融合架构演进。考生必须掌握以下三大跨层综合联动考法：

```text
拓扑全景图:
+----------+ 802.11 无线链路 +----------+ 802.3 以太网链路 +----------+
|  主机 H  | <------------> |  接入点  | <-------------> | 默认网关 | ----> [广域网 WAN]
| (无线STA) |    (CSMA/CA)   |   (AP)   |  (全双工无碰撞)  | 路由器 R |
+----------+                +----------+                 +----------+
```

### 1. 跨介质协议转换考法（802.11 及 802.3 帧格式转换与地址映射）
* **协议转换节点的层级定位**：
  AP 在逻辑上属于**数据链路层（网桥模式）**设备，其物理上拥有两个接口：一个无线 802.11 射频接口和一个有线 802.3 双绞线接口。
* **帧格式的重新封装细节**：
  - 当主机 H 上行发送分组时，H 构建 802.11 帧，填入 3 个 MAC 地址（RA=AP, SA=H, DA=Router）；
  - AP 接收到该无线帧后，进行 CRC 校验并验证 RA 是否为自身；
  - AP **完全剥离** 802.11 帧首部及尾部，取出内部承载的 IP 数据报；
  - AP **重新封装**为标准以太网 802.3 帧：目的 MAC 填入原地址 3（Router 的 MAC），源 MAC 填入原地址 2（H 的 MAC）。**注意：AP 自身的 MAC 地址彻底退出以太网帧头**。
* **ARP 协议在跨介质通信中的交互**：
  主机 H 在发送数据前，若本地无默认网关的 ARP 映射，H 会在无线信道广播 ARP 请求帧（DA 为全 1 广播地址），AP 收到后将其转换为以太网广播帧广播到有线网络，路由器 R 回复单播 ARP 响应，最终使 H 学到网关 R 的 MAC 地址。

### 2. 混合链路端到端传输时延分析大题模型
若考题要求计算主机 H 发送一个分组到达路由器 R 的总时延（忽略排队与处理时延），需分段精确建模：

$$\text{总时延} T_{\text{total}} = T_{\text{无线段}} + T_{\text{有线段}}$$

#### (1) 无线接入段时延（考虑非握手直接传输或 RTS/CTS 握手传输）：
* 若不采用 RTS/CTS 机制：
  $$T_{\text{无线段}} = \text{DIFS} + \overline{\text{退避时延}} + \frac{L_{\text{802.11帧}}}{R_{\text{无线}}} + \tau_{\text{无线传播}} + \text{SIFS} + \frac{L_{\text{ACK}}}{R_{\text{控制}}} + \tau_{\text{ACK传播}}$$
* 若采用 RTS/CTS 握手机制：
  $$T_{\text{无线段}} = \text{DIFS} + \overline{\text{退避时延}} + t_{\text{RTS}} + \text{SIFS} + t_{\text{CTS}} + \text{SIFS} + t_{\text{DATA}} + \text{SIFS} + t_{\text{ACK}} + \sum \tau_{\text{传播}}$$

#### (2) 有线以太网段时延：
以太网通常工作在全双工交换模式下，无碰撞检测与退避开销：
$$T_{\text{有线段}} = \frac{L_{\text{以太网帧}}}{R_{\text{有线}}} + \tau_{\text{有线传播}}$$

## 五、 考点速记清单

### 1. 核心公式及参数对比速查

| 参数/机制 | 符号/公式 | 核心物理作用 |
| :--- | :--- | :--- |
| **帧间间隔关系** | $\text{SIFS} < \text{PIFS} < \text{DIFS}$ | 间隔越短，优先级越高；保障短控制交互优先完成 |
| **CTS 载荷 NAV 计算** | $\text{NAV} = 2 \times \text{SIFS} + t_{\text{DATA}} + t_{\text{ACK}}$ | 隐蔽站收到 CTS 后的信道保护期，杜绝数据碰撞 |
| **退避时延基准** | $T_{\text{backoff}} = r \times \text{SlotTime},\ r \in [0, CW-1]$ | 随机竞争离散退避，重传时 $CW$ 翻倍 |
| **上行数据帧地址（To AP）** | 地址1: AP MAC；地址2: H MAC；地址3: 路由器 MAC | “1收2发3目的”，地址1决定当跳物理接收点 |
| **下行数据帧地址（From AP）**| 地址1: H MAC；地址2: AP MAC；地址3: 路由器 MAC | “1收2发3源端”，地址1指向最终无线接收主机 |

### 2. 解题核心口诀

* **帧间间隔判定**：
  > “控制应答用 SIFS，集中控制用 PIFS，竞争首发用 DIFS；时延越小权越高，抢先信道不卡壳。”
* **寻址三步速断法**：
  > “第一看方向（To AP 还是 From AP）；  
  > 地址 1 必是空中当前接收方（RA），地址 2 必是空中当前发射方（TA）；  
  > 谁连外网谁占地址 3，发给外网是目的，外网发来是源头。”
* **NAV 持续期计算避坑**：
  > “求 CTS 的 NAV 莫算 RTS，莫加 DIFS；算头不算尾，只保后续两 SIFS 加一数据一确认。”

### 3. 避坑指南

1. **不可混淆 CSMA/CD 和 CSMA/CA 机制**：
   CSMA/CD 是“边发边听，碰撞即停，无确认帧”；CSMA/CA 是“发前先听，预约避免，强制确认（必须依赖 ACK）”。
2. **NAV 包含的项目界限**：
   NAV 表示的是“未发生的未来占用时间”。接收到 CTS 时，CTS 本身的发送时延不能算入 NAV 中；同时，DIFS 作为退避前的空闲判定，决不能计入 NAV。
3. **退避计数器“冻结”特性对比以太网重置机制**：
   以太网 CSMA/CD 碰撞后每次均重新随机生成一段全新的退避时间；802.11 的退避计数器在信道忙时仅仅是“冻结”，信道再次空闲持续 DIFS 后继续倒数，绝非重新抽取。
4. **AP 的二层透明性**：
   在跨网络通信中，以太网帧头仅包含源主机 MAC 和网关路由器 MAC，AP 自身的 MAC 地址不会出现在以太网帧头中。数据帧在 AP 处完成的是 802.11 格式到 802.3 格式的重封装，而非路由层面的 IP 转发。
