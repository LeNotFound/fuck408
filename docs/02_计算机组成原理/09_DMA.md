# 二、具体考察内容

## 1. DMA 方式的核心机理与设计哲学
在计算机传统的 I/O 控制方式中，无论是程序查询方式还是程序中断方式，其本质都是以 CPU 为核心展开的数据交换：
- 程序查询方式：CPU 处于轮询死循环，严重空耗 CPU 时钟周期。
- 程序中断方式：I/O 设备每准备好一个字或字节，便向 CPU 发出中断请求。CPU 必须经历保护现场、执行中断服务程序（将数据从外设接口读入通用寄存器，再由通用寄存器写入主存）、恢复现场的完整过程。当传输高速海量数据（如磁盘块、千兆网络数据包）时，高频的中断上下文切换将使 CPU 彻底瘫痪在中断处理中，产生中断活锁（Interrupt Livelock）。

直接内存访问（Direct Memory Access，DMA）的提出旨在彻底解放 CPU。其核心哲学是：在主存与高速 I/O 设备接口之间开辟一条直接的高速硬件数据通路。在数据块传送过程中，总线主控权由 CPU 暂时移交给专用的硬件控制器——DMA 控制器（DMAC），数据无需途经 CPU 寄存器中转，而是直接在 I/O 设备接口与主存储器之间流转。

```text
[传统中断方式数据流]
+---------------+       +---------------+       +---------------+
|  I/O 设备接口  | ----> | CPU 通用寄存器 | ----> |   主存储器    |
+---------------+       +---------------+       +---------------+
   （每传送一个字，CPU 介入执行完整的保护现场、读指令、写指令、恢复现场）

[DMA 方式数据流]
+---------------+                               +---------------+
|  I/O 设备接口  | ============================> |   主存储器    |
+---------------+       直接硬件总线通路        +---------------+
        ^                                               ^
        |                                               |
        +---------------[ DMA 控制器 ]------------------+
                         提供地址与时序控制
```

## 2. DMA 控制器（DMAC）内部硬件架构与核心部件
DMA 控制器是一个具备总线主控（Bus Master）能力的专用集成电路接口。其内部核心逻辑部件包含以下寄存器与控制单元：

```text
+-------------------------------------------------------------------+
|                        DMA 控制器 (DMAC)                          |
|                                                                   |
|   +--------------------------+    +---------------------------+   |
|   | 主存地址计数器 (MAR/AR)  |    | 传送长度计数器 (CR/WC)    |   |
|   | 存放当前传输的主存物理地址 |    | 记录待传字数 (减至0或溢出)  |   |
|   +--------------------------+    +---------------------------+   |
|                |                               |                  |
|                v                               v                  |
|   +--------------------------+    +---------------------------+   |
|   |   数据缓冲寄存器 (DR)    |    | 控制/状态寄存器 (CSR/SR)  |   |
|   | 暂存双向传输数据, 平衡频宽 |    | 存放控制命令与运行状态标志 |   |
|   +--------------------------+    +---------------------------+   |
|                |                               |                  |
|                +---------------+---------------+                  |
|                                |                                  |
|                                v                                  |
|                  +---------------------------+                    |
|                  | DMA 控制逻辑与中断机构    |                    |
|                  | 总线仲裁申请、主存读写时序  |                    |
|                  +---------------------------+                    |
+-------------------------------------------------------------------+
       |                 |               |                 |
       v                 v               v                 v
   [地址总线 AB]     [数据总线 DB]   [控制总线 CB]    [中断请求线 INTR]
```

### 1) 主存地址寄存器 / 计数器（MAR / AR）
- 作用：存放要在主存储器中进行读写的物理地址。
- 工作机制：在预处理阶段由 CPU 写入传输首地址。在数据传送阶段，DMAC 将该地址驱动至系统地址总线；每传送完成一个字（或字节），MAR 自动加 1（或减 1，取决于地址增长方向），自动指向下一个存储单元。

### 2) 传送长度计数器 / 字计数器（CR / WC，Count Register / Word Counter）
- 作用：记录该数据块待传送的数据总量（以字或字节为单位）。
- 计数机制（考点细节）：
  - 减计数模式：预置实际传送字数 $N$。每传送一个字，计数器减 1，减至 0 时触发传送结束信号。
  - 补码加计数模式：将传送字数的二进制补码 $-N = 2^k - N$ 预置入计数器。每传送一个字，计数器加 1，当计数器发生溢出（Carry Out）翻转为 0 时，溢出脉冲触发传送结束信号。

### 3) 数据缓冲寄存器（DR / DB，Data Register / Data Buffer）
- 作用：暂存外设与主存之间交换的数据。
- 必要性：由于外设的读写时钟与系统总线的主存时钟通常不同步，且外设数据位宽（如 8 位串行转并行）与总线数据宽度（如 32 位、64 位）常存在差异，DR 起到时钟域隔离、组包拼装与数据平滑缓冲的作用。

### 4) 控制 / 状态寄存器（CSR：Control and Status Register）
- 控制寄存器（CR）：接收 CPU 发出的操作指令，包括传送方向（设备到主存即读入，或主存到设备即写出）、工作模式（周期挪用或块突发）、中断使能位等。
- 状态寄存器（SR）：反映 DMAC 当前硬件状态，包括传送就绪标志、传送完成标志、硬件错误/溢出（Overrun）标志等。

### 5) DMA 控制逻辑与中断机构
- 控制逻辑：负责监测外设的数据就绪请求信号（DREQ），向 CPU 或总线仲裁器发送总线保持请求（HOLD / BUS REQ），接收总线授权响应（HLDA / BUS ACK），并接管总线生成主存读/写（MEMR/MEMW）控制信号。
- 中断机构：当 CR 计数结束（整块数据传输完毕）或在传输期间检测到硬件故障时，通过该机构向 CPU 发出中断请求信号，激活后处理流程。

## 3. DMA 传送通路的端点界定
408 核心概念精准辨析：
- 控制信号通路：CPU 与 DMAC 之间存在控制通路。预处理阶段 CPU 向 DMAC 寄存器写入参数，后处理阶段 DMAC 向 CPU 发送中断请求。
- 数据传输通路：DMA 方式下，数据传送的真实通路位于**设备接口与主存之间**。DMAC 控制总线，使得外设接口与主存储器直接挂载在系统数据总线上进行数据读写。数据流绝对不流经 CPU。

## 4. DMA 传送全生命周期三阶段控制流
DMA 的完整运行周期被严格划分为三个阶段：预处理、数据传送、后处理。三阶段的软硬件分工界限极其清晰，是选择题与综合题的高频考查点。

```text
+-------------------------------------------------------------------------------------+
| 1. 预处理阶段 (软件控制, CPU 主导)                                                    |
|    - CPU 执行设备驱动程序指令                                                        |
|    - 向 DMAC 写入传送参数 (MAR = 物理起始地址, CR = 数据块字数, CSR = 传送模式与方向) |
|    - 向 I/O 设备发送启动命令                                                         |
|    - CPU 退出预处理, 继续执行原有主程序 (与 I/O 准备工作完全并行)                     |
+-------------------------------------------------------------------------------------+
                                          |
                                          v
+-------------------------------------------------------------------------------------+
| 2. 数据传送阶段 (纯硬件控制, DMAC 主导, CPU 完全不参与数据搬运)                     |
|    - 步骤 2.1: 设备准备好一个字/块数据, 向 DMAC 发出 DMA 请求 (DREQ)                |
|    - 步骤 2.2: DMAC 向 CPU 发出总线请求 (BUS REQ / HOLD)                           |
|    - 步骤 2.3: CPU 结束当前访存周期, 让出总线, 返回总线响应 (BUS ACK / HLDA)        |
|    - 步骤 2.4: DMAC 接管总线, 驱动地址总线 (MAR) 与读写控制线 (MEMR/MEMW)          |
|    - 步骤 2.5: 数据在设备接口与主存之间直接高速传输                                  |
|    - 步骤 2.6: MAR 自动递增, CR 自动减 1; DMAC 释放总线                             |
|    - 步骤 2.7: 重复 2.1~2.6, 直至 CR 计数减至 0                                     |
+-------------------------------------------------------------------------------------+
                                          |
                                          v
+-------------------------------------------------------------------------------------+
| 3. 后处理阶段 (软件控制, CPU 主导)                                                    |
|    - CR 减至 0, DMAC 硬件产生中断请求信号 (INTR) 发送给 CPU                          |
|    - CPU 响应中断, 保护当前断点, 转入执行 "DMA 结束中断服务程序"                    |
|    - 中断服务程序测试设备状态、校验数据完整性 (如 CRC/ECC)、释放缓冲区               |
|    - 唤醒等待该 I/O 的进程, 恢复现场, 返回被中断的程序                              |
+-------------------------------------------------------------------------------------+
```

## 5. DMA 传送的三种总线控制方式深度解析
根据 DMAC 占用主存总线方式的不同，系统通常支持以下三种工作模式：

### 1) 停止 CPU 访存方式（Burst / 突发块传送）
- 机制：当外设发出 DMA 请求后，DMAC 申请总线并获得控制权。在整个数据块（如 512 字节甚至更大）传送结束之前，DMAC 持续垄断系统总线，CPU 完全被排斥在总线访问之外。
- 适用场景：外设传送速率极高、外设内部缓冲区较大（能快速填满并以总线极限带宽倾倒）的专用系统。
- 优缺点：
  - 优点：硬件控制极其简单，数据块传送速度达到总线物理极限。
  - 缺点：严重损害 CPU 吞吐能力。在漫长的总线霸占期内，CPU 无法访存取指，只能依赖指令 Cache 运行；一旦发生 Cache 缺失，CPU 彻底陷入挂起等待。

### 2) 周期挪用 / 周期窃取方式（Cycle Stealing）
- 机制：外设每准备好一个总线传送单元（如一个字、双字或一个小数据包），DMAC 便申请挪用一个主存访存周期（Memory Cycle）。在该周期内传送一个单元，传送结束后立刻归还总线。在下一次数据准备好之前，总线完全交由 CPU 使用。
- CPU 与 DMA 访存冲突分析（408 核心重点）：
  1. CPU 此时不访存：CPU 正在执行片内 ALU 操作或寄存器移位，无需使用系统总线。此时 DMA 挪用总线对 CPU 零干扰，双方完全并行。
  2. CPU 正在访存：DMAC 必须等待当前访存周期执行完毕，然后紧随其后挪用下一个总线周期。
  3. CPU 与 DMA 同时发出访存请求：总线仲裁器判定 **DMA 优先级高于 CPU**。DMA 抢占该访存周期，CPU 被迫推迟一个访存周期。
- 优缺点：
  - 优点：兼顾高速外设的数据流防溢出与 CPU 的连续计算能力，是通用计算机中最广泛采用的模式。
  - 缺点：每个周期都需要进行一次总线申请与释放，总线握手控制开销略大于突发模式。

### 3) DMA 与 CPU 交替访存方式（Alternating Mode / 分时互补）
- 机制：将一个 CPU 工作周期划分为前后两个微周期。前半周期 $T_1$$ \text{专属于 CPU 访存，后半周期} $$T_2$ 专属于 DMA 访存。总线控制权通过硬件时钟严密切分，双方各执一半。
- 硬件前提：主存的物理存取周期必须小于或等于 CPU 时钟周期的一半（即主存速度是 CPU 访存需求速度的两倍以上）。
- 优缺点：
  - 优点：无需总线申请、仲裁与握手机制，CPU 与 DMA 零冲突、零等待，硬件并行度最高。
  - 缺点：对主存硬件工艺及总线时钟分配要求极其严苛；若外设无数据传送，后半周期 $T_2$ 存在主存带宽浪费。

```text
[三种 DMA 总线占用模式工作时序对比]

1. 停止 CPU 访存方式 (Burst Mode):
总线: [ DMA 独占连续传送整块数据 (如 100 个周期) ] -> [ CPU 恢复访存 ]
CPU : [=========== CPU 挂起等待 ===============] -> [ 正常执行   ]

2. 周期挪用方式 (Cycle Stealing):
总线: [DMA] [CPU] [CPU] [DMA] [CPU] [CPU] [CPU] [DMA] [CPU] ...
说明: 外设准备好一个字时挪用 1 个周期，其余周期全部由 CPU 正常访存。

3. 交替访存方式 (Alternating Mode):
时钟: |-- T1 --|-- T2 --|-- T1 --|-- T2 --|-- T1 --|-- T2 --|
总线: [  CPU  |  DMA  |  CPU  |  DMA  |  CPU  |  DMA  ]
说明: 前半周期给 CPU，后半周期给 DMA，硬件硬切分，无需仲裁。
```

## 6. DMA 请求与中断请求的深层机制对比
DMA 请求与中断请求是计算机体系结构中两类本质截然不同的异步事件请求，408 历年常在此处设立混淆陷阱。

### 1) 本质区别全方位对比
- 请求目的不同：
  - DMA 请求是向总线仲裁机构（或 CPU）申请**总线控制权**，目的是使用总线进行硬件级的数据搬运。
  - 中断请求是向 CPU 申请**程序执行权（CPU 时间片）**，目的是使 CPU 挂起当前任务转去执行特定的软件服务程序。
- 响应时刻与边界不同：
  - DMA 请求的响应边界是**机器周期（总线访存周期）结束**。因为只要当前总线访存动作完成，总线处于空闲态，总线控制权便可立即安全移交，无需等待整条指令执行结束。
  - 中断请求的响应边界是**当前指令执行周期结束**（即指令边界）。CPU 必须保证单条指令执行的原子性，在取指、译码、执行阶段均不响应外部中断，唯有在执行阶段结束、进入中断查询微操作时方可响应。
- 处理过程与开销不同：
  - DMA 数据传送由 DMAC 硬件状态机自主控制，不经过寄存器入栈出栈，CPU 无任何软件开销。
  - 中断处理必须由 CPU 运行中断服务程序，涉及保存断点、保护现场、关中断、开中断、恢复现场等多重步骤，软件开销大。

### 2) 优先级拓扑成因剖析
在系统总线仲裁和硬件排队机制中，**DMA 请求的优先级必然高于中断请求，也高于 CPU 自身的访存请求**。
- 核心成因：
  高速 I/O 设备（如旋转中的磁盘、百兆/千兆网卡）的数据流由物理机械运动或通信物理介质严格驱动，具有不可逆的硬实时特性。以磁盘读盘为例，磁头下方记录的磁介质以 7200 rpm 的恒定高速旋转划过。当控制器内部数据缓冲区被填满时，DMA 控制器必须在下一个字划过磁头之前获得总线并将数据转存入主存；如果被推迟响应，后续数据将强行覆盖缓冲区，导致硬件级数据丢失错误（Data Overrun）。
  反之，CPU 内部具备硬件流水线暂停机制与各级 Cache 缓冲，CPU 访存被推迟一个或几个周期仅仅引起指令流水线的短暂阻塞，绝对不会引起系统状态破坏或物理数据丢失；中断请求若延迟若干时钟周期响应，也仅仅是降低了响应延迟指标，数据依然安全保留在外设接口缓冲区中。因此，从保障数据完整性的物理底线出发，DMA 请求必须享有最高优先级。

## 7. DMA 传送中的主存与 Cache 一致性维护
现代计算机广泛采用层次化存储体系，主存之上存在 L1、L2、L3 高速缓存（Cache）。由于 DMA 绕过 CPU 直接读写主存储器，由此引发了严峻的 Cache 一致性问题（Cache Coherence Problem）：

```text
[DMA 写入主存导致的不一致]
CPU 试图读取物理地址 A 的数据:
1. Cache 中已存在 A 的旧副本 (Stale Data)。
2. DMA 控制器直接将外设新数据写入主存地址 A。
3. 主存中的 A 已更新，但 Cache 中的 A 仍为旧值。
4. CPU 随后访问 A 时 Cache 命中，读取到了过期的错误数据。

[DMA 从主存读出导致的不一致]
外设试图通过 DMA 读取物理地址 B 的数据:
1. CPU 曾修改了地址 B 的数据，写入策略为写回法 (Write-Back)。
2. 最新数据只停留在 Cache 行中 (Dirty Line)，尚未被写回物理主存。
3. DMA 控制器直接从主存读取地址 B 的数据。
4. DMA 读出了过期的脏数据并发送给了外设。
```

### 解决方案与硬件支持：
1. 硬件总线监听机制（Bus Snooping / 硬件一致性协议）：Cache 控制器持续监听系统总线。当检测到 DMA 写总线事务命中本地 Cache 行时，硬件强制将该 Cache 行置为无效（Invalid）；当检测到 DMA 读总线事务命中本地 Cache 的“脏”行时，Cache 控制器截获总线请求，优先将 Cache 脏数据写回主存，再允许 DMA 读取。
2. 软件冲刷机制（Software Flush / Invalidation）：由操作系统设备驱动程序在 DMA 启动前显式发出指令（如 x86 的 `clflush` 或 ARM 的 Cache 清除指令），强行将发送缓冲区的脏 Cache 写回主存，或将接收缓冲区的 Cache 行无效化。
3. 一致性 DMA 缓冲区分配（Coherent DMA Buffer）：操作系统将一段专用于 DMA 传输的物理内存页在页表中配置为“Cache 禁止”（Uncacheable / Non-cacheable），CPU 对该区域的任何读写直接绕过 Cache 穿透到主存，从根本上杜绝不一致。

## 1. 2017 年第 32 题：DMA 控制操作时序
### 题干与设问
系统将数据从磁盘读到内存的过程包括以下操作：  
① DMA 控制器发出中断请求  
② 初始化 DMA 控制器并启动磁盘  
③ 从磁盘传输一块数据到内存缓冲区  
④ 执行“DMA 结束”中断服务程序  
正确的执行顺序是（ ）。  
A. ③→①→②→④  
B. ②→③→①→④  
C. ②→①→③→④  
D. ①→②→④→③  

### 详细解析
- 解题思路：
  DMA 传送生命周期严格划分为预处理、数据传送、后处理三个阶段。
  - 第一步（预处理）：CPU 通过设备驱动程序向 DMA 控制器写入主存首地址、传送块大小以及读控制字，并向磁盘控制器发送寻道与启动命令，对应操作 ②。
  - 第二步（数据传送）：磁盘驱动器定位扇区后，DMA 控制器接管总线，控制将该磁盘数据块直接传输到主存缓冲区中，期间 CPU 与 DMA 并行工作，对应操作 ③。
  - 第三步（传送结束触发）：整块数据传送完毕，DMA 控制器的字计数器减至 0，DMA 控制器向 CPU 发出中断请求信号，对应操作 ①。
  - 第四步（后处理）：CPU 响应中断，暂停当前任务，转入执行“DMA 结束”中断服务程序，完成状态检验与资源释放，对应操作 ④。
  因此严格正确的执行时序为：②→③→①→④。
- 选项剖析：
  A 选项缺少前置的初始化与启动配置，违背硬件启动逻辑；C 选项在数据未传送完成（③之前）就由 DMA 控制器发出中断，混淆了中断的触发条件；D 选项更是逻辑倒置。
- 正确答案：**B**

## 2. 2019 年第 22 题：DMA 机制与软硬件分工辨析
### 题干与设问
下列关于 DMA 方式的叙述中，正确的是（ ）。  
Ⅰ. DMA 传送前由设备驱动程序设置传送参数  
Ⅱ. 数据传送前由 DMA 控制器请求总线使用权  
Ⅲ. 数据传送由 DMA 控制器直接控制总线完成  
Ⅳ. DMA 传送结束后的处理由中断服务程序完成  
A. 仅 Ⅰ、Ⅱ  
B. 仅 Ⅰ、Ⅲ、Ⅳ  
C. 仅 Ⅱ、Ⅲ、Ⅳ  
D. Ⅰ、Ⅱ、Ⅲ、Ⅳ  

### 详细解析
- 解题思路：
  本题考查 DMA 预处理、数据传送、后处理三阶段的软硬件协同细节。
  - 命题 Ⅰ 正确：DMA 传送开始前的预处理工作必须由操作系统底层的设备驱动程序执行。驱动程序向上封装抽象接口，向下直接操作硬件 I/O 端口，负责向 DMA 控制器的 MAR、CR、CSR 等寄存器写入参数。用户程序不能直接操控硬件。
  - 命题 Ⅱ 正确：在数据传送阶段，外设接口准备好数据后，必须由 DMA 控制器向总线仲裁机构（或 CPU）发出总线请求（BUS REQ）信号，获得总线控制权后方可驱动主存地址和控制线。
  - 命题 Ⅲ 正确：获得总线授权后，系统数据总线、地址总线和读写控制总线的主控权完全归 DMA 控制器所有，数据在设备与主存间直传，无需 CPU 介入指令执行。
  - 命题 Ⅳ 正确：当整块数据传送结束时，传送长度计数器溢出，由 DMAC 硬件触发中断请求，CPU 响应后执行“DMA 结束中断服务程序”，负责校验数据、更新页表及驱动状态等后处理工作。
- 选项剖析：
  四个命题叙述均准确无误，考查内容涵盖 DMA 的全部阶段。
- 正确答案：**D**

## 3. 2020 年第 22 题：周期挪用 DMA 机制与 CPU 访存并发性
### 题干与设问
若设备采用周期挪用 DMA 方式进行输入输出，每次 DMA 传送的数据块大小为 512 字节，相应的 I/O 接口中有一个 32 位数据缓冲寄存器，对于数据输入过程，下列叙述中错误的是（ ）。  
A. 每准备好 32 位数据，DMA 控制器就发出一次总线请求  
B. 相对于 CPU，DMA 控制器的总线使用权的优先级更高  
C. 在整个数据块的传送过程中，CPU 不可以访问主存储器  
D. 数据块传送结束时，会产生“DMA 传送结束”的中断请求  

### 详细解析
- 解题思路：
  本题重点考查“周期挪用（Cycle Stealing）”与“停止 CPU 访存（Burst Mode）”的本质区别。
  - A 选项正确：I/O 接口中的数据缓冲寄存器（DR）为 32 位（4 字节）。在输入过程中，外设以较慢速度向 DR 填充数据，一旦 32 位数据装配完毕，DMA 控制器立即发出一次总线请求，申请占用一个总线周期将这 32 位数据写入主存。
  - B 选项正确：为了防止高速外设缓冲区发生数据溢出（Overrun），总线仲裁器赋予 DMA 控制器高于 CPU 的总线主控优先级。当两者同时请求总线时，DMA 优先获得使用权。
  - C 选项错误（符合题意）：周期挪用方式的核心特征在于“分时窃取”。DMA 仅在外设准备好一个字（32 位）的离散时点挪用一个总线访存周期。在数据块传输的绝大部分时间内，外设正在准备下一个 32 位数据，总线完全处于 CPU 控制之下，CPU 可以正常访问主存取指或读写数据。只有在“停止 CPU 访存”模式下，CPU 才在整个数据块传输期间被完全剥夺访存权。
  - D 选项正确：整块数据（512 字节，共计 $512 / 4 = 128$ 次挪用）全部传送完毕后，传送计数器减至 0，DMA 控制器发出“DMA 传送结束”中断请求，通知 CPU 转入后处理。
- 正确答案：**C**

## 4. 2022 年第 44 题：磁盘参数模型与周期挪用 DMA 综合大题
### 题干与设问
假设某磁盘驱动器中有 4 个双面盘片，每个盘面有 20000 个磁道，每个磁道有 500 个扇区，每个扇区可记录 512 字节的数据，盘片转速为 7200 rpm（转/分），平均寻道时间为 5 ms，请回答下列问题。  
(1) 每个扇区包含数据及地址信息，地址信息分为 3 个字段，这 3 个字段的名称是什么？对于该磁盘，各字段至少占多少位？  
(2) 一个扇区的平均访问时间约为多少？  
(3) 若采用周期挪用 DMA 方式进行磁盘与主机之间的数据传送，磁盘控制器中的数据缓冲区大小为 64 位，则在一个扇区读写过程中，DMA 控制器向 CPU 发送了多少次总线请求？若 CPU 检测到 DMA 控制器的总线请求信号时也需要访问主存，则 DMA 控制器是否可以获得总线使用权？为什么？  

### 详细推导与规范解答
#### 第 (1) 问解析：
- 字段名称：CHS（Cylinder-Head-Sector）物理地址体系的 3 个字段分别为**柱面号（或磁道号）**、**磁头号（或盘面号）**、**扇区号**。
- 位数推导计算：
  - 柱面数等于每个盘面的磁道数，即 20000 个柱面。柱面号字段位数至少为：
    $$ \text{\lceil \log_2 20000 \rceil = 15 \text{ 位} \quad (2^{14} = 16384 < 20000 \le 32768 = 2^{15})} $$
  - 磁头数等于总盘面数。磁盘包含 4 个双面盘片，盘面总数为 $4 \times 2 = 8$ 个。磁头号字段位数至少为：
    $$ \text{\log_2 8 = 3 \text{ 位}} $$
  - 每个磁道包含 500 个扇区。扇区号字段位数至少为：
    $$ \text{\lceil \log_2 500 \rceil = 9 \text{ 位} \quad (2^8 = 256 < 500 \le 512 = 2^9)} $$

#### 第 (2) 问解析：
- 一个扇区的平均存取时间（$T_{\text{access}}$）由三部分构成：
  $$T_{\text{access}} = T_{\text{seek}} + T_{\text{rot}} + T_{\text{trans}}$$
- 参数计算：
  - 平均寻道时间 $T_{\text{seek}} = 5 \text{ ms}$（题干直接给出）。
  - 盘片转速为 7200 rpm，旋转一周耗时：
    $$t_{\text{round}} = \frac{60 \text{ s}}{7200} = \frac{60 \times 10^3 \text{ ms}}{7200} = \frac{25}{3} \text{ ms} \approx 8.33 \text{ ms}$$
  - 平均旋转延迟时间（转过半圈的时间）：
    $$T_{\text{rot}} = \frac{t_{\text{round}}}{2} = \frac{8.333 \text{ ms}}{2} \approx 4.17 \text{ ms}$$
  - 一个扇区的数据传输时间（扇区划过磁头下方的时间）：
    $$T_{\text{trans}} = \frac{t_{\text{round}}}{500} = \frac{8.333 \text{ ms}}{500} \approx 0.0167 \text{ ms} = 16.67\ \mu\text{s}$$
- 平均访问时间总计：
  $$T_{\text{access}} = 5 + 4.167 + 0.0167 \approx 9.18 \text{ ms}$$

#### 第 (3) 问解析：
- 总线请求次数计算：
  每个扇区记录的数据量为 512 字节。
  磁盘控制器中的数据缓冲区大小为 64 位，即：
  $$ \text{B_{\text{buffer}} = \frac{64 \text{ bit}}{8 \text{ bit/B}} = 8 \text{ 字节}} $$
  在采用周期挪用 DMA 方式读写一个扇区时，缓冲区每填满 8 字节，DMA 控制器就发出一次总线请求，因此总线请求次数为：
  $$ \text{N_{\text{req}} = \frac{512 \text{ B}}{8 \text{ B}} = 64 \text{ 次}} $$
- 总线控制权仲裁与原因分析：
  - 仲裁结论：**DMA 控制器可以获得总线使用权**。
  - 成因分析：
    在系统总线仲裁机制中，DMA 控制器的总线请求优先级高于 CPU 访存请求优先级。
    这是因为磁盘处于高速机械连续旋转中，扇区数据以固定速率源源不断划过磁头，数据产生具有严格的实时性要求。若 DMA 请求得不到及时响应，磁盘控制器的数据缓冲区（64 位）将在极短时间内被后续扇区数据冲刷覆盖，发生硬件缓冲区溢出错误（Data Overrun），造成数据不可逆丢失，迫使磁盘重新旋转一周甚至引发 I/O 异常。
    而 CPU 内部具备指令缓存与流水线等待机制，CPU 暂停一个访存周期仅会带来微小的流水线停顿，不会破坏系统状态或丢失数据。因此硬件系统设计中 DMA 控制器优先获得总线使用权。

## 5. 2024 年第 22 题：DMA 数据传输通路
### 题干与设问
DMA 方式中，DMA 控制器控制的数据传输通路位于（ ）。  
A. CPU 和主存之间

D. 设备接口和 DMA 控制器之间  

### 详细解析

  - D 选项仅为外设到 DMAC 内部缓冲的局部通路，忽略了最终落盘/落存的主存端点。

## 6. 2025 年第 21 题：DMA 适用外设选型
### 题干与设问
下列设备中，适合采用 DMA 输入输出的设备是（ ）。  
Ⅰ. 键盘  
Ⅱ. 网卡  
Ⅲ. 固态硬盘  
Ⅳ. 针式打印机  
A. Ⅰ、Ⅱ  
B. Ⅱ、Ⅲ  
C. Ⅱ、Ⅳ  
D. Ⅲ、Ⅳ  

### 详细解析
- 解题思路：
  I/O 控制方式的选择本质上取决于设备的数据传输速率、传输粒度以及对 CPU 开销的容忍度：
  - 键盘（Ⅰ）：极低速字符输入设备。按键触发频率极低（每秒几次），数据量极小（一次 1 字节），采用程序中断方式即可轻松处理，中断开销占 CPU 比例忽略不计，无须配置复杂的 DMA 控制器。
  - 针式打印机（Ⅳ）：机械式慢速字符输出设备。打印头机械运动速度极慢，数据吞吐量低，通常采用中断或查询方式，不属于高速块设备。
  - 网卡（Ⅱ）：高速网络通信设备。现代以太网速率普遍达到千兆（1 Gbps）乃至万兆（10 Gbps），每秒需要吞吐数以万计的数据包。若采用中断方式，CPU 将被海量中断彻底压垮，必须采用 DMA 控制器将网络数据包直接在网卡 FIFO 与主存网卡环形缓冲区（Ring Buffer）之间高速投递。
  - 固态硬盘（SSD，Ⅲ）：现代高速块存储设备。采用 PCIe/NVMe 或 SATA 接口，连续读写速率可达数百 MB/s 至数 GB/s，数据传输以数据块（如 4 KB）为基本单位，属于典型的 DMA 高频重度应用场景。
- 正确答案：**B**

# 四、综合大题应用与考查拓展

在 408 统考综合应用大题（特别是第 43 题与第 44 题）中，DMA 往往不会孤立考查，而是与计算机系统各核心模块深度联动。考生需掌握以下四大核心综合应用模型与拓展考点：

## 1. 磁盘与周期挪用 DMA 综合定量分析模型
综合题常将磁盘存储器的物理参数（转速、扇区数、扇区容量）与周期挪用 DMA 的总线占用率深度绑定考查。

### 核心公式推导体系：
1. 磁盘旋转一周时间：
   $$ \text{t_{\text{round}} = \frac{60}{R} \text{ (秒)} = \frac{60 \times 10^3}{R} \text{ (毫秒)}} $$
   （其中 $R$ 为磁盘转速，单位为 rpm）
2. 磁道数据传输率（道速率 $D_R$）：
   $$ \text{D_R = \frac{\text{单磁道数据量}}{t_{\text{round}}} = \frac{N_{\text{sector}} \times S_{\text{size}}}{t_{\text{round}}}} $$
   （其中 $N_{\text{sector}}$$ \text{为单磁道扇区数，} $$S_{\text{size}}$ 为单扇区字节数）
3. DMA 周期挪用请求的时间间隔 $T_{\text{req}}$：
   设 DMA 控制器内部数据缓冲区大小为 $B_{\text{buf}}$（字节），则外设装满该缓冲区所需时间为：
   $$T_{\text{req}} = \frac{B_{\text{buf}}}{D_R}$$
4. 总线占用比率与 CPU 效率损失：
   设总线时钟周期为 $\tau$$ \text{，完成一次总线读写（挪用一次总线）需消耗} $$k$$ \text{个总线周期（即挪用时间为} $$t_{\text{bus}} = k \cdot \tau$）。
   则 DMA 传输期间，总线利用率（DMA 占用带宽比例）为：
   $$\eta = \frac{t_{\text{bus}}}{T_{\text{req}}} = \frac{k \cdot \tau}{B_{\text{buf}} / D_R}$$
   CPU 因总线被挪用而损失的访存带宽即为 $\eta$。

## 2. 硬件缓冲防溢出临界延迟（Overrun Limit）分析
在实时 I/O 大题中，常考察总线仲裁延迟对硬件安全的影响：
- 设外设输入数据流速为 $D_R$$ \text{，DMA 缓冲区容量为} $$B_{\text{buf}}$。
- 临界响应时间上限：从外设发出 DMA 请求开始，到该次数据传输首字节真正被读走移入主存，系统总线仲裁机构允许的最大延迟时间 $t_{\text{latency}}$ 必须满足：
  $$t_{\text{latency}} \le \frac{B_{\text{buf}}}{D_R}$$
- 若由于总线拥堵或 CPU 长时间关总线导致响应时间超过此阈值，外设新送入的数据将强行冲毁缓冲区未移出的数据，造成不可恢复的 Data Overrun 硬件故障。此即 2022#44 所考查的“DMA 仲裁必须具有最高优先级”的本质物理约束。

## 3. DMA 与中断全系统 CPU 开销对比模型
设系统需要向主存读入一个大小为 $N$$ \text{字节的数据块，总线宽度为} $$W$$ \text{字节（每次传输} $$W$$ \text{字节），CPU 主频为} $$f$。

```text
[中断方式 CPU 总开销]
- 触发中断次数: M = N / W
- 每次中断开销: 保存现场 (Ts) + 执行中断服务程序 (Tserv) + 恢复现场 (Tr)
- 总 CPU 耗时: T_INT = M * (Ts + Tserv + Tr)
- 特点: 开销与传输数据规模 N 呈严格线性正比 O(N)，N 极大时 CPU 完全瘫痪。

[DMA 方式 CPU 总开销]
- 预处理开销: CPU 执行驱动写入配置寄存器耗时 T_pre (固定指令条数, 与 N 无关)
- 数据传送开销: 硬件自主完成, CPU 耗时为 0 (若采用周期挪用, CPU 仅损失微小的总线等待时间)
- 后处理开销: 整块传完后触发 1 次中断, 执行 DMA 结束中断服务程序耗时 T_post
- 总 CPU 耗时: T_DMA = T_pre + T_post
- 特点: 开销与传输数据规模 N 解耦, 呈常数级 O(1)。
```

## 4. 体系结构考查拓展：现代 Scatter-Gather DMA 与零拷贝
在软硬件结合及操作系统综合考察中，考生应关注现代体系结构中 DMA 的进阶实现：

### 1) 分散 - 聚集 DMA（Scatter-Gather DMA）
- 痛点：传统 DMA 控制器要求主存地址必须在物理内存上严格连续。但在虚拟存储管理系统下，用户空间的虚拟内存页虽然逻辑连续，但在物理内存中往往被分散分配在各个离散的物理页框（Page Frame）中。若采用传统 DMA，操作系统必须先通过 CPU 将分散的数据逐页拷贝到一块连续的物理内核缓冲区中，造成严重的 CPU 浪费。
- 硬件机制：Scatter-Gather DMA 控制器内部引入了链表解析引擎。驱动程序在内存中构建由**描述符（Descriptor）**组成的链表或环形队列（Ring Buffer），每个描述符记录一个离散物理块的起始地址与长度。DMAC 硬件自动根据链表指针（Next Pointer）依次抓取物理块并完成传送，无需 CPU 参与内存重组。

### 2) 零拷贝技术（Zero-Copy）中的 DMA 应用
在 Linux `sendfile()` 或网络数据转发中，传统 I/O 涉及 4 次数据拷贝与 4 次上下文切换。借助现代 DMA（尤其是带协议校验和卸载的 Scatter-Gather DMA），可以实现零拷贝：
1. 磁盘 DMA 将数据直接读入内核页高速缓存（Page Cache）。
2. 内核将包含内存物理地址和长度的缓冲区描述符传递给网卡队列。
3. 网卡 DMA 控制器直接根据描述符从内核页高速缓存抓取数据发送至网络。
4. 全程无 CPU 数据搬运，数据在主存中仅保留单份副本。

## 1. DMA 方式与程序中断方式核心对比表
| 对比维度 | 程序中断方式 | DMA 方式 |
| :--- | :--- | :--- |
| **数据传输控制者** | CPU 软件（中断服务程序） | DMA 控制器（纯硬件状态机） |
| **总线主控权归属** | 全程归 CPU 控制 | 数据传送阶段归 DMA 控制器所有 |
| **数据传输通路** | 外设 $\leftrightarrow$$ \text{CPU 内部寄存器} $$\leftrightarrow$$ \text{主存 | 外设接口} $$\leftrightarrow$ 主存储器（绕过 CPU） |
| **硬件系统代价** | 仅需简单接口中断触发逻辑 | 需复杂的 DMA 控制器、总线仲裁机构 |
| **数据传送基本单位** | 字（Word）或字节（Byte） | 数据块（Block，如扇区、页、帧） |
| **请求响应时机** | **当前指令执行周期结束**（指令边界） | **当前总线机器周期结束**（访存周期边界） |
| **硬件仲裁优先级** | 低于 DMA 请求 | **高于中断请求，高于 CPU 访存请求** |
| **CPU 介入时点** | 传送每个字/字节均全程参与 | 仅在预处理（开始前）与后处理（结束后）介入 |
| **适用外设类型** | 中低速、字符型设备（键盘、鼠标） | 高速、块型设备（磁盘、SSD、网卡） |

## 2. 三种 DMA 传送方式关键特征速查表
| 传送方式 | 总线控制权占用机制 | CPU 访存状态 | 硬件实现难度 | 典型适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **停止 CPU 访存** | DMA 独占总线直到整块传完 | CPU 无法访存，陷入挂起等待 | 简单 | 高速外设成组突发传输、专用处理机 |
| **周期挪用** | 准备好一个字时挪用 1 个总线周期 | 外设准备数据期间 CPU 正常访存 | 中等 | 通用计算机主流标准，平衡外设与 CPU |
| **交替访存** | 一个时钟周期均分为 CPU 与 DMA 两半 | CPU 访存完全不被打断，零冲突 | 极高（需超高速主存） | 主存存取周期远小于 CPU 时钟周期的系统 |

## 3. 核心速算公式集锦
- **DMA 请求总线次数**：
  $$ \text{N_{\text{req}} = \frac{\text{待传数据总量 (字节)}}{\text{DMA 内部缓冲寄存器容量 (字节)}}} $$
- **外设装满 DMA 缓冲时间（DMA 请求间隔）**：
  $$ \text{T_{\text{interval}} = \frac{\text{DMA 缓冲容量 (Byte)}}{\text{外设数据传输速率 (Byte/s)}}} $$
- **总线占用率（带宽开销）**：
  $$ \text{\eta = \frac{\text{单次 DMA 占用总线时长}}{T_{\text{interval}}}} $$
- **磁盘扇区 CHS 编码位数要求**：
  $$ \text{总位数} = \lceil \log_2(\text{柱面数}) \rceil + \lceil \log_2(\text{磁头数}) \rceil + \lceil \log_2(\text{单磁道扇区数}) \rceil $$

## 4. 408 考场高频陷阱与判断口诀
1. **指令边界 vs 周期边界**：
   - 看到“中断响应”，必找“指令执行阶段结束”。
   - 看到“DMA 响应”，必找“总线周期（机器周期）结束”。
2. **总线优先级 vs 中断优先级**：
   - 总线仲裁上 DMA 绝对优先于 CPU，其核心原因只有一个：**防止高速外设缓冲区溢出丢失数据**。
3. **数据通路 vs 控制通路**：
   - DMA 的控制命令由 CPU 传给 DMAC（控制通路）；
   - DMA 的真实数据流直接在**设备接口与主存**之间传递，绝对不走 CPU（数据通路）。
4. **中断存在性误区**：
   - DMA 方式并非完全不需要中断！数据传送过程不需要中断，但**整块传送结束时的后处理阶段必须依赖中断**通知 CPU 收尾。
5. **周期挪用与 CPU 访存冲突误区**：
   - 周期挪用下，CPU 并不是完全不能访存，只有在 DMA 真正发起总线访问的那一个特定时钟周期，CPU 才被推迟；其余时间 CPU 正常访存。
