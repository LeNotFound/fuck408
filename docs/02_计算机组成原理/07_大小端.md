## 二、具体考察内容

### 1. 核心概念与硬件基础

现代计算机系统通常以**字节（Byte，8 位）**为基本编址单位。然而，计算机硬件处理的数据往往由多个字节构成，例如 16 位整数（`short`，2 字节）、32 位整数（`int`，4 字节）、64 位整数/浮点数（`long long` / `double`，8 字节）以及指令编码中的多字节操作码、寻址偏移量和立即数。

当一个多字节数据存放在主存中时，它必然占据多个连续的字节编址单元。该数据所占内存区域的**最小地址**定义为该数据的**基地址（Base Address）**或**首地址**。

#### (1) 最高有效字节与最低有效字节
对于一个长度为 $n$ 字节的无符号或有符号整数：
$$X = b_{n-1} b_{n-2} \cdots b_1 b_0$$
- **最高有效字节（Most Significant Byte, MSB）**：位于数值权值最高的字节，即 $b_{n-1}$。
- **最低有效字节（Least Significant Byte, LSB）**：位于数值权值最低的字节，即 $b_0$。

例如，32 位十六进制数 $12345678\text{H}$：
- $\text{MSB} = 12\text{H}$（权值为 $2^{24}$）
- 次高字节 $= 34\text{H}$（权值为 $2^{16}$）
- 次低字节 $= 56\text{H}$（权值为 $2^{8}$）
- $\text{LSB} = 78\text{H}$（权值为 $2^{0}$）

#### (2) 大端模式（Big-Endian）
- **定义**：多字节数据的**最高有效字节（MSB）存放在低地址端**，**最低有效字节（LSB）存放在高地址端**。
- **内存映射规律**：数据的高位在低地址，数据的低位在高地址。
- **直观认知**：内存地址从低到高递增时，字节排列顺序与人类书写、阅读十六进制数的从左至右自然顺序完全一致。

#### (3) 小端模式（Little-Endian）
- **定义**：多字节数据的**最低有效字节（LSB）存放在低地址端**，**最高有效字节（MSB）存放在高地址端**。
- **内存映射规律**：数据的低位在低地址，数据的高位在高地址。
- **直观认知**：符合硬件逻辑设计。在 ALU 执行加法等算术运算时，数据是从低位向高位逐位进位运算的，小端模式使得硬件可以直接从低地址提取低位字节开始运算，简化寻址与进位逻辑。

#### (4) 大端与小端内存存放对照图
假定 32 位机器数 $12345678\text{H}$ 存放在首地址为 $00008000\text{H}$ 的主存区域中：

```
+---------------+-------------------+-------------------+
| 主存物理地址  | 大端模式存放内容  | 小端模式存放内容  |
+---------------+-------------------+-------------------+
| 0000 8000H    | 12H (MSB)         | 78H (LSB)         |
| 0000 8001H    | 34H               | 56H               |
| 0000 8002H    | 56H               | 34H               |
| 0000 8003H    | 78H (LSB)         | 12H (MSB)         |
+---------------+-------------------+-------------------+
```

### 3. 数据类型、数组、指针与大小端映射

#### (1) 基本数据类型存储宽度
在标准 32 位或 64 位考研 408 上下文中，基本 C 语言数据类型的存储宽度如下：
- `char`: 1 字节（8 位）
- `short`: 2 字节（16 位）
- `int`, `float`: 4 字节（32 位）
- `long long`, `double`: 8 字节（64 位）
- 指针类型: 32 位系统占 4 字节，64 位系统占 8 字节

#### (2) 数组的存放特性与陷阱
- **重要规则**：数组内部元素的存放顺序**不受大小端模式影响**！
- 数组下标 $0$ 的元素 `a[0]` 永远存放在最低地址端，`a[1]` 紧随其后存放在更高地址端。
- **大小端模式仅仅改变每个元素内部多字节的字节排列方式**，绝对不颠倒数组元素之间的先后顺序！

例如定义整型数组 `int arr[2] = {0x12345678, 0x9ABCDEF0};`，首地址为 $00001000\text{H}$：

```
+---------------+--------------------+--------------------+
| 内存地址      | 大端模式存放字节   | 小端模式存放字节   | 所属数组元素与说明 |
+---------------+--------------------+--------------------+
| 0000 1000H    | 12H                | 78H                | arr[0] 内部字节 0  |
| 0000 1001H    | 34H                | 56H                | arr[0] 内部字节 1  |
| 0000 1002H    | 56H                | 34H                | arr[0] 内部字节 2  |
| 0000 1003H    | 78H                | 12H                | arr[0] 内部字节 3  |
| 0000 1004H    | 9AH                | F0H                | arr[1] 内部字节 0  |
| 0000 1005H    | BCH                | DEH                | arr[1] 内部字节 1  |
| 0000 1006H    | DEH                | BCH                | arr[1] 内部字节 2  |
| 0000 1007H    | F0H                | 9AH                | arr[1] 内部字节 3  |
+---------------+--------------------+--------------------+
```

#### (3) 字符串（字符数组）的非倒置特性
- 字符串在 C 语言中本质是 `char` 数组，每个字符仅占 1 字节（如 ASCII 码）。
- 因为每个元素自身只有 1 字节，不存在“多字节内部高低位颠倒”的问题。
- 字符串 `"ABCD"`（ASCII 码分别为 $41\text{H}, 42\text{H}, 43\text{H}, 44\text{H}$）在大端和小端机器中的存放顺序**完全相同**：
  - 地址 $00\text{H}: 41\text{H}$ (`'A'`)
  - 地址 $01\text{H}: 42\text{H}$ (`'B'`)
  - 地址 $02\text{H}: 43\text{H}$ (`'C'`)
  - 地址 $03\text{H}: 44\text{H}$ (`'D'`)
  - 地址 $04\text{H}: 00\text{H}$ (`'\0'`)

#### (4) 指针强制类型转换的底层机理
当使用 C 语言指针进行强制类型转换时，指针所保存的**内存地址数值并未改变**，改变的是**解引用访存时读取的字节宽度和解析规则**。

假定 32 位机器中，变量 `int x = 0x12345678;` 存放在地址 $00002000\text{H}$：
- 在小端模式下：
  - 地址 $2000\text{H}\sim 2003\text{H}$ 分别存放：`78H`, `56H`, `34H`, `12H`。
  - 若执行 `char *p = (char*)&x;`，则 `*p` 读取地址 $2000\text{H}$ 处单字节，得到十六进制值 `0x78`。
  - 若执行 `short *p = (short*)&x;`，则 `*p` 读取地址 $2000\text{H}\sim 2001\text{H}$ 两个字节，按小端重组为 `0x5678`。
- 在大端模式下：
  - 地址 $2000\text{H}\sim 2003\text{H}$ 分别存放：`12H`, `34H`, `56H`, `78H`。
  - 执行 `char *p = (char*)&x;`，`*p` 读取地址 $2000\text{H}$ 处单字节，得到十六进制值 `0x12`。
  - 执行 `short *p = (short*)&x;`，`*p` 读取地址 $2000\text{H}\sim 2001\text{H}$ 两个字节，按大端重组为 `0x1234`。

### 4. 边界对齐（Boundary Alignment）与存储管理

#### (1) 边界对齐的硬件动因
现代计算机的主存通常按多体交叉或总线宽度并行组织。在 32 位数据总线的系统中，CPU 每次向主存发起读写事务，硬件总线一次性并行传输 4 字节（32 位），且传输的物理地址必须是 4 的整数倍（即最低两位地址线固定为 $00\text{B}$）。

- **对齐存放（Aligned Access）**：数据的起始地址是其数据长度的整数倍。此时读取一个 32 位整数只需**1 次访存周期**。
- **非对齐存放（Unaligned Access）**：数据跨越了 4 字节自然边界。CPU 必须发起**2 次访存周期**，分别读取两个相邻的 4 字节对齐字，再通过微架构内部的移位拼接网络将目标数据拼合起来，导致访存性能成倍下降，甚至在某些精简指令集（如部分 ARM、RISC-V 核心）中直接抛出硬件对齐异常中断。

#### (2) 边界对齐三大规则
1. **成员自然对齐**：数据类型长度为 $k$ 字节（$k=1, 2, 4, 8$），其存放起始地址必须能被 $k$ 整除，即满足：
   $$\text{Address} \bmod k = 0$$
2. **结构体成员偏移对齐**：结构体第一个成员的偏移量为 0。后续各个成员的起始偏移地址必须是该成员自身大小与系统默认对齐模数两者中较小者的整数倍。若不满足，必须在上一个成员后填充空闲字节（Padding Bytes）。
3. **结构体总大小整体对齐**：结构体的总占用字节数必须是结构体内部**最大成员对齐模数的整数倍**。若不满足，必须在结构体末尾填充空闲字节。这是为了确保定义结构体数组时，后续每个数组元素都能严格满足其内部各成员的自然边界对齐要求。

```
结构体对齐计算流程：
[确定各成员大小] -> [计算成员自然对齐偏移量(不足则前向填充)] -> [求得末尾有效字节] -> [按最大对齐模数向上取整补齐]
```

### 5. 网络字节序与主机字节序转换

在计算机网络通信中，异构主机（如运行小端 x86 的客户端与运行大端架构的服务器/路由器）之间交换数据时，必须统一数据格式：
- **网络字节序（Network Byte Order）**：统一强制规定采用**大端模式（Big-Endian）**。所有在网络中传输的 IP 报头字段（如 16 位总长度、16 位端口号、32 位 IP 地址）均严格按大端字节序传输。
- **主机字节序（Host Byte Order）**：各个具体主机本地运行的字节序（如 x86 体系为小端）。
- **标准转换函数族**：
  - `htons()`：Host to Network Short（16 位主机序转网络序）
  - `htonl()`：Host to Network Long（32 位主机序转网络序）
  - `ntohs()`：Network to Host Short（16 位网络序转主机序）
  - `ntohl()`：Network to Host Long（32 位网络序转主机序）

若本地主机为大端架构，上述宏定义/函数为空操作；若本地主机为小端架构，则硬件通过执行字节交换指令（如 x86 汇编中的 `BSWAP` 指令）反转字节序列。

## 三、近十年真题精讲（2016~2025）

### 1. 2016 年 408 真题第 14 题

#### 【题干与选项】
某计算机字长为 32 位，按字节编址，采用小端（Little Endian）方式存放数据。假定有一个 `double` 型变量，其机器数表示为 `1122 3344 5566 7788H`，存放在 `0000 8040H` 开始的连续存储单元中，则存储单元 `0000 8046H` 中存放的是（ ）。  
A. `22H`  
B. `33H`  
C. `66H`  
D. `77H`  

#### 【考查方向】
本题考查 64 位双精度浮点数（`double`）在小端模式、按字节编址存储系统中的物理字节布局。

#### 【详细解析】
- **第一步：明确数据宽度与高低有效字节**  
  `double` 型变量在标准 C 语言与 IEEE 754 规范中占据 8 个字节（64 位）。  
  机器数为 `1122 3344 5566 7788H`，各字节权值从高到低依次为：
  - 最高有效字节（MSB）：`11H`
  - 次高字节序列：`22H`, `33H`, `44H`, `55H`, `66H`, `77H`
  - 最低有效字节（LSB）：`88H`

- **第二步：根据小端规则建立内存映射矩阵**  
  小端模式核心规则：“**低位字节存放在低地址端，高位字节存放在高地址端**”。  
  起始基地址为 $00008040\text{H}$，连续 8 个存储单元的具体分布如下表：

```
+---------------+---------------+--------------------+
| 物理存储单元  | 存放数据内容  | 字节有效位权值说明 |
+---------------+---------------+--------------------+
| 0000 8040H    | 88H           | 最低有效字节 (LSB) |
| 0000 8041H    | 77H           |                    |
| 0000 8042H    | 66H           |                    |
| 0000 8043H    | 55H           |                    |
| 0000 8044H    | 44H           |                    |
| 0000 8045H    | 33H           |                    |
| 0000 8046H    | 22H           | 次高有效字节       |
| 0000 8047H    | 11H           | 最高有效字节 (MSB) |
+---------------+---------------+--------------------+
```

- **第三步：查找目标存储单元**  
  目标地址为 $00008046\text{H}$，对应的字节内容为 `22H`。

#### 【干扰项深度剖析】
- **误选 B（`33H`）**：错误计算了偏移量，误将基准地址加 5 当作目标单元。
- **误选 C（`66H`）**：混淆了 32 位机器字与 64 位数据类型的关系，误将低 32 位与高 32 位分别按 32 位字单独做小端转换。
- **误选 D（`77H`）**：误将大端模式应用到本题，在大端模式下，$00008046\text{H}$ 对应倒数第二个字节即 `77H`。

#### 【正确答案】
**A**

### 2. 2018 年 408 真题第 15 题

#### 【题干与选项】
某 32 位计算机按字节编址，采用小端（Little Endian）方式。若语句 `int i = 0;` 对应指令的机器代码为 `C7 45 FC 00 00 00 00`，则语句 `int i = -64;` 对应指令的机器代码是（ ）。  
A. `C7 45 FC C0 FF FF FF`  
B. `C7 45 FC 0C FF FF FF`  
C. `C7 45 FC FF FF FF C0`  
D. `C7 45 FC FF FF FF 0C`  

#### 【考查方向】
本题考查负整数补码计算、指令编码中的立即数字段与小端存储模式的综合应用。

#### 【详细解析】
- **第一步：对比机器指令结构**  
  观察基准指令 `C7 45 FC 00 00 00 00`：
  - 前 3 个字节 `C7 45 FC` 为指令的操作码、寻址方式及目标寄存器相对位移（对应汇编指令 `mov dword ptr [ebp-4], 0`）。
  - 后 4 个字节 `00 00 00 00` 对应 32 位整型立即数 `0`。  
  因此，语句 `int i = -64;` 仅需将后 4 字节立即数替换为 $-64$ 的 32 位补码形式。

- **第二步：计算数值 $-64$ 的 32 位补码**  
  $+64$ 的原码为：
  $$[+64]_{\text{原}} = 0000\ 0000\ 0000\ 0000\ 0000\ 0000\ 0100\ 0000\text{B} = 00000040\text{H}$$
  由正数求负数补码，数值位全部取反加 1：
  $$[-64]_{\text{补}} = \text{FFFFFFBFH} + 1 = \text{FFFFFFC0H}$$
  32 位补码各字节从高位到低位依次为：`FFH`, `FFH`, `FFH`, `C0H`。其中：
  - $\text{MSB} = \text{FFH}$
  - $\text{LSB} = \text{C0H}$

- **第三步：按小端规则排列指令后 4 字节**  
  指令在内存中是从低地址向高地址依次读取执行的，后 4 字节地址递增：
  - 低地址单元存放 LSB：`C0H`
  - 随后存放次低字节：`FFH`
  - 随后存放次高字节：`FFH`
  - 高地址单元存放 MSB：`FFH`  
  因此后 4 字节机器代码为：`C0 FF FF FF`。  
  整条指令机器码拼接为：`C7 45 FC C0 FF FF FF`。

#### 【干扰项深度剖析】
- **选项 B、D（含 `0C`）**：将十进制数 $64$ 错误转换为十六进制数 $0\text{CH}$（$0\text{CH}$ 为十进制 12，而 $64 = 4 \times 16 = 40\text{H}$）。
- **选项 C（`FF FF FF C0`）**：错误地采用了大端模式排布立即数，将高位字节 `FF` 排在了低地址。

#### 【正确答案】
**A**

### 3. 2019 年 408 真题第 15 题

#### 【题干与选项】
某计算机采用大端方式，按字节编址。某指令中操作数的机器数为 `1234FF00H`，该操作数采用基址寻址方式，形式地址（用补码表示）为 `FF12H`，基址寄存器内容为 `F0000000H`，则该操作数的 LSB（最低有效字节）所在的地址是（ ）。  
A. `F000FF12H`  
B. `F000FF15H`  
C. `EFFFFF12H`  
D. `EFFFFF15H`  

#### 【考查方向】
本题考查基址寻址有效地址计算、形式地址补码符号扩展、大端模式下最低有效字节（LSB）的内存物理定位。

#### 【详细解析】
- **第一步：计算基址寻址的有效地址（EA）**  
  基址寻址计算公式为：
  $$\text{EA} = (\text{BR}) + A$$
  其中基址寄存器内容 $(\text{BR}) = \text{F0000000H}$。  
  形式地址 $A = \text{FF12H}$，题目明确说明用补码表示。在 32 位地址系统中，16 位补码形式地址必须先进行**符号扩展**为 32 位：
  - 最高符号位为 1，进行带符号扩展，高 16 位补全为全 1：
    $$A_{\text{扩展}} = \text{FFFFFF12H}$$
  - 该补码表示的十进制负数为：$\text{FFFFFF12H} - 2^{32} = -(\text{000000EEH}) = -238$。  
  计算有效地址 $\text{EA}$：
  $$\text{EA} = \text{F0000000H} + \text{FFFFFF12H} = \text{EFFFFF12H}$$
  注意：地址为无符号整数，高位产生的进位直接自然溢出舍弃。$\text{EFFFFF12H}$ 即该操作数占据的 4 字节存储区域的首地址（最低地址）。

- **第二步：根据大端模式确定 LSB 的地址**  
  操作数机器数为 `1234FF00H`，共占据 4 个字节：
  - $\text{MSB} = 12\text{H}$
  - 次高字节 $= 34\text{H}$
  - 次低字节 $= \text{FFH}$
  - $\text{LSB} = 00\text{H}$  
  计算机采用**大端方式**（Big-Endian），规则为：“**高位字节存低地址，低位字节存高地址**”。  
  各个字节的具体存放地址如下：
  - 地址 $\text{EFFFFF12H}$：存放 `12H`（MSB）
  - 地址 $\text{EFFFFF13H}$：存放 `34H`
  - 地址 $\text{EFFFFF14H}$：存放 `FFH`
  - 地址 $\text{EFFFFF15H}$：存放 `00H`（LSB）  
  因此，该操作数的 LSB 所在的地址为：
  $$\text{EA} + 3 = \text{EFFFFF12H} + 3 = \text{EFFFFF15H}$$

#### 【干扰项深度剖析】
- **选项 A、B**：未对 16 位补码形式地址进行带符号扩展，直接按无符号数零扩展为 `0000FF12H` 参与加法，得出错误的有效地址 $\text{F000FF12H}$。
- **选项 C（`EFFFFF12H`）**：有效地址计算正确，但混淆了大端与小端，误将基地址（最低地址）当作 LSB 的存放位置（小端模式下 LSB 才在首地址）。

#### 【正确答案】
**D**

### 4. 2020 年 408 真题第 14 题

#### 【题干与选项】
在按字节编址，采用小端方式的 32 位计算机中，按边界对齐方式为以下 C 语言结构型变量 `a` 分配存储空间。
```c
struct record {
    short x1;
    int x2;
} a;
```
若 `a` 的首地址为 `2020FE00H`，`a` 的成员变量 `x2` 的机器数为 `12340000H`，则其中 `34H` 所在存储单元的地址是（ ）。  
A. `2020FE03H`  
B. `2020FE04H`  
C. `2020FE05H`  
D. `2020FE06H`  

#### 【考查方向】
本题考查 C 语言结构体成员边界对齐填充机制、偏移量计算与小端模式物理地址映射。

#### 【详细解析】
- **第一步：分析结构体成员大小与对齐约束**  
  在 32 位计算机中：
  - `short x1`：占 2 字节，要求起始地址为 2 的整数倍。
  - `int x2`：占 4 字节，要求起始地址为 4 的整数倍。

- **第二步：推导变量内部内存排布与对齐填充**  
  变量 `a` 的基地址为 $2020\text{FE00H}$（满足 4 的倍数）。
  1. `x1` 放置于偏移量 0 处，占用两个存储单元：
     - $2020\text{FE00H}$
     - $2020\text{FE01H}$
  2. 此时下一可用地址为 $2020\text{FE02H}$。由于成员 `x2` 是 `int` 型（4 字节），其起始地址必须对齐到 4 的整数倍：
     - $2020\text{FE02H} \bmod 4 = 2 \neq 0$，不能存放 `x2`。
     - $2020\text{FE03H} \bmod 4 = 3 \neq 0$，不能存放 `x2`。
     - 编译器在 `x1` 之后自动填充 2 个字节的空洞（Padding）：$2020\text{FE02H}$ 与 $2020\text{FE03H}$。
  3. `x2` 的起始存放地址被对齐调整为 $2020\text{FE04H}$，占用连续 4 个字节：$2020\text{FE04H}\sim 2020\text{FE07H}$。

- **第三步：依据小端规则定位字节 `34H`**  
  `x2` 的机器数为 `12340000H`：
  - 最低有效字节（LSB）：`00H`
  - 次低有效字节：`00H`
  - 次高有效字节：`34H`
  - 最高有效字节（MSB）：`12H`  
  采用**小端方式**（低位存低地址，高位存高地址）：

```
+---------------+---------------+--------------------+
| 物理存储地址  | 存放数据内容  | 成员与字段说明     |
+---------------+---------------+--------------------+
| 2020 FE00H    | x1 的低字节   | short x1           |
| 2020 FE01H    | x1 的高字节   | short x1           |
| 2020 FE02H    | 未定义 (填充) | 边界对齐空洞       |
| 2020 FE03H    | 未定义 (填充) | 边界对齐空洞       |
| 2020 FE04H    | 00H           | x2 最低字节 (LSB)  |
| 2020 FE05H    | 00H           | x2 次低字节        |
| 2020 FE06H    | 34H           | x2 次高字节        |
| 2020 FE07H    | 12H           | x2 最高字节 (MSB)  |
+---------------+---------------+--------------------+
```

  由表可知，数值 `34H` 存放在物理地址为 $2020\text{FE06H}$ 的单元中。

#### 【干扰项深度剖析】
- **误选 A（`2020FE03H`）**：未考虑边界对齐，认为 `x2` 紧随 `x1` 存放于 $2020\text{FE02H}$，在大端模式下得出 $2020\text{FE03H}$。
- **误选 B、C**：在小端排布时对字节权值识别错误，误将低字节 `00H` 对应到了 `34H`。

#### 【正确答案】
**D**

### 5. 2023 年 408 真题第 44 题

#### 【真题背景与完整题干】
C 程序段在计算机 M 上的部分机器级代码如下，每个机器级代码行中依次包含指令序号、虚拟地址、机器指令和汇编指令。

```c
for (i = 0; i < 24; i++)
```
```assembly
1   00401072  C7 45 F8 00 00 00 00              mov [ebp-8], 0
```

4. 第一次执行第 19 条指令时，取指令过程中是否会发生缺页异常？为什么？

#### 【考查方向与大小端定位】
本题重点考查第 (3) 问：通过反汇编指令的机器代码逆向推导目标计算机的大小端架构（考点精髓：基地址与立即数在机器指令字节序列中的排列顺序）。

#### 【设问 (3) 详细解析】
- **源操作数寻址方式**：第 19 条指令为 `mov [ecx+edx*4+00422000h], 0Ah`。源操作数直接在指令中给出常数值 `0Ah`，属于**立即数寻址**（Immediate Addressing）。
- **寄存器 `ecx` 内容**：二维数组元素 $a[i][j]$ 的地址计算公式为：
  $$\text{Addr}(a[i][j]) = \text{Base} + (i \times 64 + j) \times 4 = \text{Base} + j \times 4 + i \times 256$$
  汇编中寻址表达式为 `[ecx + edx*4 + 00422000h]`，已知基地址为 `00422000h`，`edx*4` 对应 $j \times 4$，因此 `ecx` 中存放的内容是 $i \times 256$（或表达为变量 $i$ 乘以行大小字节数）。
- **大小端架构判定推导**：
  分析第 19 条指令机器代码：`C7 84 82 00 20 42 00 0A 00 00 00`
  - 机器码中包含 32 位基地址偏移量 `00422000H`。对应机器码片段为连续 4 字节：`00 20 42 00`。
    - 低地址字节为 `00H`（对应数值的 LSB）
    - 随后依次为 `20H`, `42H`, `00H`（对应数值的 MSB）
    - 低位字节存放在低地址端，高位字节存放在高地址端。
  - 机器码最后 4 字节为 32 位立即数 `0000000AH`（即十进制 10）。对应机器码为：`0A 00 00 00`。
    - 最低有效字节 `0AH` 存放在该立即数字段的起始低地址处。
    - 高有效字节 `00H`, `00H`, `00H` 存放在高地址处。
  - **结论**：无论是基地址还是立即数，均遵循“**低有效字节存放在低地址单元，高有效字节存放在高地址单元**”的原则，因此计算机 M 采用的是**小端方式（Little-Endian）**。

#### 【整题标准参考答案】
1. **第 20 条指令的虚拟地址**：第 19 条指令起始地址为 `004010AEH`，其机器指令共包含 11 个字节（`C7 84 82 00 20 42 00 0A 00 00 00`）。因此第 20 条指令的虚拟地址为：
   $$004010\text{AEH} + 11 = 004010\text{AEH} + 0\text{BH} = 004010\text{B9H}$$
2. **跳转指令寻址方式与计算过程**：
   - 寻址方式：均采用**相对寻址方式**（PC 相对寻址）。
   - 计算过程：第 2 条指令机器码长度为 2 字节（`EB 09`），执行该指令时 PC 已自动指向下一条指令地址：
     $$\text{Next PC} = 00401079\text{H} + 2 = 0040107\text{BH}$$
     相对偏移量为 `09H`，因此目标地址为：
     $$\text{Target} = 0040107\text{BH} + 09\text{H} = 00401084\text{H}$$
3. **设问 3 结论**：源操作数采用**立即数寻址**；`ecx` 中存放的是 **$i \times 256$**（或 $i \times 64 \times 4$）；计算机 M 采用**小端方式**。
4. **缺页异常判断**：第一次执行第 19 条指令时，取指令过程中**不会发生缺页异常**。因为第 19 条指令所在虚拟地址（`004010AEH`）与前面已执行的第 1~8 条指令均位于虚拟页号为 `00401H` 的同一页面内，该页面已经调入主存，因此取指令不会缺页。

### 7. 2025 年 408 真题第 15 题

#### 【题干与选项】
某 32 位计算机按字节编址，采用小端方式存放数据，编译器按边界对齐方式为下列 C 语言结构型数组变量 `employee` 分配存储空间。
```c
struct record {
    int id;
    char name[10];
    int salary;
} employee[200];
```
数组 `employee` 的起始地址为 `0000A0B0H`，`employee[1].id` 的机器数为 `12345678H`，问 `56H` 的地址是多少？（ ）  
A. `0000 A0C3H`  
B. `0000 A0C4H`  
C. `0000 A0C5H`  
D. `0000 A0C6H`  

#### 【考查方向】
本题考查 C 语言结构体数组边界对齐、结构体总尺寸向上取整计算、多维数组元素定位与小端模式内存检索。

#### 【详细解析】
- **第一步：计算单个结构体 `struct record` 的大小与内部对齐**  
  在 32 位计算机中：
  1. 成员 `int id`：占 4 字节，起始偏移为 0，占用偏移量 $0\sim 3$。
  2. 成员 `char name[10]`：字符数组每个元素 1 字节，对齐模数为 1。它紧随其后存放在偏移量 $4\sim 13$（共 10 字节）。
  3. 成员 `int salary`：占 4 字节，其起始偏移量必须是 4 的整数倍。
     - 当前到达偏移量 14。
     - $14 \bmod 4 = 2 \neq 0$，不能直接存放。
     - 编译器在 `name` 之后填充 2 个字节的空洞（偏移量 14, 15）。
     - `salary` 存放在偏移量 $16\sim 19$（共 4 字节）。
  4. 结构体整体对齐：
     - 当前已使用到偏移量 19，有效总长度为 20 字节。
     - 结构体内部最大成员大小为 $\max(4, 1, 4) = 4$ 字节。
     - 结构体总大小必须是 4 的整数倍：$20 \bmod 4 = 0$，已经满足要求，末尾无需再次填充。
     - 因此每个结构体元素的大小：
       $$\text{sizeof}(\text{struct record}) = 20\text{ 字节} = 14\text{H 字节}$$

- **第二步：计算数组元素 `employee[1]` 的起始地址**  
  数组首地址 $\text{Base} = 0000\text{A0B0H}$ 对应 `employee[0]`。  
  `employee[1]` 的起始地址为：
  $$\text{Addr}(\text{employee}[1]) = 0000\text{A0B0H} + 1 \times 20 = 0000\text{A0B0H} + 14\text{H} = 0000\text{A0C4H}$$

- **第三步：依据小端模式定位 `56H` 的物理地址**  
  `employee[1].id` 位于 `employee[1]` 的起始位置，即起始地址为 $0000\text{A0C4H}$，占 4 字节。  
  其机器数为 `12345678H`：
  - $\text{MSB} = 12\text{H}$
  - 次高字节 $= 34\text{H}$
  - 次低字节 $= 56\text{H}$
  - $\text{LSB} = 78\text{H}$  
  小端模式要求“**低位字节存放在低地址端，高位字节存放在高地址端**”：

```
+---------------+---------------+--------------------+
| 物理存储地址  | 存放数据内容  | 成员与字段说明     |
+---------------+---------------+--------------------+
| 0000 A0C4H    | 78H           | id 最低字节 (LSB)  |
| 0000 A0C5H    | 56H           | id 次低字节        |
| 0000 A0C6H    | 34H           | id 次高字节        |
| 0000 A0C7H    | 12H           | id 最高字节 (MSB)  |
+---------------+---------------+--------------------+
```

  数值 `56H` 存放在存储单元 **`0000 A0C5H`** 中。

#### 【干扰项深度剖析】
- **误选 A（`0000 A0C3H`）**：错误地将数值 `78H` 放在了 $0000\text{A0C4H}$ 之前。
- **误选 B（`0000 A0C4H`）**：混淆了首字节内容，误以为求的是首地址单元存储的数据。
- **误选 D（`0000 A0C6H`）**：误用大端模式计算，$0000\text{A0C4H}$ 存 $12\text{H}$，$0000\text{A0C5H}$ 存 $34\text{H}$，$0000\text{A0C6H}$ 存 $56\text{H}$。

#### 【正确答案】
**C**

## 四、综合大题应用与考查拓展

大小端机制在 408 综合应用大题（第 43、44、45 题）中具备极强的跨学科知识联动特性。考生在备考时，必须掌握以下四大高级命题场景：

### 1. 场景一：反汇编机器码与体系结构判定（跨指令系统与微架构）
- **核心命题逻辑**：题目给出一段 C 语言循环或数组处理代码，并给出 GCC 生成的汇编代码与对应十六进制机器代码（如 2023 年第 44 题）。
- **识别破局点**：
  1. 寻找带有 32 位/64 位常数立即数的指令（如 `mov [addr], imm` 或 `cmp reg, imm`）。
  2. 对比汇编中的十六进制数值与机器码序列中的字节流。
  3. 若立即数的低位字节先出现在低地址，则判定为**小端模式**；反之若高位字节先出现，则为**大端模式**。

### 2. 场景二：主存物理/虚拟转存表（Hex Dump）还原（跨存储管理与虚拟内存）
- **核心命题逻辑**：题目给出主存中从某一连续地址开始的十六进制字节矩阵，结合变量名、数组下标要求还原参与运算的操作数机器数（如 2024 年第 44 题）。
- **避坑操作规程**：
  1. **明确数组基地址**：先由寄存器或符号表提取出首地址十六进制值。
  2. **十六进制加法求偏移**：下标乘以单元素字节大小，转换成十六进制偏移相加，杜绝十进制与十六进制混淆（例如 $20 = 14\text{H}$）。
  3. **横向定位字节**：小端模式读取多字节数据时，**必须从高地址到低地址反向书写机器数**。
     - 假设地址 $00\text{H}\sim 03\text{H}$ 分别为 `A1 B2 C3 D4`；
     - 地址 $00\text{H}$ 是 LSB（`A1`），地址 $03\text{H}$ 是 MSB（`D4`）；
     - 正确的 32 位机器数应写为：`D4C3B2A1H`，切忌顺着写成 `A1B2C3D4H`！

### 3. 场景三：C 语言底层指针强制类型转换与内存截断（跨程序设计与组成原理）
- **类型截断原理**：高位截断还是低位截断？
  - 在 C 语言表达式 `(char)i` 或 `*(char*)&i` 中：
  - `(char)i` 是数值强制转换，保留数值权值最低的 8 位二进制（即 LSB）。
  - `*(char*)&i` 是指针地址截引用，直接读取变量 `i` 的首物理地址（最低地址单元）。
  - 在**小端模式**下：首物理地址正好存放的是 LSB，因此两者结果一致。
  - 在**大端模式**下：首物理地址存放的是 MSB，`*(char*)&i` 提取的是最高有效字节，两者结果完全不同！
- **经典判定代码的微架构原理**：
```c
int check_endianness() {
    int x = 1; // 机器数 0000 0001H
    char *p = (char*)&x;
    return (*p == 1); // 返回 1 表示小端，返回 0 表示大端
}
```

### 4. 场景四：网络数据报解析（跨组成原理与计算机网络）
- 计算机网络中接收到的 IP 分组报头：
  - 版本号与首部长度（1 字节）
  - 区分服务（1 字节）
  - 总长度（2 字节，以太网帧中按大端网络序传输，如 `00 3CH` 表示 60 字节）
  - 标识（2 字节）
  - 标志与片偏移（2 字节）
- 若主机为小端系统，网卡 DMA 将网络数据写入主机内存后，驱动程序必须调用 `ntohs()` 反转这两个字节，才能正确加载到 CPU 寄存器中供协议栈分析。

## 五、考点速记清单

### 1. 核心判断口诀
- **小端（Little-Endian）**：**小对小，大对大**。低位字节存放在低地址，高位字节存放在高地址。
- **大端（Big-Endian）**：**大对小，小对大**。高位字节存放在低地址，低位字节存放在高地址。

### 2. 内存字节排布速查矩阵
以 4 字节十六进制数 `0xA1B2C3D4` 存放在首地址 `0x1000` 为例：

```
+---------------+---------------+---------------+
| 字节物理地址  | 大端存放模式  | 小端存放模式  |
+---------------+---------------+---------------+
| 0x1000 (首址) | A1H (MSB)     | D4H (LSB)     |
| 0x1001        | B2H           | C3H           |
| 0x1002        | C3H           | B2H           |
| 0x1003        | D4H (LSB)     | A1H (MSB)     |
+---------------+---------------+---------------+
```

### 3. 结构体边界对齐计算三步黄金法则
1. **第一步（自身对齐）**：各成员起始偏移量必须被该成员自身的 `sizeof(type)` 整除，不足则在前一个成员后填充空洞。
2. **第二步（结构体补齐）**：计算所有成员与填充字节之和后，检查总字节数是否为结构体内**最大成员大小**的整数倍，不足则在末尾填充空洞。
3. **第三步（数组连续）**：结构体数组下标计算为：$\text{Addr}(\text{arr}[i]) = \text{Base} + i \times \text{sizeof}(\text{struct})$，数组元素之间无额外填充。

### 4. 408 考场避坑黄金准则
1. **字符数组不翻转**：`char s[] = "ABC"` 在大小端系统中在内存的排列都是 `'A', 'B', 'C'`，绝不颠倒。
2. **数组顺序不翻转**：`int a[2]` 中 `a[0]` 永远在低地址，`a[1]` 永远在高地址。大小端只影响 `a[0]` 内部 4 个字节的顺序。
3. **十六进制进位牢记**：进行地址加减运算时，十进制数先转为十六进制（如十进制 $20 = 14\text{H}$，十进制 $16 = 10\text{H}$），严防基数错误。
4. **负数必须转补码**：遇到负数指令机器码，必须先将十进制数值转换为完整 32 位补码形式，再做小端逆序排布。
