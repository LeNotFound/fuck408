## 二、具体考察内容

### 1. 中断的基本概念与机制本质

#### 1.1 中断机制的引入诱因
在早期计算机系统中，CPU 采用程序轮询（Polling）方式与外部设备交互。由于机械或外围电气设备的响应速度（毫秒/微秒级）与 CPU 的主频执行速度（纳秒级）存在几个数量级的速度差异，轮询导致 CPU 绝大部分计算周期处于空转忙等状态。

中断（Interrupt）机制引入的核心目标是**实现 CPU 与外设之间的并行工作**。CPU 发出启动外设命令后即可继续执行其他计算任务；当外设完成数据准备或发生紧急事件时，通过向 CPU 发送硬件中断请求信号，主动打断 CPU 的当前任务，CPU 转去执行相应的中断服务程序，完成数据交互后返回原任务继续执行。

#### 1.2 中断与异常的严密边界界定
广义上的中断涵盖所有改变程序正常执行流的突发事件，但在 408 考纲与现代计算机体系结构中，必须严格区分**外部中断（外中断 / 狭义中断）**与**内部异常（内中断 / 异常）**：

| 属性维度 | 外部中断（Interrupt / 外中断） | 内部异常（Exception / 内中断） |
| :--- | :--- | :--- |
| **信号来源** | CPU 芯片外部（外设接口控制器、定时器、外部总线） | CPU 芯片内部（执行当前指令的 ALU 算术逻辑、MMU 等） |
| **时序同步性** | **异步事件**（Asynchronous），与 CPU 当前执行指令无关 | **同步事件**（Synchronous），由 CPU 当前执行的指令直接引发 |
| **采样时机** | **指令周期结束时**统一采样中断请求引脚（INTR / NMI） | 在**指令执行过程中**即时检测并响应（不能等待指令完成） |
| **典型分类** | 1. 可屏蔽中断（INTR）：外设 I/O 请求、网卡包到达、定时器到时<br>2. 不可屏蔽中断（NMI）：电源掉电、内存奇偶校验错误、硬件故障 | 1. 故障（Fault）：缺页异常、段错误（可修复并重新执行原指令）<br>2. 陷阱（Trap）：系统调用、断点调试（执行完毕执行下一条指令）<br>3. 终止（Abort）：整数除零、非法操作码、硬件崩溃（不可恢复） |
| **屏蔽机制** | 可通过 CPU 标志寄存器中的中断允许标志（IF）进行屏蔽（NMI 除外） | 无法通过软件 IF 标志进行屏蔽，必须立即响应处理 |

#### 1.3 中断周期的时序切入点
在 CPU 的标准微指令执行周期中，外部中断并非在任意时钟周期都能插入。为维护程序状态字以及指令执行的原子性，CPU 仅在**当前指令执行周期的最后一个时钟周期（时钟节拍末尾）**，统一对外部中断引脚进行电平/边沿检测与采样。若检测到有效中断请求且满足响应条件，CPU 进入专门的**中断周期（Interrupt Cycle）**。

```
指令执行周期流向：
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌────────────────────┐
│ 取指周期 │ -> │ 译码周期 │ -> │ 执行周期 │ -> │ 中断周期（采样中断）│
└──────────┘    └──────────┘    └──────────┘    └────────────────────┘
                                                           │
                                   ┌───────────────────────┴───────────────────────┐
                                   ▼                                               ▼
                           [满足响应条件]                                  [无中断或已屏蔽]
                           进入硬件隐指令操作                              进入下一条指令取指周期
```

### 2. 中断请求与判优控制逻辑

#### 2.1 中断请求触发器与屏蔽机制
每个外部中断源在接口控制器中均配备相应的状态寄存器：
- **中断请求触发器（INTR / INTI）**：置“1”表示外设已准备就绪，向 CPU 提出服务申请；置“0”表示无请求。
- **中断屏蔽触发器（MASK / IM）**：置“1”表示对该中断源进行屏蔽，禁止其请求向 CPU 传递；置“0”表示开放中断。

#### 2.2 中断判优逻辑
当多个中断源在同一时钟周期同时向 CPU 发起请求时，必须通过判优逻辑确定优先响应哪一个中断源。判优机制分为软件判优与硬件判优：

1. **软件判优（程序轮询查询）**：
   CPU 通过运行一段查询程序，依照固定的优先级顺序依次读取各设备接口状态字中的中断标志位。先被查询的设备优先获得服务。该方式硬件结构简单，但消耗较多指令执行周期，响应速度较慢。

2. **硬件判优（排队判优网络）**：
   - **菊花链串行排队电路（Daisy Chain）**：所有外设接口的中断应答线串联成链状。当 CPU 发出中断响应信号 INTA 时，该信号由首端设备逐级向下传递。位于链路前端的设备享有最高优先级。若该设备有请求，则截获 INTA 信号并阻止其继续向后传递；若无请求，则将 INTA 向下一级旁路传递。
   - **集中式并行排队器**：利用组合逻辑优先编码器（Priority Encoder），各中断请求信号并行接入判优电路，由硬件编码器直接输出当前有效请求中优先级最高的中断源编号。并行判优速度极快，是现代计算机的标准实现。

```
菊花链（Daisy Chain）硬件判优拓扑结构：
CPU [INTA] ─────> [ 设备 1 (最高级) ] ─────> [ 设备 2 ] ─────> [ 设备 3 (最低级) ]
                       │                         │                   │
                       ▼                         ▼                   ▼
                  截获或传递                截获或传递          截获或传递
```

#### 2.3 关键概念辨析：中断响应优先级 vs 中断处理优先级
408 命题在此处设置了极高频率的陷阱，必须建立清晰的概念分野：

- **中断响应优先级**：
  - **决定者**：由硬件排队电路（菊花链拓扑或优先编码器）硬件固化决定。
  - **生效阶段**：中断响应周期。当多个中断源**同时提出请求**时，CPU 物理上优先响应哪个中断。
  - **不可变性**：硬件接线完成后，中断响应优先级即被固定，**无法通过软件指令或中断屏蔽字进行修改**。

- **中断处理优先级**：
  - **决定者**：由操作系统内核通过软件设置的**中断屏蔽字（Interrupt Mask Word）**动态决定。
  - **生效阶段**：中断服务程序执行阶段。决定某个中断源在处理过程中，能够被哪些其他中断源嵌套打断，以及不能被哪些中断源打断。
  - **可变性**：可通过修改中断屏蔽字由软件动态重新排列。

### 3. 中断响应周期与硬件隐指令机制

#### 3.1 CPU 响应外部中断的充要条件
CPU 在指令周期末尾采样中断请求，并满足以下三个条件时，方可正式响应中断：
1. **中断源发出有效请求**，且该中断源的中断屏蔽触发器处于未屏蔽状态（MASK = 0）。
2. **CPU 处于开中断状态**：CPU 标志寄存器（PSW / EFLAGS）中的中断允许标志位（Interrupt Flag, IF）为 1。若 IF = 0，则处于关中断状态，CPU 忽略所有可屏蔽中断请求。
3. **当前指令执行周期结束**：CPU 必须完成当前指令的微操作时序，且当前无更高优先级的不可屏蔽中断（NMI）或致命内部异常排队。

#### 3.2 硬件隐指令（Hardware Hidden Instruction）
**硬件隐指令并非计算机指令系统中的一条汇编指令**，而是 CPU 内部控制器在硬件中断周期自动执行的一连串微操作控制序列。硬件隐指令的核心任务是为转入软件中断服务程序准备运行环境，具体包含以下三个顺序微操作：

1. **关中断（Disable Interrupt）**：
   - 微操作：$\text{IF} \leftarrow 0$。
   - 机制意义：将标志寄存器中的 IF 置 0，防止在保护断点和程序状态的过程中被新的外部中断打乱现场，确保断点保护过程的原子性与完整性。

2. **保存断点与程序状态（Save Breakpoint and Program State）**：
   - 微操作：
     $$\text{SP} \leftarrow \text{SP} - 1, \quad \text{MAR} \leftarrow \text{SP}, \quad \text{MDR} \leftarrow \text{PC}, \quad \text{Memory}[\text{MAR}] \leftarrow \text{MDR}$$
     $$\text{SP} \leftarrow \text{SP} - 1, \quad \text{MAR} \leftarrow \text{SP}, \quad \text{MDR} \leftarrow \text{PSW}, \quad \text{Memory}[\text{MAR}] \leftarrow \text{MDR}$$
   - 机制意义：将当前被中断程序的下一条指令执行地址（即程序计数器 PC 的值，称为断点）以及当前标志寄存器（PSW）压入系统堆栈（或保存至专用硬件寄存器）。断点必须由硬件自动保存，因为软件程序无法在被调走前读取到未来的 PC。

3. **引出中断服务程序入口（Fetch Vector and Branch）**：
   - 微操作：硬件通过总线读取外设送来的中断向量（Vector），经过硬件向量地址形成部件生成中断向量表项地址，进而读取中断服务程序入口地址并送入 PC：
     $$\text{PC} \leftarrow \text{IVT}[\text{Vector}]$$
   - 机制意义：强制重写 PC，使 CPU 在下一个时钟周期的取指阶段直接跳转至该设备的中断服务程序首条指令。

```
硬件隐指令操作流程图：
┌───────────────────────────────┐
│     CPU 检测到有效中断请求    │
└──────────────┬────────────────┘
               ▼
┌───────────────────────────────┐
│  操作 1：关中断 (IF <- 0)     │
└──────────────┬────────────────┘
               ▼
┌───────────────────────────────┐
│  操作 2：压栈保存断点 PC, PSW │
└──────────────┬────────────────┘
               ▼
┌───────────────────────────────┐
│  操作 3：硬件寻址加载 ISR 向量│
└──────────────┬────────────────┘
               ▼
┌───────────────────────────────┐
│  跳转进入软件中断服务例程执行 │
└───────────────────────────────┘
```

### 4. 中断处理流程与中断服务程序（ISR）

硬件隐指令执行完毕后，CPU 控制权正式移交给操作系统内核的中断服务程序（Interrupt Service Routine, ISR）。完整的软件中断处理过程分为五个阶段：

```
软件中断服务例程标准执行结构：
阶段 1: 保护现场 (PUSH 通用寄存器)
阶段 2: 设置新中断屏蔽字 (配置处理优先级)
阶段 3: 开中断 (STI 指令，多重中断必须在此处开中断)
阶段 4: 设备服务主体 (执行数据搬运、状态校验等驱动逻辑)
阶段 5: 关中断 (CLI 指令，确保恢复现场过程不被再次打断)
阶段 6: 恢复旧中断屏蔽字与现场 (POP 通用寄存器)
阶段 7: 开中断并返回 (IRET 指令，原子恢复 PC 与 PSW)
```

1. **保护现场**：
   - 由中断服务程序首部的软件汇编指令（如 `push eax`, `push ebx` 等）将原程序正在使用的通用寄存器压入系统栈。通用寄存器不可由硬件隐指令保存，因为硬件无法预知软件程序使用了哪些寄存器。
2. **设置新中断屏蔽字**：
   - 写入新的屏蔽字，屏蔽同级或低处理优先级的中断，仅开放高处理优先级中断。
3. **开中断（多重中断专属）**：
   - 执行 `STI` 指令，使 $\text{IF} = 1$。此后若有更高处理优先级的中断发生，允许发生中断嵌套。
4. **中断服务主体**：
   - 进行核心的设备交互逻辑（如将设备接口缓冲区中的数据读入内核缓冲区，或将数据发送至外设）。
5. **关中断与现场恢复**：
   - 执行 `CLI` 指令关中断，防止在恢复现场时被新中断破坏；
   - 恢复原中断屏蔽字；
   - 执行出栈指令（如 `pop ebx`, `pop eax`）恢复通用寄存器原值。
6. **中断返回（IRET）**：
   - 执行中断返回专用指令 `IRET`。该指令是一条原子操作的特权指令，硬件自动从系统栈顶弹出此前保存的断点 PC 与 PSW，同时实现特权级切换（从内核态平滑返回用户态），原程序得以在中断打断的位置继续无缝执行。

### 5. 单重中断与多重中断机制

根据中断处理过程中是否允许被其他中断源打断，中断系统分为单重中断与多重中断：

```
单重中断执行时序：
原程序 ──────┐
             │ (中断响应)
             ▼
             [硬件隐指令: 关中断]
             [保护现场]
             [设备服务] ──── (此时无论来多高优先级的请求，均保持屏蔽排队)
             [恢复现场]
             [IRET 返回: 开中断]
             │
原程序 <─────┘

多重中断（中断嵌套）执行时序：
原程序 ──────┐
             │ (中断响应 1)
             ▼
             [硬件隐指令: 关中断]
             [保护现场 1]
             [设置屏蔽字 1]
             [开中断] ───────┐
             [设备服务 1]     │ (更高处理优先级的中断响应 2)
                             ▼
                             [硬件隐指令: 关中断]
                             [保护现场 2]
                             [设置屏蔽字 2]
                             [设备服务 2]
                             [恢复现场 2]
                             [IRET 返回]
             [继续服务 1] <──┘
             [关中断]
             [恢复现场 1]
             [IRET 返回]
             │
原程序 <─────┘
```

#### 5.1 多重中断实现的充要条件
1. **中断服务程序中提前开中断**：在保护现场与设置新屏蔽字后，必须执行开中断指令，将 CPU 重新置于允许中断响应的状态。
2. **严格的优先级管理**：由中断屏蔽字对所有等于或低于当前处理优先级的中断源进行强制屏蔽，仅允许高于当前处理优先级的中断打断，避免无休止自我递归或低优先级抢占高优先级。

### 6. 中断屏蔽字设计与优先级重构

#### 6.1 屏蔽字定义规则
在多重中断系统中，每个中断源均对应一个中断屏蔽字寄存器。其位宽等于系统中断源总数。
- **位定义惯例**：通常定义“1”表示屏蔽该中断源；“0”表示开放该中断源（允许打断）。（注：若考题有特殊说明反转定义，以题干说明为准）。
- **基本法则**：
  1. **自身必屏蔽**：每个中断源的屏蔽字中，对应自身的位必须设为“1”（禁止同级中断源自嵌套导致堆栈溢出）。
  2. **屏蔽低级与同级**：中断源 A 的处理优先级若高于中断源 B，则在 A 的屏蔽字中，对应 B 的位必须为“1”；反之在 B 的屏蔽字中，对应 A 的位必须为“0”。
  3. **“1”的个数判定法**：在“1 代表屏蔽”的标准定义下，**处理优先级越高的中断源，其屏蔽字中“1”的个数越多**；最高处理优先级的中断源屏蔽字全为 1，最低处理优先级的中断源屏蔽字仅自身位为 1。

#### 6.2 经典优先级重构案例推导
**设定条件**：设系统有 4 个中断源 $L_1, L_2, L_3, L_4$，其硬件响应优先级为：
$$L_1 > L_2 > L_3 > L_4$$
若操作系统通过软件配置，将其中断处理优先级调整为：
$$L_2 > L_4 > L_1 > L_3$$
求各中断源对应的中断屏蔽字（屏蔽字各位依次为 $L_1, L_2, L_3, L_4$，1 为屏蔽，0 为开放）。

**推导过程**：
1. 分析 $L_2$（最高处理优先级）：不能被任何中断打断，必须屏蔽所有中断源，故对应位全为 1：
   $$\text{Mask}(L_2) = 1111$$
2. 分析 $L_4$（第二高处理优先级）：只能被优先级更高的 $L_2$ 打断，必须屏蔽 $L_1, L_3, L_4$：
   $$\text{Mask}(L_4) = 1011$$
3. 分析 $L_1$（第三高处理优先级）：能被优先级更高的 $L_2, L_4$ 打断，必须屏蔽 $L_1, L_3$：
   $$\text{Mask}(L_1) = 1010$$
4. 分析 $L_3$（最低处理优先级）：能被 $L_2, L_4, L_1$ 打断，仅屏蔽自身 $L_3$：
   $$\text{Mask}(L_3) = 0010$$

**汇总表格**：

| 中断源 | 处理优先级排位 | 屏蔽的中断源 | 屏蔽字（$L_1 L_2 L_3 L_4$） | “1”的个数 |
| :---: | :---: | :---: | :---: | :---: |
| $L_1$ | 3 | $L_1, L_3$ | **1 0 1 0** | 2 |
| $L_2$ | 1（最高） | $L_1, L_2, L_3, L_4$ | **1 1 1 1** | 4 |
| $L_3$ | 4（最低） | $L_3$ | **0 0 1 0** | 1 |
| $L_4$ | 2 | $L_1, L_3, L_4$ | **1 0 1 1** | 3 |

### 7. I/O 控制方式全景横向对比

在计算机输入输出系统中，共存在四种主要的控制方式，其控制主体与开销演进关系如下：

| 控制方式 | 数据传送基本单位 | CPU 参与程度 | 硬件复杂度 | 总线控制权 | 典型应用场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **程序查询（轮询）** | 字 / 字节 | **全程忙等**（CPU 持续空转读取状态字） | 极低（仅需简单 I/O 状态端口） | CPU 始终掌握 | 早期工控单片机、低速无中断能力的设备 |
| **中断驱动（中断 I/O）** | 字 / 字节 | **仅中断时介入**（外设准备数据时 CPU 可执行其他进程） | 较低（需中断控制器与隐指令时序） | CPU 始终掌握 | 键盘、鼠标、打印机等低速字符型设备 |
| **直接内存访问（DMA）** | **数据块（Block）** | **仅块传输始末介入**（预置参数与传输完毕中断） | 较高（需 DMA 专用控制器及总线仲裁） | DMA 控制器在数据传送期接管总线 | 机械硬盘、固态硬盘、网卡等高速块设备 |
| **通道控制（I/O Channel）** | **通道程序（一组块）** | **仅通道程序始末介入**（完全实现 I/O 指令级自主执行） | 极高（需专用小型 I/O 协处理器） | 通道控制器完全控制 I/O 总线 | 大型主机、多外设高吞吐密集型系统 |

#### 7.1 外设数据准备时间与中断处理时间的物理约束
设外设接口的数据缓冲区大小为一个数据字，外设准备一个数据字的时间为 $T_{\text{准备}}$，CPU 响应并执行完一次中断服务程序（将缓冲区数据读走）的时间为 $T_{\text{中断处理}}$。
为确保数据不被后续新数据覆写丢失，必须满足不等式：
$$T_{\text{准备}} \ge T_{\text{中断处理}}$$
若 $T_{\text{准备}} < T_{\text{中断处理}}$，外设写入控制器的速度超过 CPU 读走数据的速度，造成**缓冲区溢出覆写（Data Overrun）**，导致严重的数据丢失。因此，高速块设备无法使用中断 I/O 方式，必须采用 DMA 或通道方式。

## 三、近十年真题精讲（2016~2025）

### 1. 2016 年第 44 题
**考查方向**：异步串行通信帧结构、字符吞吐率、中断时钟周期开销推导、硬件隐指令微操作。

**完整题干**：
假定 CPU 主频为 $50\text{ MHz}$，CPI 为 4。设备 D 采用异步串行通信方式向主机传送 7 位 ASCII 字符，通信规程中有 1 位奇校验位和 1 位停止位，从 D 接收启动命令到字符送入 I/O 端口需要 $0.5\text{ ms}$。请回答下列问题，要求说明理由。
(1) 每传送一个字符，在异步串行通信线上共需传输多少位？在设备 D 持续工作过程中，每秒钟最多可向 I/O 端口送入多少个字符？
(2) 设备 D 采用中断方式进行输入/输出，示意图如下：
```
       请求 响应 启动
CPU    ──┐   ┌───┐   ┌───┐
         │   │   │   │   │
外设 D ──┴───┘   └───┴───┘
         工作     工作     工作
         完成     完成     完成
```
I/O 端口每收到一个字符申请一次中断，中断响应需 10 个时钟周期，中断服务程序共有 20 条指令，其中第 15 条指令启动 D 工作。若 CPU 需从 D 读取 1000 个字符，则完成这一任务所需时间大约是多少个时钟周期？CPU 用于完成这一任务的时间大约是多少个时钟周期？在中断响应阶段 CPU 进行了哪些操作？

**详细解析**：
- **设问 (1) 推导**：
  - 异步串行通信的标准帧格式包含：1 位起始位（必须具备，标志帧起始）、数据位、校验位与停止位。
  - 数据位为 7 位 ASCII 码，外加 1 位奇校验位和 1 位停止位，故每传送一个字符需传输的总位数为：
    $$\text{总位数} = 1\text{（起始位）} + 7\text{（数据位）} + 1\text{（奇校验位）} + 1\text{（停止位）} = 10\text{ 位}$$
  - 设备 D 从接收启动到将字符送入 I/O 端口需耗时 $0.5\text{ ms} = 5 \times 10^{-4}\text{ s}$。在持续工作状态下，每秒钟最多向 I/O 端口送入字符数为：
    $$\text{字符吞吐量} = \frac{1\text{ s}}{0.5\text{ ms}} = \frac{1000\text{ ms}}{0.5\text{ ms}} = 2000\text{ 个/秒}$$

- **设问 (2) 推导**：
  - **基础时钟周期计算**：
    $$\text{时钟周期 } \tau = \frac{1}{f} = \frac{1}{50\text{ MHz}} = 20\text{ ns}$$
    设备 D 准备一个字符的耗时折合时钟周期为：
    $$N_{\text{设备}} = \frac{0.5\text{ ms}}{20\text{ ns}} = \frac{0.5 \times 10^{-3}\text{ s}}{20 \times 10^{-9}\text{ s}} = 25000\text{ 个时钟周期}$$
  - **单字符流水时序分析**：
    分析 CPU 与设备 D 的并行工作时序：设备 D 准备好字符送入端口并申请中断；CPU 响应中断需 10 个时钟周期；进入中断服务程序执行前 15 条指令（每条指令耗费 $\text{CPI} = 4$ 个周期，共 $15 \times 4 = 60$ 个周期）；执行到第 15 条指令时发出启动命令重新启动设备 D。
    因此，从设备 D 上一次被启动，到下一次被重新启动，其流水间隔周期为：
    $$T_{\text{周期}} = N_{\text{设备}} + T_{\text{响应}} + T_{\text{前15条指令}} = 25000 + 10 + (15 \times 4) = 25070\text{ 个时钟周期}$$
    传送 1000 个字符所需总时间大约为：
    $$T_{\text{总}} = 1000 \times 25070 = 25070000\text{ 个时钟周期}$$
    *(注：若考虑最后一个字符启动后无需等待后续设备准备，最后剩余 5 条指令执行完毕，计算结果为 $999 \times 25070 + 25000 + 10 + 20 \times 4 = 25070020$ 个周期，官方评分标准均认定为正确满分)。*
  - **CPU 占用时间计算**：
    CPU 真正花费在读取该字符任务上的时间仅为：单次中断响应周期加上完整的 20 条中断服务指令执行周期。外设自身准备数据的 25000 周期 CPU 在执行其他主程序，不占用 CPU 处理时间。
    单次中断消耗 CPU 时间为：
    $$T_{\text{CPU单次}} = T_{\text{响应}} + T_{\text{服务}} = 10 + (20 \times 4) = 90\text{ 个时钟周期}$$
    读取 1000 个字符累计占用 CPU 时间为：
    $$T_{\text{CPU总}} = 1000 \times 90 = 90000 = 9 \times 10^4\text{ 个时钟周期}$$
  - **中断响应阶段操作**：
    即硬件隐指令的三个关键步骤：① 关中断；② 保护断点和程序状态（保存 PC 和 PSW）；③ 识别中断源并引出中断服务程序入口地址（将向量地址送入 PC）。

**规范解答**：
(1) 共需传输 10 位（1位起始位、7位数据位、1位奇校验位、1位停止位）。每秒最多送入 2000 个字符。  
(2) 完成该任务所需时间大约为 25070000 个时钟周期（或 25070020 个时钟周期）。CPU 用于该任务的时间大约为 $9 \times 10^4$ 个时钟周期。CPU 在中断响应阶段的操作包括：关中断、保护断点和程序状态字（PC 与 PSW 压栈）、识别中断源并送中断服务程序入口地址至 PC。

### 2. 2017 年第 45 题（小问 3）
**考查方向**：中断控制方式下 `scanf()` 引发的进程状态转换与特权级变更。

**完整题干**：
假定计算机 M 的 I/O 采用中断控制方式。若进程 P 在调用函数 f1 之前通过 `scanf()` 获取变量 n 的值，则在执行 `scanf()` 的过程中，进程 P 的状态会如何变化？CPU 是否会进入内核态？

**详细解析**：
1. **陷入内核**：进程 P 调用 `scanf()` 属于系统调用操作，通过软件陷阱指令（如 `int 0x80` 或 `syscall`）陷入操作系统内核，CPU 特权级由用户态切换为内核态。
2. **进程阻塞**：内核 I/O 处理例程检测键盘接口输入缓冲区，此时键盘尚未输入字符，数据未就绪。进程 P 放弃 CPU 调度，状态由**运行态变为阻塞态（等待态）**，并挂入键盘等待队列；操作系统调度其他处于就绪态的进程运行。
3. **中断唤醒**：用户在键盘上键入字符并回车，键盘控制器产生外部硬件中断请求。CPU 响应中断转入键盘中断处理程序，将数据从设备控制器读入内核缓冲区。此时输入完成，键盘驱动程序将进程 P 从阻塞队列移出并挂入就绪队列，进程 P 状态由**阻塞态变为就绪态**。
4. **调度返回**：当进程调度程序再次调度到进程 P 时，进程 P 状态由**就绪态变为运行态**。内核将数据从内核空间拷贝至进程 P 的用户缓冲区，系统调用返回，CPU 由内核态恢复为用户态。

**规范解答**：
进程 P 在执行 `scanf()` 的过程中，因等待外设输入数据从**运行态变为阻塞态**；输入完成后被键盘中断处理程序唤醒，从**阻塞态变为就绪态**；被调度程序选中后从**就绪态恢复为运行态**。在此过程中，执行系统调用及中断处理时 CPU 会进入**内核态**。

### 3. 2018 年第 22 题
**考查方向**：外部 I/O 中断的响应时机、硬件隐指令功能与排队机制。

**完整题干**：
下列关于外部 I/O 中断的叙述中，正确的是（ ）。  
A. 中断控制器按所接收中断请求的先后次序进行中断优先级排队  
B. CPU 响应中断时，通过执行中断隐指令完成通用寄存器的保护  
C. CPU 只有在处于中断允许状态时，才能响应外部设备的中断请求  
D. 有中断请求时，CPU 立即暂停当前指令执行，转去执行中断服务程序  

**详细解析**：
- **A 项错误**：中断优先级排队由硬件排队电路（如优先编码器或菊花链）固化的响应优先级以及中断屏蔽字决定的处理优先级控制，绝非依照请求到达的时间先后次序。
- **B 项错误**：中断隐指令仅负责保存断点（PC）和程序状态字（PSW）。保护通用寄存器属于“保护现场”范畴，是由操作系统软件中断服务程序的第一段指令显式执行（如执行 PUSH 指令）完成的。
- **C 项正确**：外部可屏蔽中断请求（INTR）的响应必须满足 CPU 处于中断允许状态（即标志寄存器中开中断标志 $\text{IF} = 1$）。若处于关中断状态（$\text{IF} = 0$），CPU 忽略外部请求。
- **D 项错误**：CPU 响应外部中断必须保证指令的原子性，只有在当前指令执行周期的最后一个时钟周期末尾才进行中断检测与采样，绝不能在指令执行中途“立即暂停”。

**正确答案**：C

定时器产生时钟中断后，由时钟中断服务程序更新的部分内容是（ ）。

### 5. 2019 年第 21 题
**考查方向**：中断缓冲位宽、传输率与 CPU 时间占用率的计算模型。

**完整题干**：
某设备以中断方式与 CPU 进行数据交换，CPU 主频为 $1\text{ GHz}$，设备接口中的数据缓冲寄存器为 32 位，设备的数据传输率为 $50\text{ KB/s}$。若每次中断开销（包括中断响应和中断处理）为 1000 个时钟周期，则 CPU 用于该设备输入/输出的时间占整个 CPU 时间的百分比最多是（ ）。  
A. 1.25%  
B. 2.5%  
C. 5%  
D. 12.5%  

**详细解析**：
1. **确定单次中断传输的数据量**：
   数据缓冲寄存器为 32 位，折合为字节数为：
   $$\text{单次中断传输量} = \frac{32\text{ bit}}{8\text{ bit/B}} = 4\text{ B}$$
2. **计算单位时间内的中断请求次数（中断频率）**：
   设备数据传输率为 $50\text{ KB/s} = 50 \times 10^3\text{ B/s}$（计算通信传输率时 $1\text{K} = 10^3$），每秒产生的中断次数为：
   $$f_{\text{中断}} = \frac{50 \times 10^3\text{ B/s}}{4\text{ B}} = 12500\text{ 次/秒}$$
3. **计算单次中断消耗的时间与总开销**：
   CPU 主频为 $1\text{ GHz} = 10^9\text{ Hz}$，则每次中断消耗的时间为：
   $$T_{\text{中断}} = \frac{1000\text{ 个时钟周期}}{10^9\text{ Hz}} = 10^{-6}\text{ s} = 1\text{ }\mu\text{s}$$
4. **计算 CPU 时间占用率**：
   一秒钟内 CPU 用于处理该设备中断的总时间为：
   $$T_{\text{总CPU}} = 12500 \times 10^{-6}\text{ s} = 0.0125\text{ s}$$
   占整个 CPU 时间（1秒）的百分比为：
   $$\text{百分比} = \frac{0.0125\text{ s}}{1\text{ s}} \times 100\% = 1.25\%$$
   *(等价计算式：$\frac{12500 \times 1000}{10^9} = \frac{12.5 \times 10^6}{10^9} = 1.25\%$)*。

**正确答案**：A

### 6. 2020 年第 20 题
**考查方向**：外部中断与内部异常的分类辨析。

**完整题干**：
下列事件中属于外部中断事件的是（ ）。  
Ⅰ. 访存时缺页  
Ⅱ. 定时器到时  
Ⅲ. 网络数据包到达  
A. 仅 Ⅰ、Ⅱ  
B. 仅 Ⅰ、Ⅲ  
C. 仅 Ⅱ、Ⅲ  
D. Ⅰ、Ⅱ、Ⅲ  

**详细解析**：
- **Ⅰ 错误**：访存缺页是由 CPU 执行访存指令时，地址变换机构（MMU/TLB）检测到页表项有效位为 0 所产生的内部异常，属于**故障（Fault）**类型，与当前执行指令同步发生，为内部事件。
- **Ⅱ 正确**：定时器是挂接在 CPU 芯片外部的总线外围硬件，定时器计数器归零溢出时向 CPU 的中断引脚发出中断请求，属于**外部中断（外中断）**。
- **Ⅲ 正确**：网络数据包由网络接口卡（网卡）硬件接收，接收完毕存入网卡 FIFO 队列后，由网卡控制器向 CPU 发送外部硬件中断信号，通知 CPU 取走数据，完全独立于 CPU 指令执行流，属于**外部中断（外中断）**。

**正确答案**：C

Ⅰ. 保存被中断程序的中断点  
Ⅱ. 提供中断服务  
Ⅲ. 初始化中断向量表

### 8. 2022 年第 21 题
**考查方向**：中断 I/O 方式的适用对象、工作机理与时序约束。

**完整题干**：
下列关于中断 I/O 方式的叙述中，不正确的是（ ）。  
A. 适用于键盘、针式打印机等字符型设备  
B. 外设和主机之间的数据传送通过软件完成  
C. 外设准备数据的时间应小于中断处理时间  
D. 外设为某进程准备数据时 CPU 可运行其他进程  

**详细解析**：
- **A 项正确**：键盘、打印机等设备传输速率低，每次仅传送单个字符，中断开销不会导致系统过载，是中断 I/O 方式最典型的应用场景。
- **B 项正确**：在中断 I/O 方式下，外设接口缓冲区中的数据是通过 CPU 执行中断服务例程中的 `IN` 或 `MOV` 软件指令读取并送入内存的，必须依赖软件完成数据中转。

- **D 项正确**：中断方式的最大优势正是外设独立准备数据时，被阻塞进程让出 CPU，CPU 调度其他就绪进程运行，实现 CPU 与外设并行。

**正确答案**：C

### 10. 2023 年第 24 题
**考查方向**：中断向量表在操作系统内核中的物理数据结构。

**完整题干**：
在操作系统内核中，中断向量表适合采用的数据结构是（ ）。  
A. 数组  
B. 队列  
C. 单向链表  
D. 双向链表  

**详细解析**：
中断向量表（Interrupt Vector Table, IVT）的核心任务是：根据硬件传递过来的中断向量号（中断类型号，通常为 0~255 的整数 $i$），瞬间定位到对应的中断服务例程入口地址。
1. **随机访问性能要求**：中断响应对时间确定性与实时性要求极高。采用**数组（连续内存空间）**能够实现 $O(1)$ 时间复杂度的基地址加偏移量计算：

### 11. 2023 年第 46 题
**考查方向**：键盘中断、驱动程序、系统调用、进程状态机跨学科综合全流程。

**完整题干**：
进程 P 通过执行系统调用从键盘接收一个字符的输入，已知此过程中与进程 P 相关的操作包括：  
① 将进程 P 插入就绪队列；  
② 将进程 P 插入阻塞队列；  
③ 将字符从键盘控制器读入系统缓冲区；  
④ 启动键盘中断处理程序；  
⑤ 进程 P 从系统调用返回；  
⑥ 用户在键盘上输入字符。  
以上编号 ①~⑥ 仅用于标记操作，与操作的先后顺序无关。请回答下列问题。  
(1) 按照正确的操作顺序，操作 ① 的前一个和后一个操作分别是上述操作中的哪一个？操作 ⑥ 的后一个操作是上述操作中的哪一个？  
(2) 在上述哪个操作之后 CPU 一定从进程 P 切换到其他进程？在上述哪个操作之后 CPU 调度程序才能选择进程 P 执行？  
(3) 完成上述哪个操作的代码属于键盘驱动程序？  
(4) 键盘中断处理程序执行时，进程 P 处于什么状态？CPU 处于内核态还是用户态？  

**详细解析**：
- **设问 (1) 全流程时序剖析**：
  1. 进程 P 发起键盘读取系统调用，由于缓冲区无数据，内核将进程 P 挂入等待队列，执行操作 **②（将进程 P 插入阻塞队列）**；
  2. 用户在键盘上敲击按键，产生击键事件，执行操作 **⑥（用户在键盘上输入字符）**；
  3. 键盘接口硬件产生外部中断信号，CPU 响应后执行操作 **④（启动键盘中断处理程序）**；
  4. 键盘驱动程序响应并执行操作 **③（将字符从键盘控制器读入系统缓冲区）**；
  5. 数据已就绪，中断处理程序唤醒等待该事件的进程 P，执行操作 **①（将进程 P 插入就绪队列）**；
  6. 进程调度程序在后续某个时刻选中进程 P 投入运行，拷贝数据，最终执行操作 **⑤（进程 P 从系统调用返回用户空间）**。
  - 完整逻辑序列为：**② $\rightarrow$ ⑥ $\rightarrow$ ④ $\rightarrow$ ③ $\rightarrow$ ① $\rightarrow$ ⑤**。
  - 因此：操作 ① 的前一个操作是 **③**，后一个操作是 **⑤**。操作 ⑥ 的后一个操作是 **④**。

- **设问 (2) 调度触发时机剖析**：
  - 操作 **②（插入阻塞队列）** 发生后，进程 P 丧失运行条件，内核执行进程切换，CPU 一定从进程 P 切换到其他就绪进程运行。
  - 操作 **①（插入就绪队列）** 发生后，进程 P 重新具备运行资格，只有进入就绪队列，CPU 调度程序才能在就绪队列中选出进程 P 执行。

- **设问 (3) 驱动程序归属**：
  - 设备驱动程序（Device Driver）的核心职责是与特定的外设控制器硬件寄存器直接通信。因此将硬件状态与数据寄存器中的扫描码/字符读取到内存内核缓冲区的代码，即操作 **③**，属于键盘驱动程序。

- **设问 (4) 状态判别**：
  - 键盘中断处理程序执行时，输入数据刚刚到达系统，进程 P 仍在阻塞队列中等待数据唤醒，因此进程 P 处于**阻塞状态（等待状态）**。
  - 中断处理程序属于操作系统内核的核心中断上下文，因此 CPU 处于**内核态（管态）**。

**规范解答**：
(1) 操作 ① 的前一个操作是 ③，后一个操作是 ⑤。操作 ⑥ 的后一个操作是 ④。  
(2) 在操作 ② 之后 CPU 一定从进程 P 切换到其他进程。在操作 ① 之后 CPU 调度程序才能选中进程 P 执行。  
(3) 完成操作 ③ 的代码属于键盘驱动程序。  
(4) 键盘中断处理程序执行时，进程 P 处于阻塞状态。CPU 处于内核态。

### 12. 2024 年第 21 题
**考查方向**：中断屏蔽字、响应优先级与处理优先级的深度辨析。

**完整题干**：
下列关于中断 I/O 方式的叙述中，错误的是（ ）。  
A. 中断屏蔽字用于确定中断响应的优先级  
B. 保存断点和程序状态字在中断响应阶段完成  
C. 保存通用寄存器和设置新中断屏蔽字由软件实现  
D. 单重中断方式下，中断处理时 CPU 处于关中断状态  

**详细解析**：
- **A 项错误**：**中断屏蔽字用于动态设置和调整中断“处理”的优先级**，而非“响应”的优先级。中断响应优先级是在中断响应阶段，由硬件排队判优电路物理固化的，无法通过中断屏蔽字来决定。
- **B 项正确**：在中断响应阶段，CPU 执行硬件隐指令，自动将程序计数器（PC，即断点）和程序状态字（PSW）压入系统堆栈保存。
- **C 项正确**：通用寄存器的保护（PUSH）以及写入新的中断屏蔽字属于中断服务例程的代码逻辑，由操作系统内核软件显式执行指令实现。
- **D 项正确**：单重中断的核心特征是全过程禁止任何嵌套。硬件隐指令在响应时自动关中断（$\text{IF} = 0$），在中断服务程序执行期间始终不再开中断，直到最后 `IRET` 返回原程序前才恢复开中断。因此中断处理时 CPU 始终处于关中断状态。

**正确答案**：A

### 13. 2024 年第 31 题
**考查方向**：键盘中断服务例程执行完毕时数据的驻留层级。

**完整题干**：
键盘中断服务例程执行结束时，所输入的数据存放位置是（ ）。  
A. 用户缓冲区  
B. CPU 的通用寄存器  
C. 内核缓冲区  
D. 键盘控制器的数据缓冲区  

**详细解析**：
在现代分时操作系统的标准 I/O 子系统架构中，数据流转呈现严格的层级流动：
```
键盘硬件击键 -> 键盘控制器数据寄存器 -> 触发中断 -> 中断服务例程将数据读入【内核缓冲区】
                                                                    │
(应用程序调用 read/scanf 唤醒)                                       ▼
用户应用程序空间 <────── [copy_to_user 内存拷贝] ────── 操作系统内核缓冲区
```
1. 击键发生后，字符首先进入**键盘控制器的数据寄存器**；
2. 触发中断后，CPU 执行键盘中断服务例程（ISR），ISR 通过 `IN` 指令将字符从键盘控制器中读出；
3. 为隔离硬件与用户进程空间、支持行缓冲与流控制，ISR 将数据写入**内核缓冲区（系统缓冲区）**暂存；
4. 用户缓冲区属于特定用户进程的虚拟地址空间。在中断上下文中，当前 CPU 执行的可能与目标等待进程完全无关，且处于异步状态，驱动程序不能直接向用户缓冲区写入；待目标进程被唤醒并投入运行后，由系统调用从内核缓冲区复制（Copy）到用户缓冲区。
5. 通用寄存器仅在 ISR 执行期间用于临时暂存指令操作数，ISR 执行结束前必须通过 `POP` 恢复原值，不可能作为输入数据的长期存放介质。

## 四、综合大题应用与考查拓展

### 1. CPU 数据通路与中断响应硬件微操作时序联动
在 408 计算机组成原理与体系结构大题（如 43 题、44 题）中，常考查在特定单总线或多总线数据通路下，硬件隐指令对应的微操作控制信号流向。

设系统采用单总线结构，堆栈指针寄存器为 SP，程序计数器为 PC，程序状态字寄存器为 PSW，内存地址寄存器为 MAR，内存数据缓冲寄存器为 MDR，向量地址生成器输出为 VAD。当中断周期触发时，硬件控制器产生的微操作步骤与控制信号流向如下：

```
时钟周期 1（关中断并保存断点 PC）：
    (SP) - 1 -> SP                  ; 堆栈指针自减，开辟栈顶空间
    SP -> MAR                       ; 将栈顶地址打入内存地址寄存器
    PC -> MDR, Write                ; 将当前断点 PC 送入数据缓冲器，向存储器发写控制信号
时钟周期 2（保存程序状态字 PSW）：
    (SP) - 1 -> SP                  ; 堆栈指针再次自减
    SP -> MAR                       ; 栈顶地址送 MAR
    PSW -> MDR, Write               ; 将 PSW 送入 MDR，向存储器发写控制信号
    0 -> IF                         ; 硬件将标志寄存器中的 IF 置 0（关中断）
时钟周期 3（硬件向量引出）：
    VAD -> PC                       ; 中断向量地址生成器输出送入 PC，下一周期转去取 ISR 首条指令
```

### 2. I/O 中断通信与吞吐量计算模型化
在 2016#44 与 2019#21 等综合题与选择题中，形成了固定的中断量化计算模型：

1. **基本物理量换算**：
   - CPU 主频 $f$，时钟周期 $\tau = \frac{1}{f}$。
   - 设备缓冲区大小 $B$（字节），数据传输速率 $R$（字节/秒）。
2. **单位时间中断频度公式**：
   $$N_{\text{int}} = \frac{R}{B}\text{ （次/秒）}$$
3. **单次中断开销时钟周期**：
   $$C_{\text{int}} = C_{\text{响应}} + \sum (\text{指令条数} \times \text{CPI})$$
4. **CPU 占用率（利用率）计算公式**：
   $$\eta = \frac{N_{\text{int}} \times C_{\text{int}}}{f} \times 100\% = N_{\text{int}} \times C_{\text{int}} \times \tau \times 100\%$$
5. **系统极限吞吐能力边界**：
   若外设传输速度极高，使 CPU 时间占用率 $\eta \to 100\%$，此时 CPU 陷入**活锁（Live-lock）/ 中断风暴（Interrupt Storm）**，系统无法执行任何用户计算任务，必须切换为 DMA 控制方式。

### 3. 跨学科全链路穿透：键盘字符输入的软硬件时序协同图
2017#45 与 2023#46 考查了从外设硬件到用户程序执行的全流程。其完整跨学科时序链路如下：

```
[硬件物理层] 
  用户敲击按键 
     │
     ▼
[外设控制器] 
  键盘接口编码，扫描码送入键盘数据寄存器，置 INTR=1
     │
     ▼
[总线与硬件判优] 
  INTR 信号通过中断控制器（8259A/APIC）发送至 CPU 引脚
     │
     ▼
[CPU 硬件层] 
  当前指令执行周期末尾采样 -> 满足开中断(IF=1) -> 执行【硬件隐指令】：
  ① 关中断(IF=0)；② 压栈保存 PC、PSW；③ 硬件查找中断向量表，入口送 PC
     │
     ▼
[操作系统内核驱动层] 
  进入键盘中断服务例程(ISR)：
  ① 软件压栈保护通用寄存器现场；
  ② 执行 IN 指令，从键盘接口控制器数据寄存器读入扫描码/ASCII码；
  ③ 将数据写入操作系统【内核缓冲区】；
  ④ 检测是否存在阻塞在该输入设备上的进程（如进程 P）；
  ⑤ 将进程 P 的状态由【阻塞态】转为【就绪态】，挂入系统就绪队列；
  ⑥ 恢复通用寄存器现场，执行 IRET 指令原子恢复 PC 与 PSW，退出中断
     │
     ▼
[操作系统进程调度层] 
  调度程序在就绪队列中选中进程 P -> 进程 P 状态转为【运行态】
     │
     ▼
[系统调用返回层] 
  内核通过 copy_to_user 将内核缓冲区数据拷贝到进程 P 的【用户缓冲区】
  系统调用返回用户态，进程 P 继续执行后续用户代码
```

## 五、考点速记清单

### 1. 中断全流程软硬件职责分工速记表

| 处理步骤 | 对应操作内容 | 执行主体 | 关键机制与依据 |
| :---: | :--- | :---: | :--- |
| **步骤 1** | 中断请求检出 | **硬件** | 外设置 INTR=1，CPU 指令周期末尾硬件采样 |
| **步骤 2** | 排队判优 | **硬件 / 软件** | 菊花链或优先编码器（硬件）；轮询检测（软件） |
| **步骤 3** | **关中断** | **硬件隐指令** | 自动置 $\text{IF} = 0$，保证断点保存的原子性 |
| **步骤 4** | **保存断点与程序状态** | **硬件隐指令** | 自动将 PC、PSW 压入系统堆栈 |
| **步骤 5** | **引出中断服务程序** | **硬件隐指令** | 硬件查中断向量表，将 ISR 首地址赋给 PC |
| **步骤 6** | **保护通用寄存器现场** | **软件（ISR）** | ISR 头部执行 PUSH 指令保存通用寄存器 |
| **步骤 7** | **设置新中断屏蔽字** | **软件（ISR）** | 写入屏蔽字寄存器，调整处理优先级 |
| **步骤 8** | **开中断（多重中断）** | **软件（ISR）** | 执行 STI 指令，允许更高处理优先级中断打断 |
| **步骤 9** | 设备服务主体 | **软件（ISR）** | 读写 I/O 端口、将数据暂存至内核缓冲区 |
| **步骤 10** | 关中断与恢复现场 | **软件（ISR）** | 执行 CLI 指令，POP 恢复通用寄存器，恢复旧屏蔽字 |
| **步骤 11** | **中断返回（IRET）** | **硬件指令** | 执行特权指令 IRET，硬件原子恢复 PC、PSW 并切回用户态 |

### 2. 中断响应优先级 vs 处理优先级速记口诀
- **响应看硬件，连线定死不能改**：排队器（菊花链/优先编码器）决定同时来请求先理谁，属于硬件响应优先级。
- **处理看软件，屏蔽字改随心换**：中断屏蔽字决定处理中途能被谁打断，属于软件处理优先级。
- **屏蔽字中 1 越多，处理等级越极高**：在“1 屏蔽、0 开放”标准下，最高级全为 1，最低级仅自身为 1。

### 3. 中断屏蔽字极速构建“三步法”
- **第一步：看自身**。所有中断源自身对应位一律填 **1**。
- **第二步：看等级**。若本中断处理优先级**高于**目标中断，则目标中断位填 **1**（我处理时你必须被屏蔽）。
- **第三步：放通行**。若本中断处理优先级**低于**目标中断，则目标中断位填 **0**（我处理时允许你打断我）。

### 4. 核心计算公式手册
1. **字符传输总位数**：
   $$\text{Bits} = 1\text{（起始位）} + N_{\text{数据位}} + 1\text{（校验位，若有）} + N_{\text{停止位}}$$
2. **中断频率**：
   $$f_{\text{int}} = \frac{\text{外设传输速率（B/s）}}{\text{接口数据缓冲寄存器位宽（B）}}$$
3. **CPU 时间开销占比**：
   $$\text{CPU 占用率} = \frac{f_{\text{int}} \times \text{单次中断时钟周期}}{f_{\text{CPU}}} \times 100\%$$
4. **无损数据传输安全条件**：
   $$T_{\text{外设准备数据}} \ge T_{\text{CPU中断响应与服务}}$$

### 5. 考场避坑五大戒律
1. **严防“隐指令保存寄存器”陷阱**：硬件隐指令**仅压栈 PC 和 PSW**，任何通用寄存器（R0~R3、EAX 等）的保存必须由软件 ISR 中的 PUSH 指令完成。
2. **严防“中断立即响应”陷阱**：外部硬件中断**必须等到当前指令执行周期的最后一个时钟周期**才响应，不可在指令中途打断。
3. **严防“屏蔽字控制响应”陷阱**：中断屏蔽字控制的是**处理优先级（嵌套打断权限）**，绝不决定**响应优先级**。
4. **严防“数据直达用户空间”陷阱**：中断服务程序执行完毕时，输入数据存放在**内核缓冲区（系统缓冲区）**，而非用户进程的缓冲区。
5. **严防“内部异常受开中断控制”陷阱**：标志寄存器中的 $\text{IF}$ 标志只能屏蔽外部可屏蔽中断（INTR），内部异常（缺页、除零、溢出）以及外部不可屏蔽中断（NMI）无法被屏蔽，必然立即强制响应。
